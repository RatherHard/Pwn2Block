# ret2rop 参考解法

考点是**用 `ret` 把 gadget 串成链**：不是跳到一个现成的 `win`，而是让 `vuln` 的 `ret` 先落到
`pop rax; ret`，之后每一格依次是下一段的地址和它要的数据。四段代码各干一件事，合起来把
`RBX` 算成 `target` 要的 `0x1010`。

## 1. 栈上有什么

初态 `RIP = 0x400000`（`main`）、`RSP = RBP = 0x7fffff00`。程序前七条指令把帧建好：

- `call vuln`：`RSP` 减 8 → `0x7ffffef8`，并把返回地址 `0x400009` 压进去（`main` 里那条 `syscall 60`）；
- `push rbp`：`RSP` 减 8 → `0x7ffffef0`，压入旧 `RBP`；
- `mov rbp, rsp`：`RBP = 0x7ffffef0`，帧从这里往高地址长；
- `sub rsp, 0x50`：`RSP = 0x7ffffea0`，这就是 `buf`，也是 `read` 的落点。

于是三段的地址是：

| 段 | 地址 | 长度 |
|---|---|---|
| `buf` | `0x7ffffea0` – `0x7ffffeef` | `0x50` |
| saved rbp | `0x7ffffef0` – `0x7ffffef7` | `8` |
| ret addr | `0x7ffffef8` – `0x7ffffeff` | `8` |

`read(0, buf, 0x100)` 从 `buf` 起最多写 `0x100` 字节，所以 `buf` 到 ret addr 的
`0x50 + 8 = 0x58` 字节都是 padding，从第 `0x58` 个字节开始写链。

`leave` 之后 `RSP = RBP + 8 = 0x7ffffef8`，`ret` 正好弹出 ret addr 那一格；再往后
`RSP` 继续往上走，链就接在 ret addr 之后。

## 2. 链长什么样

`text` 段的四个片段（地址见指令视图的「函数」列表）：

| 片段 | 地址 | 作用 |
|---|---|---|
| `pop rax; ret` | `0x40002b` | `rax = [rsp]`，`rsp += 8` |
| `add rax, 0x10; ret` | `0x40002d` | `rax += 0x10` |
| `mov rbx, rax; ret` | `0x400037` | `rbx = rax` |
| `target` | `0x400039` | `rbx == 0x1010` 才判胜 |

按顺序摆在 ret addr 之后：

```
0x58  0x40002b   pop rax; ret          ← vuln 的 ret 先到这里
0x60  0x1000     pop 进 RAX 的值
0x68  0x40002d   add rax, 0x10; ret    ← RAX = 0x1010
0x70  0x400037   mov rbx, rax; ret     ← RBX = 0x1010
0x78  0x400039   target                ← 检查通过
```

执行过程：`ret` → `pop rax` 取 `0x1000`、`ret` → `add rax, 0x10` 得 `0x1010`、`ret` →
`mov rbx, rax`、`ret` → `target` 比较 `RBX` 与 `0x1010` 相等，`jne` 不跳，
执行 `syscall 99` 把 `FLAG` 置 1 并退出。判胜条件是 `FLAG == 1` 且 `RBX == 0x1010`，
两个都成立，所以 `verdict` 是 `won`。

只写到 `target` 是不够的：少一段 `mov`、或者 `pop` 出来的不是 `0x1000`，
`target` 里的 `jne lose` 就会把程序送去 `syscall 60`，判负。

## 4. 与原题的差异（给维护者）

- 原题把三个 gadget 写成「收一个结构体指针、改结构体里的假寄存器」的函数，再配一个
  16 字节的 `name` 全局当寄存器文件；那是为了在纯 C 演示里打印 `rax` / `rbx`。
  本项目有真实的寄存器视图，所以这里直接用 `RAX` / `RBX`，链的形状与原题演示的
  「假栈布局」（`pop rax` → `0x1000` → `add` → `mov` → `target`）逐格一致。
- 原题 `vuln` 读入后还有一层「用 `/dev/urandom` 生成的 key 做 XOR」的混淆，
  以及一条 `read(0, name, 0x10)`。本 VM 没有随机源，且「输入自混淆」属于另一件考点，
  按项目「一道题一个考点」的口径没有移植；本题只保留 ROP 主线。
- 原题 `target` 只是 `puts` 成功/失败文案；这里把成功收敛成 `syscall 99`，
  并把 `RBX == 0x1010` 写进判胜条件，避免「直接跳进 `syscall 99`」绕过整条链。
