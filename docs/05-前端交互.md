# 05 前端交互

前端只负责展示公开投影、编辑 payload、提交动作，不执行 VM，也不判题。

## 1. 整页布局

- 整页左右 1:1 分割，无间隙、无边框。
  - **右半**：payload 窗口（§3）。
  - **左半**：视图管理器（§2）。
- 顶部菜单两组：
  - **视图**：打开 / 关闭各内存视图。
  - **运行**：编译、运行、单步、回退、重置、提交判题，与 payload 工具栏等价。
- 页面有**两种模式**，顶部切换，对应 [04](04-会话与API.md) §1 的两个实例：
  - **调试模式**（默认）：所有视图实时反映调试实例。随便试，随便回退。
  - **判题结果**：提交后切到这里，显示判定结论和回放录像。拖动时间线，视图跟着变。
  - 两种模式共用同一套视图，只是数据源不同：前者是调试实例的当前投影，后者是录像里的某一帧。
  - 判胜提示只在调试模式里出现，且只说“当前状态已满足成功条件”，不发 flag。flag 只在判题结果里。
- 题面面板：可折叠，显示 `briefing` 与提示（§5）。
- 主题只做一套终端风格（深色、等宽字体），不做多主题。

## 2. 视图管理器与内存视图

### 2.1 视图管理器

- 同时显示 2 个视图槽位，上下排列；更多视图通过纵向平滑滚动切换。
- 列表按钮：弹出视图列表，可勾选显示 / 隐藏、拖动排序。
- `Ctrl+↑ / Ctrl+↓` 在视图之间切换。
- 所有视图的数据来源都是同一份最新投影；投影变化的字节和寄存器高亮一次。

### 2.2 栈视图

- 每行 W 字节（64 位为 8 字节），可设置对齐偏移。
- 锚点：`sp`、`bp` 所在行带标签，执行后自动滚动到 `sp`。
- 地址跳转输入框；字节序列搜索（hex 或 ASCII）。
- `labels` 中 `buffer / saved_bp / ret_addr / custom` 对应的行按类别着色并显示名称。
- pwndbg 风格的特殊显示，每行右侧附注：
  - 值若指向可见内存，显示跳转链 `→ 0x… → 0x…`，最多 3 跳。
  - 链落到可执行区域时，显示该地址的伪汇编（取自投影 `disasm`）。
  - 可打印字节显示 ASCII。
- 未映射或隐藏的地址一律显示为空，二者在界面上没有区别。

### 2.3 指令视图

- 列：地址、机器码、伪汇编，数据直接来自投影 `disasm`，前端不解码。
- 跳转 / 调用目标（`target`）可点击，跳到目标地址。
- 函数列表：由 `labels` 中 `kind = func` 的条目生成，点击跳转。
- 锚点：`ip` 所在行高亮，执行后自动滚动。
- MVP 没有断点，所以行首没有断点开关。想停在某条指令之前，用“运行 N 步”冲过去再 `step_back` 倒回来。

### 2.4 寄存器视图

- 显示投影中的寄存器与 `ZF / CF / SF`，变化的值高亮。
- 点击值复制到剪贴板。
- 寄存器名作为标签出现在其他视图中指向的地址上，例如栈视图的 `RSP →`。

### 2.5 自由视图

- 显示可见 VMA 列表（id、kind、label、范围、权限），选中后以 hex dump 浏览。
- 只能浏览投影中的可见 VMA，不提供任意地址读取。

MVP 不做可配置的视图模板、视图分屏比例和自定义列。

## 3. Payload 窗口

由上到下三部分：

1. **积木画布**（Blockly）+ 工具栏。
2. **程序区**：显示编译得到的原子动作序列，每行一个动作，当前执行位置高亮。
3. **输出区**：每个动作的结果（成功 / 拒绝 / 异常）和错误解释。

工具栏按钮：

| 按钮 | 行为 |
|---|---|
| 编译 | 把积木编译成原子动作序列（§4），显示在程序区，不提交 |
| 试运行 | 把程序区剩余动作提交到**调试实例**（一次 `actions` 请求）；序列用完时提交 `run` |
| 单步 | 提交程序区的下一个动作；序列用完时提交 `step` |
| 运行 N 步 | 输入框 + 按钮，提交 `step` 带 `count`。断点的替代品，见 [04](04-会话与API.md) §2 |
| 后退一步 | 提交 `step_back`，倒回一条指令。最近 64 条内有效 |
| 撤销 | 提交 `undo`，回退上一次提交 |
| 重置 | 提交 `reset`，程序区高亮回到开头 |
| **提交判题** | 把完整动作序列发到 `/submit`，切到判题结果模式 |

- 前七个按钮都只作用于调试实例，怎么点都不影响判题。只有"提交判题"是那一次正式的射击。
- 修改积木后程序区标记为“已过期”，需重新编译才能试运行或提交。
- 不设“暂停”按钮：一次请求在服务端同步执行完，没有可暂停的中间态。长时间运行由 `maxSteps` 截断。

### 3.1 积木分类

- **通用**：变量、列表、条件分支、循环、带返回值的函数、算术与赋值、字符串。
- **字节**：
  - `padding(byte, n)`：n 个重复字节。
  - `string(s)`：UTF-8 字节。
  - `int(v, width, endian)`：定宽整数，默认小端、宽度 W。
  - `addr(v)`：等价于 `int(v, W, little)`，单独列出便于教学。
  - `raw(hex)`：原始 hex。
  - `concat(...)`：拼接。
- **动作**：`write_bytes`、`push`、`pop`、`call`、`ret`、`step`、`run`，按题目 `allowedActions` 过滤，未允许的不出现在工具箱中。
- **出题人积木**：由 `authorBlocks` 动态生成，参数按 `params.type` 生成输入槽。
- 每块积木悬停显示 tooltip（出题人积木取 `tooltip` 字段）。
- 画布上只有一个“开始”积木，程序从它往下执行；未连到开始积木的积木不参与编译。

## 4. 客户端编译

- 编译在浏览器内完成，产物是原子动作序列：`write_bytes / push / pop / call / ret / block / step / run`。
- 循环与分支在编译期展开：
  - 循环展开上限 256 次，表达式求值上限 4096 步，超出即编译报错并指出积木位置。
- **payload 里没有"读取当前状态"类积木。** 偏移必须是学习者自己算出来的字面值。
  - 理由：payload 从初始状态回放（[04](04-会话与API.md) §5.1），而"读取 RSP"在初始状态下读到的不是调试时看见的那个值。允许它只会制造"试运行能过、提交就失败"的困惑。
  - 教学上这也更对：调试模式负责让学习者**算出**偏移，payload 负责证明他**算对了**。
- 编译结果提交给服务端：试运行走 `actions`，判题走 `submit`。服务端照常逐个校验，前端编译只是便利，不承担任何安全职责。
- 编译错误显示在输出区，并高亮出错积木。

## 5. 提示与错误解释

- **提示面板**：按 `hints` 顺序逐级揭示。
  - “下一条提示”按钮手动揭示。
  - 设置了 `unlockAfterFailures` 的条目，在投影 `failures` 达到阈值时自动揭示并提示。
  - 已揭示的提示保存在 `localStorage`，按题目 id 区分；丢失也不影响做题。
- **错误解释**：动作被拒绝或实例进入 `failed` 时，在输出区显示投影中的 `error.message` 与 `error.note`，并在相关视图中定位出错地址（仅可见地址）。

## 6. 状态反馈

调试模式：

- 进入 `satisfied`：输出区提示“当前状态已满足成功条件”，并引导去提交判题。**不发 flag、不显示判胜依据**，否则调试模式等于答案。所有动作照常可用。
- 进入 `failed / exited`：输出区显示原因，提示用 `step_back` 倒回去看，或 `undo` / `reset` 重来。
- 回退按钮在无可退时禁用，并说明原因（历史为空 / 已退到指令窗口之外）。

判题结果：

| `verdict` | 界面 |
|---|---|
| `won` | 通过横幅 + flag + 复制按钮，提示去 CTF 平台提交 |
| `incomplete` | “payload 跑完了，但没有达成目标”——强调这不是写错了，是还差东西 |
| `failed` | 显示命中的异常或失败条件，定位到录像里出事的那一帧 |
| `rejected` | 显示哪个动作被拒绝、为什么，高亮对应积木 |

- 四种结果都带回放录像，时间线可拖。失败的那一帧默认选中。
- “回到调试”按钮随时可用，调试实例的状态没被提交动过。
- 提交不限次数，界面不显示剩余次数，也不做任何劝阻。

通用：

- 网络错误或会话过期（404）：提示“会话已失效”，提供“重新开始”按钮创建新会话。

## 7. 可访问性（P0 基线）

- 所有按钮和菜单可键盘操作，焦点样式可见。
- 状态变化（满足条件、失败、错误、判题结论）通过 `aria-live` 区域播报。
- 颜色不是唯一信息载体：高亮同时带文字标签或符号。
- 模式切换要让屏幕阅读器能分辨当前在调试还是在看判题结果。

Blockly 画布本身的完整键盘导航留到 P1。
