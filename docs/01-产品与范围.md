# 01 产品与范围

## 1. 背景

AI 让 CTF 新生赛里的经典题失去了区分度，新生也很难从中获得正向反馈。Pwn2Block 换一种做法：把内存直接画出来，让新生通过受控的操作改写内存来解题。在这个过程中，他们会建立对栈帧、缓冲区和返回地址的直觉。

## 2. 用户

**Pwn 初学者**

- 通过内存可视化分析谜题。
- 在服务端调试实例里单步、回退、试运行，算出偏移后用积木构造 payload，提交判题。
- 获取分级提示，并看到可解释的失败原因。
- 认识地址、字节、十六进制、小端序、基本寄存器和伪汇编。

**出题人**

- 用公开包和私有包描述一道题，格式见 [03](03-题目包格式.md)，包括：
  - VM 位宽
  - 寄存器
  - VMA 布局
  - 指令编码
  - 可用接口
  - 成功条件
  - 提示
- 维护 6–10 道渐进式题目。

**协作者**：题目由多人分工编写，所以出题格式必须有工具链和文档支撑，见 [06](06-出题指南.md)。

与 CTF 平台的接入方式是最轻的一种：判胜后页面显示 flag，学习者自己复制到平台提交。平台侧不需要任何改动。

## 3. MVP 闭环

学习者完成一题的流程如下：

闭环分两段：**调试模式**里边搭边看反馈，搭好了**提交判题**。这映射真实 pwn 流程——gdb 里反复调，写出 exploit，然后打一次远端。

调试（随便试，不计后果）：

1. 打开题目页，阅读题面。
2. 前端创建服务端会话，拿到调试实例的公开投影。
3. 观察栈视图、寄存器视图和指令视图，找到 buffer、saved RBP 和 return address。
4. 手动写字节、单步、运行 N 步、后退一步，**算出**偏移。这些手工动作不进 payload。
5. 在积木窗口里拼出 payload，例如填充 + 地址，试运行看效果。
6. 失败时阅读错误解释，或揭示下一级提示；回退后改了再试。

判题（证明 payload 自足）：

7. 点"提交判题"。判题实例重置到初始状态，回放 payload。
8. 判胜则显示 flag；否则看回放录像定位问题，回到调试模式继续。提交不限次数。

**为什么要分两段。** 调试模式允许做 payload 之外的事，所以"调试时赢了"不等于"payload 能赢"。提交要证明的是：光靠这份 payload，从初始状态出发就能赢。手工试出来的认识必须落回积木——调试模式负责让学习者算出偏移，payload 负责证明他算对了。

**完成标准**：上述闭环可以走通，并且篡改浏览器内存或请求既拿不到隐藏数据，也无法伪造通过。

**交付物**：

- 后端 VM 引擎和会话 API。
- 前端单页应用。
- 6–10 道题目包，从“认识栈”逐步过渡到 ret2win。
- 出题工具链：默认编码表、伪汇编汇编器、题目包校验 CLI，以及给协作者看的出题指南（[06](06-出题指南.md)）。

## 4. 题目梯度（建议）

| # | 主题 | 考察点 |
|---|---|---|
| 1 | 认识内存与小端序 | `write_bytes` 写一个值使寄存器或内存等于目标 |
| 2 | push / pop | 栈指针移动 |
| 3 | call / ret | 返回地址入栈、出栈 |
| 4 | 栈帧 | `push rbp; mov rbp, rsp; leave; ret` |
| 5 | 缓冲区溢出覆盖局部变量 | 偏移计算 |
| 6 | ret2win | 覆盖 return address |
| 7 | 带参数的 win | 寄存器传参（gadget） |
| 8 | 隐藏区与接口 | `syscall` 读虚拟文件 |

## 5. 非目标

以下内容 MVP 一律不做：

- 完整 x86-64 指令集、ELF 加载、真实 shellcode、真实系统调用。
- 堆分配器、多架构、ASLR、PIE、NX 开关。
- 在线出题编辑器、AI exploit、多人协作、排行榜。
- 浏览器本地执行 VM 或本地判题，永远不做。
- 嵌入式插件、iframe、Web Component 对外集成、多租户、宿主成绩回传。
- 独立 verifier 进程、审计日志、签名发布、版本锁定。
- 用户认证与进度持久化：MVP 无登录，会话存在内存里，重启即丢。因此**不要长期挂在公网**，见 [07](07-工程约定.md) §7。

## 6. 安全底线（不可妥协）

1. **后端权威**：完整 VM 状态、私有题目包和 flag 只存在于后端。浏览器只发送受限动作，只接收公开投影。
2. **隐藏即不下发**：隐藏区域和 FLAG 寄存器的值不以任何形式出现在响应里，包括字段、长度和错误差异。访问隐藏地址时，响应必须与访问未映射地址完全一致。
3. **客户端不可信**：服务端不接受客户端提交的状态、快照或成功标志。是否通过只由服务端判定。
4. **出题 DSL 是数据，不是脚本**：题目包里没有回调和 eval，只能组合封闭的内置原语。

前端混淆、禁用右键、检测 DevTools 都不算安全措施，MVP 不做这些。
