## 1. 七天版承诺什么

| 项目 | 本轮安排 |

| 并行容量 | 8 个职责角色、最多 8 个 agent；各用独立工作区，不要求每时每刻全部运行 |
| 开发节奏 | D1–D6 开发与滚动集成；D7 只做回归、修复和交接，不再加功能 |
| 功能目标 | 01–06 的 MVP 功能与至少 6 道题不主动删减；第 7–8 题不纳入本轮 |
| 安全实现 | 不删除 Schema 校验、权限检查、资源限制、隐藏投影、双实例隔离或服务端判胜 |
| 安全验收 | 保留 6 组核心检查；延期 4 类专项和更广的组合测试，详见 §5 |
| 其他质量要求 | 保留 typecheck、lint、现有单元/集成测试、引擎覆盖率 ≥80%、全部题目 check/solve、1 条真实 E2E |

## 2. 八个 agent 与写入边界

增加的两个角色分别分担引擎和前端，避免只是多开 agent 却仍卡在同一个文件。

| 角色 | 工作 | 独占写入范围 |
|---|---|---|
| A：契约 / 集成 | workspace、shared、配置、CI、文档、集成发布 | `packages/shared/**`、根配置/锁文件、CI、`docs/**`、`CLAUDE.md` |
| B：执行引擎 | 解码、指令执行、动作分发、判胜与纯提交回放 | `packages/engine/**`，**排除 G 的三个子目录** |
| G：内存 / I/O | VMA、COW、快照存取、syscall 与虚拟文件 | `packages/engine/src/memory/**`、`src/io/**`、`src/snapshots/**`，测试就近放在这三个目录内 |
| C：服务端 | 题目加载、会话、公开投影、REST、静态托管 | `packages/server/**` |
| D：前端界面 | Lit、视图、网络状态、工具栏、调试/判题模式 | `packages/web/**`，**排除 H 的两个子目录** |
| H：积木 / 编译器 | Blockly、字节构造、编译与错误定位 | `packages/web/src/blocks/**`、`src/compiler/**`，测试就近放在这两个目录内 |
| E：出题工具 / 题库 | 编码表、asm/check/new/solve、六道题 | `packages/authoring/**`、`presets/**`；题目使用独立任务与分支 |
| F：验收 | 核心安全检查、黑盒集成、主路径 E2E、验收记录 | `tests/acceptance/**`、`tests/e2e/**` |

这里 `src/io/**`、`src/snapshots/**` 均相对 `packages/engine/`；所有目录在 D1 建立。

### 并行协作规则

1. **D1 上午先由 A 完成骨架和契约合并**。其他角色先输出接口需求、样例和测试案例；不得在未定义的接口上各造一套实现。
2. B/G 先定内存读写、不可变 VM 状态、syscall 结果、快照接口；B 拥有执行循环和回退编排，G 只实现状态存取，避免两份历史管理。
3. D/H 先定工作区编辑事件、编译结果、动作到积木位置映射；H 不依赖页面状态，D 不复制编译器。
4. B 提供无 HTTP 依赖的提交回放能力，供 C 与 E 复用；`challenge:solve` 不调用 server，不另写判题器。
5. 每个文件同批次只有一个写入者。包入口由 B/D 分别负责，G/H 不顺手修改包入口或配置。
6. 依赖安装、根脚本和锁文件由 A 统一维护；其他角色提出变更请求。各 owner 自己编写单元测试，F 不负责兜底所有测试。
7. shared 变更由 A 收齐消费者适配后在同一提交集成；暂停受影响文件写入，禁止类型改完而 server/web 仍失配。
8. 每人独立分支/worktree，只有 A 集成主线；每天中午、收工前各集成一次。当前无 remote，先本地分支协作；有 remote 后按仓库 PR 规范执行。
9. 出题用 `challenge/<id>` 分支，只改 `challenges/<id>/`；题目暴露的工具/引擎缺陷另开任务。
10. 这里仅安排角色，不启动 agent 或创建工作区。并发容量不足时按依赖排队，并重新估算日期，不假设八个角色天然都可同时运行。

## 5. 安全测试：本轮保留什么、实际削减什么

**削减的是验证范围，不是安全功能。** 下面的“六组”不是六个简单断言；每组列出的条件都必须验证。明确延期的四类专项才是实际减量，不能声称只是合并文件就省了一半工作。

### 本轮必过：六组核心检查

- [ ] **S01 · F，B/G/C 配合** 隐藏内容边界：隐藏 VMA 的 write_bytes、隐藏栈槽的 pop/ret 被拒绝且状态不变；投影/错误/录像不含未经程序公开的隐藏字节或虚拟文件内容；隐藏区无 hex/disasm，响应不含私有 win/fail 谓词。
- [ ] **S02 · F，B/C 配合** 判题边界：调试 satisfied 不发 flag、不记录通过；submit 从初态回放，不能借用手工调试状态，且不修改调试实例。
- [ ] **S03 · F，C 配合** 请求边界：伪造快照/成功标记、未知动作、未允许的动作被拒绝；拒绝不修改状态，回退动作按契约仍可用。
- [ ] **S04 · F，C/H 配合** payload 边界：block 由服务端展开，不相信客户端提供的展开结果；读状态 payload 被 rejected，而不是变成零。
- [ ] **S05 · F，C/E 配合** flag 边界：缺失环境变量，或虚拟文件/隐藏 VMA 内容包含注入的 flag 真值时拒绝加载；使用测试哨兵值，不把真实 flag 写进仓库。
- [ ] **S06 · F，A/C 配合** 发布边界：检查构建产物和实际静态 HTTP 路径，不能取得 private.json、solution.md、环境文件或注入的 flag 哨兵值。

与 07 §5 原清单的映射：S01 覆盖第 1–2 条；S02 覆盖第 8–9 条并验证提交隔离；S03 覆盖第 11–12 条；S04 覆盖第 10、13 条；S05 覆盖第 7 条；S06 补充静态发布检查。不是废除全部安全测试。

### 延期：不阻塞本轮内部候选版，仍阻塞完整 MVP 验收

- [ ] **T01 · G/B/F** reveal → undo/step_back 的跨层组合验证：重新隐藏、stdin 位置、stdout、文件偏移同时恢复（原第 3 条）。
- [ ] **T02 · G/F** read/write/copy 跨 VMA、尾字节越权和无副作用的完整黑盒矩阵，以及 count 超过 0x1000 的专项（原第 4 条）。
- [ ] **T03 · G/C/F** stdin/stdout 4KB 边界及多请求累积的专项黑盒验证（原第 5 条）。
- [ ] **T04 · B/G/F** 未声明 syscall 调用号的专项黑盒验证（原第 6 条）。
- [ ] **T05 · F + 各 owner** 核心场景之外的更多位宽/权限/请求交错/错误路径组合、长时间资源压力与额外浏览器复测；本轮不新增模糊测试或负载测试设施。
- [ ] **T06 · A/F** 正式验收前恢复 07 的完整清单和 CI 门槛，全部复测通过后才可标记完整 MVP 验收完成。

延期的专项如已由基础单测顺手覆盖，保留并继续跑；**不删除已有测试、不跳过已有失败测试、不移除实现中的防护来让测试通过**。上述延期不降低引擎 80% 覆盖率门槛，但覆盖率达标也不证明这些组合边界已经验证。

风险记录：本轮对“回退后隐藏内容是否正确恢复”“越权 I/O 是否完整回滚”“连续请求能否突破资源限制”等场景证据不足。候选版只使用测试 flag 和非敏感题目数据，在本机或隔离测试环境内部试用；该限制降低暴露面，**不等于风险消失**。
