# Pwn2Block 需求文档（MVP）

本目录是 Pwn2Block 的 MVP 需求文档，只保留首个教学闭环需要的内容。

## 一句话定位

这是一个内存可视化的 Pwn 概念实验室。学习者用积木拼装 payload，交给后端权威 VM 执行，再观察栈、寄存器和指令的变化，在这个过程中学会栈帧、缓冲区溢出和返回地址劫持。

它不是浏览器里的 Linux 或 x86 模拟器。

## MVP 主要取舍

保留的部分：

- 后端权威 VM，浏览器只拿公开投影。
- VMA 内存模型，以及出题人可配置的位宽、寄存器、指令编码。
- Blockly 积木 payload。
- 四种内存视图。
- 分级提示和可解释错误。

舍弃的部分（MVP 不做）：

- 分发与接入机制：独立 verifier 进程、启动票据 / 嵌入协议、多租户、宿主成绩同步、admin 管理面。
- 会话协议的工程机制：revision 防重、幂等键、协议版本握手、规范化 JSON、状态哈希、签名发布链。
- 部署与运维：每会话独立进程加 NDJSON 引擎协议、PostgreSQL / Redis / MinIO、监控指标、CI 机检门禁。
- 引擎的高级特性：IR 程序形态（只保留字节形态）、自定义微算子指令、多阶段状态机、seed / ASLR、隐藏测试。
- 前端断点：`run` 只保留步数上限，不支持运行到断点。想看某一瞬间就多跑几步再 `step_back`，见 04 §3。
- checkpoint 与任意时间点跳转：MVP 只做三级回退（重置 / 撤销 / 后退一步）。判题侧的回放时间线是免费副产品，不开放给调试实例。
- 用户认证与进度持久化：MVP 无登录，会话只在内存里。

## 关键决策

技术选型与工程约定在 [07](07-工程约定.md) §1 有完整表格，几条影响面最大的：

- 全栈 TypeScript，Fastify 单进程同时承担引擎、API 和静态托管。
- 一个会话两个实例：调试实例随便试、不发 flag；提交判题时判题实例重置到初始状态回放 payload，判胜才下发 flag。见 04 §1。
- 判胜后直接下发 flag，学习者复制到 CTF 平台提交。flag 真值由环境变量注入，不进 git。
- 三级回退（仅调试实例）：`reset` 回初始状态、`undo` 以请求为粒度、`step_back` 以指令为粒度（环形缓冲 64 步）。
- 题目由多人编写，所以配套默认编码表、伪汇编汇编器和校验 CLI，见 [06](06-出题指南.md)。
