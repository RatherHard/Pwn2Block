# 06 出题指南

本文写给出题协作者。格式的权威定义在 [03](03-题目包格式.md)，本文只讲怎么动手、容易错在哪里。

## 1. 一道题的目录

```
challenges/<id>/
├── public.json      # 公开包，会原样下发给浏览器
├── private.json     # 私有包，只在服务端读取
├── program.asm      # 伪汇编源码（可选，但强烈建议）
└── solution.md      # 参考解法（一份自足的 payload），不进入运行时
```

`program.asm` 不是运行时产物：汇编器把它编译成 `private.json` 里 code VMA 的 `init` hex。保留它是为了以后能改题，手写的 hex 过三天就没人看得懂了。

## 2. 工具链

| 命令 | 作用 |
|---|---|
| `pnpm challenge:new <id>` | 从模板生成上面四个文件 |
| `pnpm challenge:asm <id>` | 编译 `program.asm`，把 hex 写回 `private.json` |
| `pnpm challenge:check <id>` | 校验两个包：Schema、VMA 布局、编码表、谓词 |
| `pnpm challenge:solve <id>` | 把 `solution.md` 里的 payload 当成一次提交回放，断言 `verdict` 为 `won` |
| `pnpm dev` | 起本地服务，在浏览器里实际做一遍自己的题 |

**每道题都必须有 `challenge:solve` 能跑通的参考解法**，它同时是这道题的回归测试。只有参考解法通过的题才允许合并。

### 2.1 默认编码表

项目提供 `presets/x86ish.json`，opcode 取值刻意贴近真实 x86（`0x50` 是 push、`0xc3` 是 ret、`0xc9` 是 leave），这样学习者以后看真实反汇编不会陌生。

在 `public.json` 里引用它：

```json
{ "encoding": { "preset": "x86ish", "add": [ … ], "remove": ["0xe8"] } }
```

- `add` 追加本题特有的 opcode，`remove` 删掉不想让学习者用的。
- 加载时展开成完整的 `encoding` 数组再下发，前端看到的始终是展开后的表。
- **只声明这道题需要的作用**。多给一个 `jmp` 就多一条非预期解法。

### 2.2 伪汇编

```asm
.vma text                 ; 对应 private.json 里的 VMA id
vuln:
    leave
    ret
win:
    syscall 99            ; 调用号，查 public.json 的 syscalls
lose:
    syscall 60
```

- 支持标签、`.vma` 段切换、`.byte` / `.ascii` 填字面数据。
- `syscall N` 匹配编码表里 `const:N` 的那一项；不带数字的 `syscall` 匹配无操作数的那一项，调用号运行时取自 `nr` 寄存器。
- 跳转目标写标签，汇编器算出绝对地址。手写地址也允许，但不建议。
- 汇编器输出一份地址清单，直接拿去填 `labels` 和 `solution.md`。
- 没有宏、没有表达式求值。它只是“别手写 hex”的工具，不是真汇编器。

### 2.3 solution.md 的机器可读块

`challenge:solve` 要把参考解法**当成一次提交回放**，所以 `solution.md` 里必须有且只有一个 ```json 代码块：

```json
{
  "actions": [
    { "type": "block", "id": "gets", "args": { "data": "4141…" } },
    { "type": "step", "count": 3 }
  ],
  "expectedVerdict": "won"
}
```

- `actions` 是完整 payload，字段与 `POST /api/sessions/:id/submit` 完全一致（[04](04-会话与API.md) §5.1）。
- `expectedVerdict` 默认 `won`；个别题目可以写成 `failed` 来固化“这条错路必然失败”的反例。
- 代码块之外的正文写思路，随便写；代码块之外的内容不参与回放。
- 格式定义与解析器在 `packages/shared/src/solution.ts`，出题工具与验收共用同一份实现。

`pnpm challenge:new <id>` 会生成带这个块的模板。

## 3. 出题流程

1. **先写一句话考点。** 比如“算出 buf 到返回地址的偏移”。考点不止一个，就拆成两道题。
2. `pnpm challenge:new`，写 `program.asm`，`pnpm challenge:asm`。
3. 布好 VMA 和初始寄存器，让程序停在学习者该接手的那一刻（通常是 `gets` 刚返回）。用到 syscall 的题，在公开包里声明 `syscallAbi`、`syscalls`、`fds`，只声明这道题要用的。
   - 判断一样东西该放公开包还是私有包，就问：真实题目里拿到 binary 能不能看到它？能看到就公开；只有运行时才知道的（文件内容、canary 之类）才藏。
4. 写 `win`。先用最直接的谓词，比如 `reg_eq FLAG 0x1`。
5. **写 `fail`。** 没有 `fail` 的题，学习者走错路之后只会卡住，不知道自己已经输了。
6. 写 `labels`：`buffer`、`saved_bp`、`ret_addr` 让栈视图能标出关键位置；`func` 喂给指令视图的函数列表。
7. 写 `hints`，三条左右，从“往哪看”到“具体怎么算”，别一上来给答案。
8. 写 `errorNotes`，至少覆盖 `memory_fault` 和 `invalid_ip`，这两个是新生最常撞的。
9. 写 `solution.md`。它必须是一份**自足的 payload**：偏移写成字面量，不含读状态积木，从初始状态回放就能赢——判题实例就是这么跑的，见 [04](04-会话与API.md) §1。机器可读块的要求见 §2.3。
10. `pnpm challenge:solve`，再 `pnpm dev` 自己做一遍，走完"调试算偏移 → 提交判题"整条路。
11. 找一个没见过这题的人做一遍。卡在哪里，提示就该补在哪里。

## 4. 常见错误

| 问题 | 后果 | 怎么办 |
|---|---|---|
| 关键数据放在可见 VMA 里 | 学习者在自由视图里直接看到答案 | 该藏的设 `hidden: true`。地址和大小仍公开，藏的是内容 |
| 虚拟文件里放了 flag 真值 | 调试实例里一个 `write` 就打出 flag，绕过判题 | 文件放题目自己的秘密，用 `stdout_contains` 判胜。服务端加载时也会拒绝 |
| syscall 声明多了 | 多一个 `write` 或 `reveal` 就多一条泄露路径 | 只声明考点需要的 |
| `allowedActions` 放太宽 | 溢出题里留着 `call` / `write_bytes`，直接改 ip 或返回地址就赢了 | 溢出类题目只留 `step / run`，输入走出题人积木或 `feed` |
| 编码表给多了作用 | 出现非预期解法，考点被绕过 | 用 `remove` 砍掉，只留必要的 |
| 没写 `fail` | 学习者不知道自己已经失败 | 至少加“已退出且未判胜” |
| `init` 补丁写错端序 | 地址莫名其妙，自己都调不出来 | 用 `challenge:asm` 和 `addr()` 积木，别手写 |
| VMA 没按 0x1000 对齐 | 加载直接失败 | `challenge:check` 会报出来 |
| 把 flag 明文写进题目包 | 仓库一旦公开，flag 全部泄露 | `flag` 字段写 `"env:FLAG_<ID>"`，真值在部署时注入 |
| 提示里直接给出偏移 | 题目失去意义 | 提示指方向，不给数字 |
| 没有参考解法 | 题目改坏了没人发现 | 补 `solution.md`，CI 会跑 |

## 5. 合并前自查

- [ ] `challenge:check` 通过
- [ ] `challenge:solve` 通过
- [ ] 自己在浏览器里完整做过一遍
- [ ] `public.json` 里没有任何答案信息（偏移、flag、隐藏内容的值）
- [ ] `encoding` 和 `syscalls` 里没有多余的作用
- [ ] 虚拟文件和隐藏 VMA 里没有 flag 真值
- [ ] `win` 和 `fail` 都写了
- [ ] `labels` 覆盖了栈上的关键位置
- [ ] 至少 2 条提示 + 2 条 `errorNotes`
- [ ] 题面说清了目标，没有说漏前置条件

## 6. 协作约定

- 一道题一个 PR，PR 里写清考点和预期解法。
- `private.json` 进 git：它是题目的一部分，不是密钥。隐藏内容和虚拟文件写在里面没问题，因为仓库的读者是出题人，不是正在做题的学习者。
- **唯一不能进 git 的是 flag 真值。** `flag` 字段写成 `"env:FLAG_RET2WIN"`，服务端启动时从环境变量取值；缺失时拒绝加载这道题并报错。本地开发时在 `.env` 里随便填一个，`.env` 已被 `.gitignore` 排除。
- 题目 id 用小写加连字符，比如 `ret2win`、`stack-frame-01`。
- 改动已有题目时必须重跑 `challenge:solve`：改了一个字节就可能让参考解法失效。
