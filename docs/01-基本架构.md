# Pwn2Block 基本架构

## 1. 产品定位

Pwn2Block 是一个面向 Pwn 初学者的内存可视化实验室。学习者在浏览器中观察栈、寄存器、指令和 I/O，通过节点画布组合 payload；真正的 VM、题目私有数据和 flag 始终由服务端掌握。

MVP 的学习闭环是：**调试试验 → 观察状态 → 组合 payload → 从初始状态回放判题 → 成功后显示 flag**。

## 2. 代码分层

```text
packages/shared    前后端共享类型、动作、投影、校验和限制
        ↓
packages/engine    权威 VM：内存/VMA、寄存器、指令、syscall、快照和回放
        ↓
packages/server    Fastify 单进程：题目加载、会话、API、投影、限流、静态托管
        ↓
packages/web       Vite SPA：节点画布、状态视图、payload 编译、交互和回放

packages/authoring 出题工具：创建题目、伪汇编、题包检查、参考解法验证
challenges/        题目包；public.json 对外，private.json 只在服务端使用
presets/           可复用的 VM/编码预设
```

项目使用 pnpm workspace，整体为 TypeScript。开发时可以分别启动 server/web，发布时由 Fastify 同时提供 API 和 `packages/web/dist`。

当前节点画布是默认且唯一的 payload 编辑器，沿用这条依赖方向：

```text
packages/shared/src/workflow   图 Schema、节点规格、值编解码、工具函数、Python 求值协议
        ↓
packages/web/src/workflow      校验、依赖求值、动作生成、异步产物状态（本地纯计算）
packages/web/src/graph         几何计算与编辑命令（纯函数，无 DOM）
        ↓
packages/web/src/components    Lit 画布与面板：只收手势、渲染结果、发编辑事件
```

当前画布采用 Lit + SVG，图的编辑命令和坐标计算独立于 DOM。数据边表达依赖，执行顺序由有序序列和区域表达，不存冗余执行边。本轮交互目标见 [10-需求](10-节点画布交互与布局优化需求.md)，当前技术选择允许在满足该需求的前提下重新评估。

画布把图编译成受限的原子动作序列，仍由服务端权威执行；浏览器不判定成功、不持有隐藏数据。Python 代码只在服务端隔离运行器里求值，浏览器只提交代码与命名输入、接收检查过的值。运行、单步与提交都消费画布产物，没有第二条积木路径。详见 [08-节点画布技术决策](archive/graph-2026-10-19/08-节点画布技术决策.md)。

## 3. 一次请求如何流转

1. 浏览器请求题目列表，服务端只返回公开元数据。
2. 浏览器创建会话；服务端在内存中创建一个调试实例和一个判题实例。
3. 浏览器发送受限动作，例如 `write_bytes`、`step`、`run`、`undo` 或画布展开的原子动作。
4. 服务端串行校验并执行动作，VM 生成公开投影；隐藏 VMA、私有题包内容和 flag 不进入投影。
5. 点击提交时，服务端丢弃/重置判题实例，从初始状态回放 payload。
6. 只有判题实例满足成功条件时才返回 flag；调试实例中的 `satisfied` 只表示当前试验状态满足条件，不代表通过。

## 4. 会话和数据边界

- 会话只保存在服务端内存，重启后丢失；空闲会话会被回收。
- 调试实例用于反复试验，判题实例用于证明 payload 自足；两者互不污染。
- 浏览器接收的是公开投影：可见内存、寄存器、指令、状态、错误和回放帧。
- hidden VMA、`private.json`、`solution.md` 和 flag 不通过 API、静态文件或错误信息泄露。
- 题目伪代码写在可选的 `challenges/<id>/pseudocode.c`，属于公开面：加载时规范化（去 BOM、统一 LF、去末尾空白）后并入公开包的 `pseudocode` 字段，随 `GET /api/challenges/:id` 下发。`public.json` 里不能直接写这个字段；空文件、超过 `MAX_PSEUDOCODE_CHARS`（20 000 字符）、含 `env:FLAG_` 占位符或 flag 真值的伪代码会让该题拒绝加载。
- flag 通过部署环境中的 `FLAG_<CHALLENGE_ID>` 注入，不写入仓库。

## 5. 当前题目梯度

当前题库有七道题：`endian`、`pushpop`、`callret`、`stackframe`、`localvar`、`ret2win`、`ret2rop`，从内存与小端序逐步过渡到栈帧、局部变量覆盖、返回地址覆盖和 ROP 链。前六道是 MVP 交付，`ret2rop` 是之后补的 ROP 链题目。

## 6. MVP 的刻意边界

MVP 不是通用 x86 模拟器，也不是在线 CTF 平台。它只实现教学所需的受控指令、VMA、syscall、题目判定和回放能力；认证、持久化、多租户、完整 ELF/x86、ASLR/PIE、排行榜和平台自动交题等能力留到后续阶段。

## 7. 前端交互要点

以下只描述浏览器侧的组织方式，不改变 §3–4 的边界：前端的编译、运行和终止都只是组织受限动作的发送方式，判定仍在服务端。

- **路由**：history 路由，`/` 是题目列表（只有一道题也停在列表），`/challenges/<id>` 是题目页；刷新、前进后退和直接打开链接都落到对应页面。id 不在服务器题目列表里时显示「题目不存在」。服务端只对 `/` 和 id 形状合法的 `/challenges/<id>` 回 `index.html`，其余未命中路径仍是 404，不做通配回退。请求在飞时前进后退不切页。
- **布局**：顶栏放「返回题目列表」、调试 / 判题结果切换和「运行」菜单（单步、运行 N 步、后退一步、撤销、重置、提交判题）；左侧是视图区，右侧是 payload 窗口，底部通栏是输出区，最下方是状态栏 `DEBUG │ <状态> │ ip=0x… │ 动作 n/m`。
- **视图**：视图区一次只显示一个视图，用固定标签（栈、指令、寄存器、内存，以及本题可用时的 I/O 和伪代码）切换，支持 ←/→/Home/End 和页面级 Ctrl+↑/↓。当前标签存于 `localStorage` 的 `p2b:view-tab`，所有题目共用；读取失败或值非法时回到「栈」。伪代码视图显示公开包里的 `pseudocode`（见 §4），等宽只读，并按 C 语法着色：注释、预处理指令、字符串、数字、关键字、类型和函数名各用一种颜色（`--p2b-syn-*`，与值区域的语义色分属两条轴）。着色只是可读性装饰，不承载额外信息，文本仍是纯数据经 Lit 插值、不经过 `innerHTML`；题目没有伪代码时不出现该标签。
- **payload 窗口**：节点画布占据右栏（左栏留一份、右栏两份），标题栏是编译状态、运行/终止和撤销/重做。工具箱按阶段列出节点，检查器就地改参数、切「手填 / 接线」、进模块和升级调用。改动后自动编译，也可手动重编译；编译错误、执行结果和判题信息都进入输出区，点击条目定位节点。
- **运行 / 终止**：「运行」先发 `[reset]`，再按 `MAX_ACTIONS_PER_REQUEST` 分片发送完整动作序列，末尾不补 `run`，因此调试实例看到的就是判题实例将回放的序列；空程序发 `[reset]` + `[run]`。「终止」只是客户端的取消标志：不再发送后续分片，已发出的请求不撤回，服务端没有对应动作。
- **题面 Markdown**：题面和提示由自研解析器转成节点树，再由 Lit 插值渲染，不使用 `innerHTML`。支持标题、段落、代码块、引用、列表（最多 3 层）、分隔线、粗体、斜体、行内代码和链接文字；链接不生成 `<a>`。
