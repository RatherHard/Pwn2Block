# 02 VM 模块

VM 模块有五条设计目标，作为硬性规范，下面逐条落成 MVP 方案。

| 设计目标 | MVP 落地 |
|---|---|
| 位宽由出题人指定 | `archBits ∈ {32, 64}` |
| 寄存器名称、种类、数量由出题人自由设定 | 寄存器列表自由命名，另指定 `sp / bp / ip` 三个角色 |
| 以 VMA 为基本单元，权限、类型、大小由出题人设定 | 见 §3，大小须为 4KB 的倍数 |
| 指令集由出题人自由设定 | 出题人定义“指令作用 ↔ 机器码”的映射表，指令作用从内置语义中选取 |
| 未获取的内存数据不提前下发 | 隐藏 VMA 不下发；“获取”后（读入可见内存，或执行 reveal）才可见 |

## 1. 数值与端序

- 所有值以 64 位容器承载，按 `archBits` 掩蔽高位。算术、移位和比较都在掩蔽域内进行，溢出时按 2^archBits 回绕。
- 端序固定为小端（little-endian）。
- 字长 `W = archBits / 8` 字节，内存操作数、立即数、栈槽都按 W 计。
- 题目包和 API 中的地址与值一律使用十六进制字符串，例如 `"0x7ffff000"`。

## 2. 寄存器

出题人声明寄存器列表，例如：

```json
{ "registers": ["RAX", "RDI", "RSP", "RBP", "RIP"],
  "roles": { "sp": "RSP", "bp": "RBP", "ip": "RIP" },
  "secretRegisters": [] }
```

- 寄存器名匹配 `^[A-Z][A-Z0-9_]{0,15}$`，数量为 1–32。
- `roles` 必须指定栈指针、帧指针和指令指针。这样 32 位题目可以命名为 `ESP / EBP / EIP`，不强制使用固定的字面名。
- `secretRegisters` 中列出的寄存器，其值永不进入公开投影，只能用于判题。
- 标志位只有 `ZF / CF / SF` 三个，由引擎内置。它们不含秘密，会出现在投影中供教学展示。
  - `add / sub / cmp` 设置全部三个标志。
  - 逻辑运算和移位只设置 `ZF / SF`。

## 3. 虚拟内存（VMA）

```json
{ "id": "stack", "kind": "stack", "label": "栈",
  "start": "0x7fffe000", "size": "0x2000", "perm": "rw",
  "hidden": false, "init": [ { "at": "0x7fffff10", "hex": "00…" } ] }
```

| 字段 | 约束 |
|---|---|
| `id` | 题内唯一 |
| `kind` | `code / global / stack / heap / key / custom`。`key` 表示关键区；`custom` 必须带 `label` |
| `start` / `size` | `size` 为 0x1000 的倍数；`start` 按 0x1000 对齐；各 VMA 互不重叠 |
| `perm` | `r / w / x` 的任意子集 |
| `hidden` | 为 `true` 时整个区域不进入投影，只能写在私有包里 |
| `init` | 初始内容补丁列表 `[{ "at": "0x…", "hex": "…" }]`，补丁不得越出本 VMA；未覆盖的部分为 0 |

访问规则如下：

- 读需要 `r`，写需要 `w`，取指需要 `x`。违反时报 `memory_fault`。
- 访问未映射地址时报 `memory_fault`。
- 学习者对隐藏 VMA 发起的任何直接动作，其响应与访问未映射地址逐字节一致。
  - 包括错误码、错误文案、有无副作用。
  - 这样学习者无法通过探测画出隐藏布局。
- 程序指令在执行时可以正常读写隐藏 VMA，权限检查照常进行。这正是“获取”数据的途径。

“获取”的语义：隐藏数据一旦被程序复制进可见 VMA，或被接口效果 `reveal` 公开，就自然出现在投影里。除此之外不存在别的揭示通道。

## 4. 指令集：作用 ↔ 机器码映射

MVP 只支持**字节形态**：程序就是 code VMA 里的字节，IP 是字节地址。取指可以从任意可执行地址开始，因此指令中间的 gadget 也能执行。MVP 不支持 IR 形态。

出题人在**公开包**中声明编码表 `encoding`。编码表不含秘密，学习者需要它来理解机器码、寻找 gadget。表里每一项把 1 字节 opcode 映射为“内置作用 + 操作数形态”：

```json
{ "opcode": "0x50", "op": "push", "operands": ["reg:RBP"] },
{ "opcode": "0xb8", "op": "mov",  "operands": ["reg:RAX", "imm"] },
{ "opcode": "0xe8", "op": "call", "operands": ["imm"] }
```

- 操作数形态共四种：
  - `reg:R`：固定寄存器
  - `const:N`：固定常量，例如 `syscall` 的接口号
  - `imm`：内联立即数
  - `mem:R+disp`：内存操作数，`disp` 为内联位移
- 寄存器操作数固定写进 opcode。同一个助记符搭配不同寄存器，就是不同的 opcode。这样编码最简单，也能让学习者直接看懂机器码。
- `imm` 和 `disp` 按 W 字节小端紧跟在 opcode 之后。
- 内存操作数写作 `mem:REG+disp`，有效地址 = 寄存器 + disp，按 2^archBits 回绕。
- 出题人可以给每项配置 `mnemonic` 作为显示名，默认取 `op`，供指令视图的伪汇编使用。
- 未命中编码表的字节在取指时报 `invalid_instruction`，在指令视图中显示为 `db 0x??`。
- 编码表可以只声明题目用到的那部分作用；没有声明的作用在本题中不存在。
- 项目提供一张默认编码表（x86 风味的 opcode 取值），出题人可以直接引用并按需增删，不必从零设计。配套的汇编器让出题人写伪汇编而不是手写 hex，见 [06](06-出题指南.md)。
- 反汇编（伪汇编）由服务端针对可见的可执行区域生成，随投影下发。前端不自己实现解码器。

### 4.1 内置指令作用（封闭集）

| 作用 | 操作数形态 | 语义 |
|---|---|---|
| `mov` | R,I / R,R / R,M / M,R | 赋值 |
| `push` | R / I | `sp -= W; [sp] = v` |
| `pop` | R | `r = [sp]; sp += W` |
| `add` `sub` `cmp` | R,R / R,I / R,M | 算术，设置标志；`cmp` 不写回 |
| `and` `or` `xor` `shl` `shr` | R,R / R,I | 位运算；移位量对 archBits 取模 |
| `jmp` | I / R / M | 无条件跳转 |
| `je` `jne` `jb` `jae` | I | 条件跳转（ZF / CF） |
| `call` | I / R | `push 下一条地址; ip = 目标` |
| `ret` | — | `ip = pop`；允许无配对 call（ROP） |
| `leave` | — | `sp = bp; pop bp` |
| `syscall` | const / I（接口号） | 派发到出题人接口，见 §5 |
| `nop` | — | 无操作 |

跳转目标 I 是绝对地址，这样实现最简单，学习者也能直接看到地址。相对跳转留到 P1。

## 5. 出题人接口（syscall）

`syscall N` 按接口号查找私有包里的 `interfaces[]`：

```json
{ "id": 1, "name": "read_flag", "effects": [ { "type": "reveal", "vma": "flag" } ] }
```

接口效果是封闭原语的有序列表。执行完毕后直接继续执行下一条指令，不压栈。

| 效果 | 语义 |
|---|---|
| `exit` | 程序结束，立即判题 |
| `reveal` | 把指定隐藏 VMA 变为可见 |
| `set_flag` | 把指定 secret 寄存器置为常量，供判题使用 |
| `copy` | 在两段内存之间复制固定长度，权限检查照常 |
| `noop` | 无 |

- 接口号未声明时报 `invalid_instruction`。
- 接口没有宿主副作用，也不能执行任意代码。

## 6. 执行模型与异常

- 一次 `step` 执行恰好一条指令：取指 → 解码 → 执行 → 判题。
- 运行受资源上限约束，默认值为：
  - 单次运行最多 10 000 步
  - 每会话累计最多 1 000 000 步
  - 历史快照最多 1 000 份

  超出上限时报 `resource_limit`。

| 异常 | 触发 |
|---|---|
| `memory_fault` | 越权、未映射或隐藏区域的非法访问 |
| `invalid_ip` | ip 落在不可执行或未映射的地址 |
| `invalid_instruction` | 未命中编码表，或接口号未声明 |
| `resource_limit` | 超出步数上限 |

- 指令执行期间发生异常时，会话进入 `failed`。学习者可以 undo 回到异常前的状态，便于在教学中反复尝试。
- 错误响应由服务端用模板生成，内容包括出错地址（仅限可见地址）、原因，以及一条教学提示。
  - 例如：“`ret` 跳到了 0x4141414141414141，该地址未映射。检查 padding 长度和小端序。”
  - 涉及隐藏地址时只给出“地址不可访问”，不暴露任何细节。

## 7. 快照与确定性

- 引擎完全确定：不读取时间，不使用随机数。
- 内存按 4KB 分页，采用写时复制（COW）。每个执行类动作执行前压入一份快照，用于支持 undo。
- 实现语言建议使用 Rust，也可以用 TS 进程内实现。MVP 只要求 VM 运行在服务端，不要求独立进程隔离。
