# 10 前端设计基线

这份文档是当前真实前端的视觉和交互基线，服务于 `packages/web` 的实现与验收。它不再描述一套独立原型，也不复制 API 契约。

## 页面目标

Pwn2Block 是一个深色调试工作台。用户应该能在同一屏完成三件事：读懂题面、构造 payload、观察 VM 投影。视觉重点留给当前状态、变化数据和可执行操作。

## 固定结构

```text
顶部导航：品牌 / 视图菜单 / 运行菜单 / 调试与判题结果
题面卡片：题目说明与分级提示，可折叠
状态条：当前模式、执行结果、错误或恢复提示
主工作区：左右两栏
  左栏：两个视图槽位，可滚动切换栈、指令、寄存器、内存、I/O
  右栏：运行工具栏 → Blockly 画布 → 程序区 → 输出区
判题模式：结果横幅、flag、被拒动作定位、回放时间线
```

左右栏保持相等的主视觉权重；窄屏降为单列，两个区域各自保持可滚动和可操作。

## 视觉语言

- 深海蓝背景，青绿色作为主操作色；黄色表示变化/警告，红色表示错误，紫色表示隐藏标记，蓝色表示键盘焦点。
- 正文使用系统无衬线字体；地址、寄存器、hex、伪汇编和表格使用等宽字体。
- 面板使用 1px 低对比边框、圆角和轻阴影建立层次；避免大面积纯黑和连续细线。
- 控件高度、内边距和圆角保持一致；禁用状态降低对比度但仍能读清原因。
- 颜色不能单独承载状态：状态同时提供文字、符号或标签。

## 交互基线

- 视图菜单可显示/隐藏并调整顺序；`Ctrl+↑ / Ctrl+↓` 切换视图。
- 顶部“运行”和 payload 工具栏使用同一份按钮模型，禁用原因保持一致。
- Blockly 修改后立即标记产物过期并重新编译；编译错误和被拒动作都能定位到积木。
- 题面可折叠，提示按失败次数自动解锁，也可手动揭示并保存进度。
- 判题结果复用同一套视图，回放时间线只改变选中的服务端录像帧，不覆盖调试实例。
- 所有按钮、菜单、折叠区、输入框和时间线必须可键盘操作，并提供可读的 `aria-label` 或状态播报。

## 验收尺寸与检查

优先检查 1440×900，再检查 1280×720 和 1920×1080；窄屏检查 980px 和 620px 两个断点。

- 顶部操作和模式状态始终可见。
- 视图、画布、程序和输出都能滚动，不出现内容被裁切。
- 加载、空态、恢复失败、编译失败、请求中、已满足、判负、被拒、成功和过期状态都有清楚的下一步。
- 焦点环、变化行、当前指令、隐藏字节和错误定位在深色背景上可辨识。
- 视觉验收必须基于真实 `packages/web` + API；`design/frontend` 里的旧截图只作历史参考。

## 修改边界

视觉调整优先改 `packages/web/src/theme.ts` 和组件自己的 `static styles`。不要复制一套状态逻辑或改变事件契约；改变布局语义时同步 [05-前端交互](05-前端交互.md)。
