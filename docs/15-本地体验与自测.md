# 本地体验与自测

适用版本：2026-10-16 的 D7 交付。核心功能可以本机体验，但完整 MVP 尚未验收，G4 未放行；残留事项集中见 [14-MVP未完成事项](14-MVP未完成事项.md)。本文以 Windows PowerShell 为例，使用仓库提供的假 flag。

## 1. 安装、构建和启动

在仓库根目录打开 PowerShell。项目要求 Node >=22、pnpm 11.25.0；本轮实际验证环境为 Node 24.20.0、pnpm 11.25.0。

```powershell
Set-Location 'F:\Pwn2Block'
node --version
pnpm --version
pnpm install --frozen-lockfile
if ($LASTEXITCODE -ne 0) { throw '依赖安装失败，请先处理终端错误' }
pnpm build
if ($LASTEXITCODE -ne 0) { throw '构建失败，请先处理终端错误' }
$env:PORT='8798'
node --env-file=.env.example --import tsx packages/server/src/index.ts
```

保持这个终端运行，在浏览器地址栏输入 `http://127.0.0.1:8798`。这会使用生产构建，前后端同源。`.env.example` 只含公开测试值；不用创建真实 `.env`。进程中已有的同名变量优先于样例文件，如果曾设置过 `FLAG_*`，请在专用终端将它们设为样例值再运行。

**`pnpm start` 本身不会加载 `.env` 或 `.env.example`**，因此上述命令显式让 Node 读取样例。监听地址固定为 `127.0.0.1`。若 8798 已占用，改用一个空闲端口，并同步修改浏览器地址和后续测试地址。

另开一个 PowerShell 终端检查后端：

```powershell
Invoke-RestMethod 'http://127.0.0.1:8798/api/health'
$challengeList = Invoke-RestMethod 'http://127.0.0.1:8798/api/challenges'
$challengeList | Select-Object id
$challengeList.Count
```

预期健康请求成功，列表有六题：`ret2win`、`endian`、`pushpop`、`callret`、`stackframe`、`localvar`。

## 2. 手动体验一条完整交互路径

建议先用桌面 Chromium 浏览器，将窗口展开。以下步骤对应已有三尺寸冒烟覆盖的实际交互，不要求先完成题目解法。

| 步骤 | 操作 | 观察点 |
|---|---|---|
| 进入题目 | 点击「回到胜利」 | 出现题面、内存/寄存器区域和积木画布，「编译」可用 |
| 检查布局 | 折叠题面，打开顶部「视图」菜单；用 Tab 移动焦点、Enter 操作菜单 | 双栏可用，工具栏按钮可见，键盘焦点可辨认 |
| 搭建最小程序 | 从「开始」分类拖出开始积木；从「动作」分类拖出单步积木，接到开始积木下方，参数为 1 | 两块正确吸附连接；单步数值参数保留 |
| 编译 | 点击「编译」 | 程序区恰有一条 `step`，文案为「执行 1 条指令」 |
| 调试与回退 | 点击工具栏「单步」，再点「后退一步」 | 执行计数先增加再恢复，状态显示随之更新 |
| 判题与回放 | 点击「提交判题」 | 这段最小程序预期为 `incomplete`（未完成），并可查看判题回放；它不是通关程序 |
| 查看时间线 | 操作「回放时间线」，也可聚焦后按 Home / End | 可以查看初态和末态 |
| 返回调试 | 点击「回到调试」 | 回到此前调试状态，判题回放不覆盖调试实例 |
| 刷新恢复 | 刷新页面，再次点击「回到胜利」 | 服务仍运行且会话未过期时接回旧会话；积木连接、参数恢复，再点「编译」仍得到同一条指令 |

要体验更多页面，可切换其他题目阅读题面、观察不同初始状态与内存视图。教学材料索引见 [六题交付说明](12-六题交付说明.md)。

## 3. 可选：自行跑自动检查

先让上面的服务保持运行。在第二个 PowerShell 终端进入仓库根目录，首次运行浏览器测试时安装 Chromium，然后跑三个桌面尺寸的冒烟：

```powershell
Set-Location 'F:\Pwn2Block'
pnpm exec playwright install chromium
if ($LASTEXITCODE -ne 0) { throw '浏览器安装失败' }
$env:PWN2BLOCK_E2E='1'
$env:PWN2BLOCK_BASE_URL='http://127.0.0.1:8798'
$env:PWN2BLOCK_E2E_OUTPUT_DIR=('.tmp/self-test-' + (Get-Date -Format 'yyyyMMdd-HHmmss-fff'))
pnpm e2e --project=chromium-desktop-1280x720 --project=chromium-desktop-1440x900 --project=chromium-desktop-1920x1080
```

预期 **3 passed、0 skipped**。如想看到浏览器操作，可给最后一条命令追加 `--headed`。截图和失败 trace 在指定的 `.tmp/self-test-*` 目录，JSON 报告在同名 `.json` 文件。没有设置 `PWN2BLOCK_E2E=1` 时测试会跳过；全 skipped 不代表通过。此命令只覆盖三个尺寸的交互冒烟，不代表 G4 或完整 MVP 验收通过。

代码质量和已有全量测试可分别运行，逐项确认退出码为 0：

```powershell
pnpm typecheck
pnpm lint
pnpm test:coverage
```

构建应先于全量测试完成，以便测试实际静态产物。本轮基线结果为 112 个文件通过、1617 passed、5 个既有 todo，todo 不是通过项；后续代码改动可能改变数量。完整历史证据及覆盖率见 [D7 验收与交接](13-D7验收与交接.md)。

## 4. 常见现象与停止

| 现象 | 处理或解释 |
|---|---|
| 浏览器打不开 | 查看启动终端是否报错；核对端口与健康请求，确认服务仍在运行 |
| 题目少于六个、某题 503 | 检查假 flag 配置是否加载、同名进程变量是否为空；修正后重启服务 |
| 首页缺失或仍是旧页面 | 在仓库根重新执行 `pnpm build`，再刷新；这套启动方式没有前端热更新 |
| 重启服务后旧会话消失 | 这是内存会话的既有行为；重新进入题目建立会话。浏览器保存的画布与服务端会话生命周期不同 |
| 构建提示 chunk 大于 500 kB | 当前已知非阻塞警告；以构建退出码判断成功，记录见交接文档 |
| 单元测试输出 canvas 未实现警告 | 既有 DOM 测试环境警告；查看最终测试结果，真实浏览器交互由上述冒烟验证 |

结束时回到服务终端按 Ctrl+C；端口应随本次服务关闭。更多环境配置和部署边界见 [部署与内部试用](11-部署与内部试用.md)。
