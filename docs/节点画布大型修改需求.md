# 节点画布大型修改需求

状态：需求对齐中，尚未形成完整实现与验收基线。

原始说明：[节点画布大型修改.md](节点画布大型修改.md)。本文持续记录原文要求、访谈确认的规则和待确认问题；待确认项不能视为已接受的设计。

## 1. 修改目标与原文范围

重构节点画布的数据组织、流程表达与视觉交互，使用户通过数据节点、吸附拼接、派生变量和包络转换快速搭建 payload。

以下范围以原文为基础，并纳入访谈中已确认的调整；尚未明确的具体语义和边界仍需逐项对齐：

- 画布区分流程节点、数据节点、转换节点。
- 数据类型包括 byte、int、double、string、bool；数据节点以变量或常量形式存在。
- 数据连接可表达运算、赋值、逻辑和拼接关系。
- byte/string 支持吸附拼接，可选择合并为一个串或保留各串构成数组；其他类型也支持通过吸附构成数组。
- 拼接顺序先从左到右、后从上到下；同一行完整连接，各行开头对齐。
- 全局变量可不显式指定初值，默认零值规则见 R-08；依赖其他全局变量的初始化表达式建立派生关系。
- 数组、字符串支持切片；bool 节点支持取反。
- 转换节点包络整体或局部数据结构，对整体值转换；包络与内部结构共同作为数据节点使用。
- 流程节点包括开始、条件分支、次数循环、条件循环、break、continue、出题人提供的方法和模块封装。原文中的跳转节点已取消，见 R-37。
- 循环包络流程结构；条件循环的条件判定包络数据结构。
- 模块类似带形参与实参的函数，也能作为数据节点使用；未提供返回值时默认为 int(0)。
- 节点使用白色大方框；数据连接以留有间距的彩色中小方框表达；流程连接使用非白色直角线与外置小方框接点。
- 移除 Python 支持，具体删除范围和旧数据处理方式待确认。

## 2. 已确认规则

### R-01 变量定义、运行时修改与派生关系

确认依据：用户同意第一轮关于赋值连接与运行时修改的建议。

1. 定义时的赋值连接负责确定普通变量的初始值，或建立派生变量的表达式关系。
2. 使用常量赋值时，确定变量初始值；初始化表达式引用其他全局变量时，建立持续的派生关系。
3. 执行过程中修改普通变量，必须由流程在明确的执行步骤触发。
4. 派生变量由其表达式计算，不允许直接改写。
5. 读取派生变量时，结果反映其依赖变量的当前值。
6. 普通变量未显式指定初值时，默认初始化为对应类型的零值，见 R-08。

示例：

```text
base   = 0x1000
offset = 0x20
target = base + offset
```

其中 base、offset 为具有初始值的普通变量，target 为派生变量。

验收场景：

| 操作 | 预期结果 |
|---|---|
| 修改 base 前读取 target | 得到 0x1020 |
| 流程执行修改操作，将 base 设为 0x2000，再读取 target | 得到 0x2020 |
| 对 target 发起直接修改 | 不允许改写；提示位置与阻止时机待确认 |

上述示例仅说明已确认的赋值与派生语义，不规定表达式输入方式或连接控件样式。

### R-02 byte 表示可变长字节串

确认依据：用户明确要求 byte 按“可变长字节串”理解。

1. 原文中的 byte 表示字节串，不表示只能容纳一个字节的标量；一个数据节点可以容纳多个字节。
2. 字节串片段合并时，结果是一个连续的字节串。
3. 选择保留各串构成数组时，每个片段作为一个字节串元素保留，不自动展开为单字节元素。
4. 需求正文使用“字节串”指代该概念；界面及存档中的类型标识是否由 byte 改为 bytes，留待命名与兼容性规则确定。

验收场景：两个字节串节点分别包含十六进制 `41 42` 和 `43 44`。

| 拼接模式 | 预期结果 |
|---|---|
| 合并为一个字节串 | `41 42 43 44`，共 4 字节 |
| 保留各串构成数组 | `[字节串(41 42), 字节串(43 44)]`，共 2 个字节串元素 |

字节串的长度上限与编辑方式尚待确认；混合类型的拼接约束见 R-03，空值规则见 R-07。

### R-03 数组同类型与显式转换

确认依据：用户明确要求“数组元素同类型，混合类型先显式转换”。

1. 同一个数组的元素必须具有相同类型，不进行隐式类型转换。
2. 不同类型的数据需要先通过转换节点统一类型，再组成数组或合并为串。
3. 字节串数组中的各元素可以具有不同的字节长度；长度不同不代表类型不同。
4. 字符串和字节串属于不同类型，不能直接混合合并；需要显式转换。

验收场景：

| 输入与操作 | 预期结果 |
|---|---|
| int(1) 与 int(2) 组成数组 | 得到整数数组 `[1, 2]` |
| 字节串 `41 42` 与字节串 `43` 组成数组 | 得到含 2 个字节串元素的数组，保留各元素长度 |
| int(1) 与 string("A") 直接组成数组 | 不允许；要求先显式统一类型 |
| 字符串 "AB" 与字节串 `43 44` 直接合并 | 不允许；要求先显式转换为相同类型 |

整数与字节串转换的默认参数见 R-20，文本转换的默认编码见 R-19；其他转换参数仍待确认。数组嵌套规则见 R-04，编辑中的类型冲突处理见 R-17，错误提示与执行阻止规则见 R-18。

### R-04 显式嵌套数组与换行

确认依据：用户明确要求“支持显式构造嵌套数组，画布换行不自动增加数组层级”。

1. 同一个吸附拼接结构内，元素按先从左到右、后从上到下的顺序排列；换行不自动产生子数组。
2. 支持先构造数组，再将该数组作为完整元素组成上层数组，以此显式表达嵌套。
3. 数组嵌套继续遵守同类型约束：整数数组可以与整数数组组成上层数组；整数与整数数组不能直接混在同一层。
4. 对字节串使用合并模式时，换行也不引入额外的数据层级；依照同一读取顺序合并为一个字节串。

验收场景：

| 结构与操作 | 预期结果 |
|---|---|
| 同一拼接结构中，第一行是 int(1)、int(2)，第二行是 int(3)、int(4) | 得到 `[1, 2, 3, 4]` |
| 将数组 A = `[1, 2]` 与数组 B = `[3, 4]` 各自作为完整元素组成新数组 | 得到 `[[1, 2], [3, 4]]` |
| 将 int(1) 与整数数组 `[2, 3]` 直接作为同一数组的元素 | 不允许，元素类型不同 |
| 合并模式下，第一行是字节串 `41`、`42`，第二行是字节串 `43`、`44` | 得到单个字节串 `41 42 43 44` |

嵌套的具体编辑方式、子数组长度是否必须相等、首次创建空数组时的类型指定方式和最大嵌套深度尚待确认；清空已有数组时的类型保留规则见 R-07。

### R-05 拼接结构的拖动与重排

确认依据：用户明确要求“拖动预览、落位后更新拼接顺序，整体移动不改变值”。

1. 整体移动拼接结构时，内部顺序与结果值保持不变。
2. 在结构内拖动元素调整顺序时，显示插入位置预览；成功落位后，按新位置更新拼接顺序。
3. 拖动途中不修改已经确定的数据；取消拖动时保留原顺序与结果值。
4. 仅调整换行位置且元素的读取顺序不变时，结果值保持不变。
5. 完成重排后的预览与后续求值必须使用新的拼接顺序。

验收场景：原拼接结构为 `[AA] [BB] [CC]`，使用字节串合并模式。

| 操作 | 预期结果 |
|---|---|
| 整体移动结构 | 结果仍为字节串 `AA BB CC` |
| 将 CC 拖向 AA 与 BB 之间，尚未落位 | 显示插入位置预览，已确定的结果仍为 `AA BB CC` |
| 在 AA 与 BB 之间完成落位 | 顺序更新为 AA、CC、BB，结果变为 `AA CC BB` |
| 预览插入位置后取消拖动 | 恢复原排列，结果仍为 `AA BB CC` |
| 将原排列换行为第一行 AA、BB，第二行 CC | 结果仍为 `AA BB CC` |

拖出元素与自动补位的规则见 R-06；拖入新元素和非法落点的行为尚待确认。

### R-06 拖出元素与自动补位

确认依据：用户明确要求“拖出即解除拼接，剩余元素自动补位，保留相对顺序”。

1. 将元素拖到拼接结构外的空白处并松手后，解除该元素与原结构的拼接关系；被拖出的节点保留在画布上。
2. 原结构中的剩余元素自动补位，并保留原有相对顺序；补位后的排列继续满足同行完整连接、各行开头对齐的要求。
3. 拖出作为完整元素的子数组时，父数组移除该元素，子数组的内部结构保持不变。
4. 拖动途中只显示预览，不提前移除元素；取消拖动则保留原结构与结果值。

验收场景：

| 原结构与操作 | 预期结果 |
|---|---|
| 字节串合并结构 `[AA] [BB] [CC]` 中，将 BB 拖到外部空白处并松手 | 原结构补位为 `[AA] [CC]`，结果为 `AA CC`；BB 保留为独立节点 |
| 上述拖出操作在落位前取消 | 原结构与结果仍为 `AA BB CC` |
| 嵌套数组 `[[1, 2], [3, 4], [5, 6]]` 中，将完整子数组 `[3, 4]` 拖出 | 父数组变为 `[[1, 2], [5, 6]]`；被拖出的子数组仍为 `[3, 4]` |

原结构仅剩一个元素或没有元素时的规则见 R-07；跨结构直接拖入的行为尚待确认。

### R-07 单元素与空拼接结构

确认依据：用户明确要求“剩一个或零个元素时，仍保留结构、类型与拼接模式”。

1. 移出元素后，即使原结构只剩一个元素或没有元素，也保留原结构、结果类型与拼接模式，不自动拆解或删除。
2. 数组只剩一个元素时仍为数组，不自动变为该元素；嵌套数组也不自动减少层级。
3. 数组清空后保留原元素类型；例如整数数组清空后仍是整数数组，整数数组的数组清空后仍保留对应的嵌套类型。
4. 字节串合并结构清空后，结果为长度为 0 的字节串。
5. 空结构在画布上保留可继续放入元素的位置。
6. 空数组、空字节串是明确的值；普通变量未显式指定初值时使用对应类型的默认零值，见 R-08。

验收场景：

| 原结构与操作 | 预期结果 |
|---|---|
| 整数数组 `[1, 2]` 中移出 2 | 得到整数数组 `[1]`，不变为 int(1) |
| 将上述数组中最后一个元素移出 | 得到保留整数元素类型的空数组 `[]`，结构继续存在 |
| 嵌套数组 `[[1, 2], [3, 4]]` 中移出第二个子数组 | 得到 `[[1, 2]]`，保留两层 |
| 将上述嵌套数组中的最后一个子数组移出 | 得到元素类型仍为整数数组的空数组 |
| 字节串合并结构中移出所有片段 | 得到长度为 0 的字节串，保留合并模式与结构 |
| 向清空后的结构重新放入符合其类型的元素 | 按保留的类型与模式继续构造结果 |

首次创建空数组时如何指定元素类型、空结构的具体外观和删除结构的交互尚待确认。

### R-08 未显式指定初值的变量默认初始化为零值

确认依据：用户明确说明“未初始化就是初始化为零”。

1. 普通变量可以不显式指定初值；此时默认初始化为其类型对应的零值。
2. 变量不存在等待首次读取才初始化的独立“未初始化”状态，默认零值就是其当前值。
3. 具有显式初值的普通变量使用该初值；流程修改操作可以正常改变其当前值。
4. 派生变量继续按照表达式计算。依赖的普通变量没有显式初值时，使用该普通变量的默认零值参与计算，不将派生表达式的结果直接替换为零。
5. 读取变量不会因其未显式指定初值而报错，也不会覆盖流程已经写入的当前值。

验收场景：

| 场景 | 预期结果 |
|---|---|
| 定义 int 类型的普通变量 base，不显式指定初值 | base 的当前值为 0，可直接读取 |
| 在上述定义基础上建立派生变量 target = base + 0x20 | target 的值为 0x20 |
| 流程随后将 base 修改为 0x1000 | 再读取 base 得到 0x1000，读取 target 得到 0x1020 |
| 普通变量显式赋为空数组或空字节串 | 使用已有空值 |

各类型零值的具体定义见 R-09，重复运行时变量的生命周期见 R-10；编辑预览使用的值尚待确认。

### R-09 各类型的默认零值

确认依据：用户同意以下默认零值表。

| 类型 | 默认零值 |
|---|---|
| int | `0` |
| double | `0.0` |
| bool | `false` |
| string | 空字符串 `""` |
| byte（字节串） | 长度为 0 的空字节串 |
| 数组 | 保留元素类型的空数组 `[]` |
| 嵌套数组 | 空数组 `[]`，类型中保留完整嵌套层级 |

1. 字节串的默认零值不包含任何字节；内容为 `00` 的单字节字节串需要显式指定。
2. 嵌套数组的默认零值不自动生成子数组。例如，整数数组的数组默认没有元素，其值为 `[]`，类型仍保留两层数组结构。
3. 派生变量按照表达式计算，依赖的普通变量使用其对应类型的初值或当前值；例如 base 默认值为 0 时，target = base + 0x20 的值为 0x20。

验收时应覆盖表中的全部类型，并验证空字节串长度为 0、显式字节串 `00` 长度为 1，以及空嵌套数组保留完整类型。

### R-10 每次从头运行重新初始化变量

确认依据：用户同意“每次从头运行重新初始化，同一次运行内保留修改”。

1. 每次从头运行流程时，普通变量恢复其显式初值；没有显式初值的变量恢复对应类型的默认零值。
2. 派生变量按本次运行中依赖变量的值计算，不沿用上一次运行的计算结果。
3. 同一次运行内，流程对普通变量的修改持续有效，后续读取使用当前值。
4. 同一次运行内的循环迭代不会重新初始化全局变量。
5. 本条约束画布变量的生命周期；后端调试实例的状态如何处理不由本条规定。

验收场景：

| 场景 | 预期结果 |
|---|---|
| count 为未显式指定初值的 int 变量，流程循环三次，每次增加 1 | 本次运行中依次为 0、1、2、3 |
| 上述流程执行完成后，再次从头运行 | 重新从 0 开始，依次为 0、1、2、3 |
| count 显式初值为 10，流程循环三次，每次增加 1 | 每次从头运行都从 10 开始，最终为 13 |
| base 初值为 0，target = base + 0x20；某次运行将 base 改为 0x1000，随后重新从头运行 | 新运行中 base 恢复为 0，target 的值恢复为 0x20 |

编辑预览与运行结果的显示方式，以及模块参数和局部变量的生命周期尚待确认。

### R-11 派生依赖禁止成环，流程修改允许自增

确认依据：用户明确要求“派生依赖禁止成环，流程中的普通变量自增允许”。

1. 派生变量允许多级依赖；读取结果须反映各级依赖变量的当前值。
2. 派生关系禁止直接或间接依赖自身，包括自引用和多个变量之间的循环依赖。
3. 检测到派生依赖成环时，标出相关变量与连接，并阻止运行。
4. 流程中的普通变量修改可以先读取该变量的当前值，再计算并写回；`a ← a + 1` 每执行一次增加一次，不视为派生依赖成环。
5. 本条不改变派生变量禁止直接改写的规则。

验收场景：

| 定义或操作 | 预期结果 |
|---|---|
| base = 0x1000，address = base + 0x20，end = address + 8 | address 为 0x1020，end 为 0x1028 |
| 将上述 base 通过流程修改为 0x2000 | 再读取 address 得到 0x2020，读取 end 得到 0x2028 |
| 派生定义 a = b + 1，b = a + 1 | 检出循环依赖，标出相关变量与连接，阻止运行 |
| 派生定义 a = a + 1 | 检出自引用，阻止运行 |
| 普通变量 a 初值为 0，流程执行一次 a ← a + 1 | a 变为 1，允许正常运行 |

double 非有限数值的错误处理见 R-13；所有数据计算与类型转换错误的统一处理见 R-18。

### R-12 int 的精度与定长字节转换

确认依据：用户明确要求“int 为任意精度有符号整数，定长转换时检查范围，超出范围报错”。

1. int 表示任意精度有符号整数，支持负数；整数计算不隐式限制为 32 位或 64 位，也不因固定整数宽度发生截断或回绕。
2. int 转换为定长字节串时，由转换配置明确指定字节宽度、大小端与有无符号。
3. 转换前检查值是否处于目标表示范围；超出范围时报错，不自动截断高位或回绕。
4. 需要截取低位等处理时，用户应显式表达相应运算。

验收场景：

| 操作 | 预期结果 |
|---|---|
| 计算 `0xffffffff + 1` | 得到整数 `0x100000000` |
| 计算 `0 - 1` | 得到整数 `-1` |
| 将 `256` 转为 1 字节无符号字节串 | 报错，超出目标范围 |
| 将 `256` 转为 2 字节无符号小端字节串 | 得到 `00 01` |

整数与字节串转换的默认参数见 R-20，字节串转整数的输入长度校验见 R-21，有符号补码见 R-22，字节宽度见 R-23，整数除法与余数见 R-26。整数位运算与移位见 R-27；转换失败的执行处理见 R-18。

### R-13 double 的精度与非有限数值处理

确认依据：用户明确要求“double 为 64 位浮点数，允许正常舍入，非有限数值报错并停止执行”。

1. double 使用 64 位双精度浮点数，支持正负小数，允许正常的浮点舍入误差。
2. double 只接受有限数值。输入、运算或转换产生 NaN、正无穷或负无穷时，定位到相关节点并报错。
3. 运行中出现上述错误时，停止本次执行，不将异常结果替换为零，不将其作为有效值继续传给后续节点。
4. 默认零值初始化与数值计算失败是不同情形；R-08、R-09 的默认零值规则不用于掩盖非有限数值错误。

验收场景：

| 场景 | 预期结果 |
|---|---|
| double 输入或运算结果为有限的正数、负数或零 | 接受该值，允许正常浮点舍入 |
| 节点配置中输入 NaN、正无穷或负无穷 | 报错并定位相关节点，不作为有效 double 值接受 |
| 运行中的运算或转换产生 NaN、正无穷或负无穷 | 定位相关节点并报错，停止本次执行，后续流程不继续执行 |
| double 变量未显式指定初值 | 使用默认值 0.0，不视为计算失败 |

int 与 double 之间的显式转换见 R-24，算术与数值比较的同类型要求见 R-25；浮点字节表示的转换参数尚待确认。所有数据计算与类型转换错误的统一处理见 R-18。

### R-14 字符串与字节串的长度和切片单位

确认依据：用户明确要求“string 按 Unicode 码点，byte 按字节，分别计算长度和执行切片”。

1. string 按 Unicode 码点计算长度，切片边界也按码点定位。
2. byte（字节串）按实际字节数计算长度，切片边界按字节定位。
3. 字节串允许在任意字节边界切片，不要求保持完整的文本编码片段。
4. 字符串经显式编码转换为字节串后，按照所得字节串的单位处理；字节串中的字节数量不一定等于原字符串的码点数量。

验收场景：将字符串 `"A中"` 显式按 UTF-8 编码为字节串 `41 E4 B8 AD`。

| 数据与操作 | 预期结果 |
|---|---|
| 计算字符串 `"A中"` 的长度 | 2 个码点 |
| 从上述字符串切出第二个单位 | 得到字符串 `"中"` |
| 计算字节串 `41 E4 B8 AD` 的长度 | 4 字节 |
| 从上述字节串切出第二个单位 | 得到字节串 `E4`，允许保留不完整的文本编码片段 |

文本转换默认使用 UTF-8，节点明确显示编码，编码与解码失败时严格报错，见 R-19。其他可选编码的范围尚待确认；切片索引和边界规则见 R-15。

### R-15 切片索引、边界与步长

确认依据：用户确认采用所提议的统一切片规则。

1. string、byte 和数组统一采用 `start:end:step` 的切片语义：索引从 0 开始，包含起点，不包含终点。string 的索引单位为 Unicode 码点，byte 为字节，数组为当前层级的元素。
2. 支持负索引，从末尾倒数定位，`-1` 表示最后一个单位。
3. 起点和终点均可省略。正步长时，默认从第一个单位向后取到末尾；负步长时，默认从最后一个单位向前取到开头。负步长下省略终点表示越过首个单位的边界，与显式填写终点 `-1` 不同。
4. 起止边界越界时按遍历方向裁剪至有效切片边界，不因切片端点越界而报错。切片范围内没有符合方向和步长的单位时，得到同类型的空结果。
5. 步长默认为 `1`；支持负步长；步长为 `0` 时报错。
6. 切片结果保留输入类型。数组切片保留元素类型与嵌套层级，仅选取当前层级的元素，不展开子数组。
7. `start:end:step` 是语义记法，不要求界面必须使用文本语法；具体编辑控件另行对齐。

验收场景：以下数组示例的输入为 int 数组 `[10,20,30,40]`。

| 操作 | 预期结果 |
|---|---|
| `[1:3]` | `[20,30]` |
| `[-2:]` | `[30,40]` |
| `[:99]` | `[10,20,30,40]`，终点裁剪至末尾边界 |
| `[::2]` | `[10,30]` |
| `[::-1]` | `[40,30,20,10]` |
| `[2:2]` | 保留 int 元素类型的空数组 `[]` |
| `[::0]` | 报错，不产生有效切片结果 |
| 对嵌套数组 `[[1,2],[3,4]]` 执行 `[1:]` | `[[3,4]]`，保留嵌套层级 |
| 对 string `"A中"` 执行 `[1:]` | string `"中"` |
| 对 byte `41 E4 B8 AD` 执行 `[1:2]` | byte `E4` |

本规则定义切片，不据此推定单元素索引访问的越界行为。切片参数的编辑方式与参数合法性约束仍待确认；步长为零等切片错误按 R-18 处理。

### R-16 转换包络的选取范围与嵌套

确认依据：用户明确要求“连续选取、允许嵌套、禁止交叉”。

1. 转换包络可以包住完整的数据结构；包住拼接结构的局部时，必须选取拼接顺序中连续的一段，不允许跳过中间元素。
2. 连续性按已确认的拼接顺序判断，允许跨画布换行选取；视觉换行不改变包络的求值范围或数组层级。
3. 包络允许嵌套。两个包络的范围可以互不重叠，或由外层完整包含内层；不允许部分重叠、交叉覆盖。
4. 每个包络先求被包络结构的整体值，再执行指定转换。嵌套时由内向外求值，内层转换的输出参与外层结构的求值。
5. 转换节点与被包络内容共同视为一个数据节点，按转换后的输出类型参与外部结构；外部结构仍须满足同类型拼接等已有类型要求。

验收场景：拼接结构的顺序为 `A B C D`，以下仅检验范围关系；转换本身还须满足输入、输出类型要求。

| 包络操作 | 预期结果 |
|---|---|
| 包住 `B C` | 允许，对该连续片段的整体值执行转换 |
| 包住全部 `A B C D` | 允许，对完整结构的整体值执行转换 |
| 内层包住 `B C`，外层包住全部 | 允许，先计算内层转换，再求外层整体值并转换 |
| 分别包住 `A B` 和 `C D` | 允许，两个范围互不重叠 |
| 一个包住 `A B C`，另一个包住 `B C D` | 拒绝交叉包络 |
| 同一包络选取 `A C`，跳过 `B` | 拒绝不连续选取 |
| 第一行是 `A B`、第二行是 `C D`，选取 `B C` | 允许，跨行但拼接顺序连续 |

转换输出与外层类型不匹配时的编辑处理见 R-17，转换失败的统一处理见 R-18。包络内外节点的共享引用规则、一般运算结构的局部选取方式，以及支持的转换种类与参数尚待确认。

### R-17 编辑中的类型冲突与运行阻止

确认依据：用户明确要求“允许保留这种编辑中的无效结构，在冲突位置标错，并阻止运行，直到用户修复”。

1. 转换输出与外层拼接结构的类型要求不兼容时，允许保留该编辑状态，用户可以继续修改结构或补充显式转换。
2. 在类型冲突的位置标错，说明外层要求的类型与实际输出类型；冲突未修复前阻止运行。
3. 编辑器不自动进行隐式类型转换，也不因该类型冲突自动拆开原结构。
4. 用户修复后重新校验；冲突消失则清除对应错误，在不存在其他运行阻止条件时允许运行。
5. 允许保留编辑状态不改变 R-03 的同类型要求，类型冲突的结构不具有可供正常执行使用的有效拼接结果。

验收场景：`A B C D` 均为 byte，外层采用字节串合并模式。

| 操作或状态 | 预期结果 |
|---|---|
| 将包住 `B C` 的转换节点配置为输出 int | 保留包络及外层结构，在 int 输出与外层 byte 合并要求冲突处标错 |
| 类型冲突尚未修复时尝试运行 | 阻止运行，提示修复冲突 |
| 为该 int 输出补充显式转换，使其输出 byte | 重新校验，类型匹配后清除该冲突；不存在其他阻止条件时允许运行 |
| 用户尚未修复冲突 | 不自动转换成 byte，不自动拆开原拼接结构 |

本规则处理编辑中的类型不匹配；所有数据计算与类型转换错误的统一处理见 R-18。R-16 中禁止交叉和不连续包络的规则保持适用。

### R-18 数据计算与类型转换错误的统一处理

确认依据：用户要求将已提出的错误处理规则统一用于所有数据计算和类型转换错误。

1. 编辑时能够确定的计算或转换错误，应定位相关节点或冲突位置、说明原因，并阻止启动运行；用户可以继续编辑和修复。
2. 运行中才出现的数据计算或类型转换错误，应定位相关节点、说明原因，并立即停止本次执行，后续流程不继续执行。
3. 不以默认零值替代失败结果，不将失败结果作为有效输出传递。R-08、R-09 的默认初始化规则不适用于计算或转换失败。
4. 保留停止前的运行记录，供用户定位问题；已经发生的变量修改与后端动作不自动回滚。
5. 修复后重新校验，清除已解决的错误；不存在其他运行阻止条件时允许运行。每次从头运行的画布变量初始化仍遵循 R-10；本条不规定后端 VM 的重置规则。
6. 本规则统一错误发生后的处理方式；各运算、转换的合法输入、可选参数和精度规则分别定义，不由本条推定。

验收场景：

| 场景 | 预期结果 |
|---|---|
| 编辑时可确定将常量 `256` 转为 1 字节无符号字节串 | 标出超出范围的错误，阻止启动运行 |
| 运行中变量变为 `256`，随后转换为 1 字节无符号字节串 | 在转换节点报错，立即停止本次执行，不截断、不补零继续 |
| 编辑时切片步长已明确为 `0` | 标出步长错误，阻止启动运行 |
| 切片步长在运行中计算为 `0` | 在相关节点报错并停止本次执行 |
| double 运算或转换产生非有限数值 | 按 R-13 报错，并遵循本条的停止、记录保留与不自动回滚规则 |
| 已修改普通变量、已执行后端动作，后续数据计算失败 | 保留停止前的运行记录，不自动撤销此前修改或后端动作，后续流程不执行 |
| 修复已知错误后重新从头运行 | 校验通过后按 R-10 重新初始化画布变量并开始运行 |

### R-19 文本编码转换的默认值与严格校验

确认依据：用户明确要求“默认 UTF-8、明确显示编码、严格报错”。

1. string 与 byte 之间的文本编码转换默认采用 UTF-8；转换节点须明确显示当前使用的编码，包括使用默认值时。
2. string 转 byte 时，按指定编码生成字节串；无法按该编码表示或编码失败时严格报错。
3. byte 转 string 时，按指定编码解码；遇到无效或不完整的编码序列时严格报错，不自动插入替换字符，也不跳过出错字节。
4. 编码与解码错误统一按 R-18 处理：编辑时可确定的错误阻止启动，运行中出现的错误停止本次执行，不以零值或替代结果继续。
5. byte 本身不要求是合法的文本编码序列。按 R-14、R-15 执行字节切片时，可以产生不完整的文本编码片段；随后将其解码为 string 时才按所选编码检查合法性。

验收场景：

| 场景 | 预期结果 |
|---|---|
| 新建 string 与 byte 之间的文本转换节点 | 默认采用 UTF-8，节点显示 UTF-8 |
| 将 string `"A中"` 按 UTF-8 编码 | 得到 byte `41 E4 B8 AD` |
| 将 byte `41 E4 B8 AD` 按 UTF-8 解码 | 得到 string `"A中"` |
| 对 byte `41 E4 B8 AD` 执行 `[1:2]` | 得到有效的 byte 值 `E4`，切片本身不因文本编码不完整而报错 |
| 将 byte `E4` 按 UTF-8 解码 | 因编码序列不完整而报错，不产生替换字符、不跳过该字节；按 R-18 阻止启动或停止运行 |

UTF-8 之外的可选编码范围尚待确认。

### R-20 整数与字节串转换的默认参数

确认依据：用户明确要求“默认 8 字节、小端、无符号”。

1. 新建 int 与 byte 之间的转换节点时，默认参数为 8 字节、小端、无符号。
2. 默认值用于初始化转换配置，不限制 int 本身的任意精度，也不将所有 byte 值固定为 8 字节；定长转换仍按所配置的参数执行。
3. int 转 byte 时，数值超出所配置长度和符号模式可表示的范围，按 R-12、R-18 报错，不自动截断或回绕。

验收场景：

| 场景 | 预期结果 |
|---|---|
| 新建整数与字节串转换节点 | 默认配置为 8 字节、小端、无符号 |
| 按默认配置将 int `256` 转为 byte | 得到 `00 01 00 00 00 00 00 00` |
| 按默认配置将 byte `00 01 00 00 00 00 00 00` 转为 int | 得到 `256` |
| 按默认配置将 int `-1` 转为 byte | 因无符号模式不能表示负数而报错 |
| 按默认配置将 int `18446744073709551616`（2 的 64 次方）转为 byte | 超出 8 字节无符号范围，按 R-18 报错 |

byte 转 int 时输入长度不符的处理方式见 R-21，有符号模式的补码规则见 R-22，字节宽度与快捷选项见 R-23。参数控件的具体布局与修改交互尚待确认。

### R-21 字节串转整数的输入长度校验

确认依据：用户明确要求“长度必须匹配，否则报错，不自动补齐或截断”。

1. byte 转 int 时，输入字节串的实际字节数必须等于转换节点配置的字节数。
2. 输入长度不足或超出配置时均报错，不自动补齐，不自动截断，也不根据输入长度自动改变转换配置。
3. 长度错误统一按 R-18 处理：编辑时可确定的错误阻止启动，运行中出现的错误停止本次执行，不产生替代整数结果。

验收场景：转换配置为 2 字节、小端、无符号。

| 输入 | 预期结果 |
|---|---|
| `00 01` | 长度匹配，得到 int `256` |
| `01` | 长度不足，报错，不补齐为 2 字节 |
| `00 01 02` | 长度超出，报错，不截取其中 2 字节 |
| 空字节串 | 长度不足，报错，不按默认零值规则转换为 int `0` |

使用默认 8 字节配置时同样要求输入恰好为 8 字节；本条不改变 R-20 的默认参数。

### R-22 有符号整数转换的补码与范围

确认依据：用户明确要求“有符号模式使用指定宽度的补码，超出范围报错”。

1. int 与 byte 之间的转换在有符号模式下采用指定字节宽度的补码表示，正反转换使用同一规则。
2. 配置为 N 字节时，位宽为 `8N`，可表示的有符号整数范围为 `-2^(8N-1)` 至 `2^(8N-1)-1`，包含两端。int 转 byte 前检查范围，超出范围按 R-18 报错，不截断、不回绕。
3. byte 转 int 时，先按 R-21 检查长度，再按配置的字节序与有符号补码规则解释整个输入。
4. 同一字节串可以因符号模式不同而得到不同的整数；该解释由转换配置决定，不改变原字节串的内容，也不改变 int 的任意精度语义。

验收场景：以下均使用 1 字节宽度。

| 转换配置与操作 | 预期结果 |
|---|---|
| 有符号模式，int `-1` 转 byte | `FF` |
| 有符号模式，int `-128` 转 byte | `80` |
| 有符号模式，int `127` 转 byte | `7F` |
| 有符号模式，byte `FF` 转 int | `-1` |
| 有符号模式，byte `80` 转 int | `-128` |
| 有符号模式，byte `7F` 转 int | `127` |
| 有符号模式，int `128` 或 `-129` 转 byte | 超出范围，按 R-18 报错 |
| 无符号模式，byte `FF` 转 int | `255` |

本条不改变默认的无符号模式；新建节点的默认参数仍按 R-20。

### R-23 整数转换的字节宽度与快捷选项

确认依据：用户明确要求“支持任意正整数字节宽度，提供常用快捷选项，并受资源上限约束”。

1. int 与 byte 之间的转换允许配置任意正整数字节宽度，但不得超过统一资源上限。
2. 界面提供 `1、2、4、8` 字节快捷选项，并允许手动输入 `3、6、16` 等其他正整数宽度；默认仍为 R-20 规定的 8 字节。
3. `0`、负数、小数字节宽度均为非法参数，按 R-18 报错，不进行自动取整或修正。
4. 超过资源上限时明确报错，不自动缩小宽度。资源上限的具体数值与字节串长度、数组大小等运行限制一并确定。
5. 所有允许的宽度均适用既有规则：int 转 byte 检查数值范围，byte 转 int 检查输入长度，有符号模式采用指定宽度的补码。

验收场景：

| 操作或配置 | 预期结果 |
|---|---|
| 使用快捷选项设置为 1、2、4 或 8 字节 | 采用所选宽度执行转换 |
| 手动设置为 3、6 或 16 字节，且未超过资源上限 | 接受配置，按对应宽度执行转换 |
| 3 字节、小端、无符号，将 int `256` 转为 byte | 得到 `00 01 00` |
| 3 字节配置下，将长度为 2 字节的 byte 转为 int | 按 R-21 报错，不自动补齐 |
| 字节宽度设置为 `0`、`-1` 或 `1.5` | 参数非法，标错并阻止启动 |
| 字节宽度超过资源上限 | 明确报错，不采用较小宽度继续转换 |

### R-24 int 与 double 的显式转换

确认依据：用户明确要求“int 转 double 允许正常舍入，double 转 int 向零截断，非有限数值报错”。

1. int 显式转换为 double 时，按 64 位浮点数表示，允许正常舍入，不要求转换后的数值与原整数完全相等。
2. double 显式转换为 int 时，按当前实际数值向零截断，去掉小数部分；正数与负数均向零方向处理。结果为任意精度 int，不隐式限制为 32 位或 64 位整数。
3. 转换输入或结果为 NaN、正无穷或负无穷时，按 R-13、R-18 报错：编辑时可确定的错误阻止启动，运行中出现的错误停止本次执行。
4. 转换依据当前实际值进行。int 转 double 时已经因舍入丢失的精度，不会在随后转回 int 时恢复；往返转换不保证得到原整数。

验收场景：

| 转换 | 预期结果 |
|---|---|
| int `42` 转 double | 得到 double `42.0` |
| double `3.9` 转 int | 得到 int `3` |
| double `-3.9` 转 int | 得到 int `-3` |
| double `0.9` 或 `-0.9` 转 int | 得到 int `0` |
| double `3.0` 转 int | 得到 int `3` |
| int 转 double 发生正常舍入，但结果有限 | 接受舍入后的 double 值，不因精度变化报错 |
| int 转 double 产生非有限数值 | 按 R-18 报错，不返回可继续使用的转换结果 |
| 尝试将 NaN、正无穷或负无穷作为转换输入 | 按 R-13、R-18 拒绝，不替换为 int `0` |

int 与 double 不直接混合参与算术或数值比较，须先显式统一类型，见 R-25。

### R-25 算术与数值比较的同类型要求

确认依据：用户明确要求“算术与数值比较均要求同类型，混合类型先显式转换”。

1. 算术运算及数值比较要求操作数类型相同；int 与 double 混合时，必须先通过显式转换统一类型，不自动将 int 提升为 double，也不自动将 double 截断为 int。
2. 数值比较的同类型要求同时适用于大小比较和相等性比较；不能因数值看起来相等而跳过类型检查。
3. 用户选择统一为 int 或 double 后，按目标类型执行运算；显式转换中的舍入与截断遵循 R-24。
4. 类型冲突允许作为编辑中的无效状态保留，在冲突处标错并阻止运行，直到用户修复，遵循 R-17、R-18。

验收场景：

| 表达式或操作 | 预期结果 |
|---|---|
| `int(2) + double(0.5)` | 类型冲突，标错并阻止运行，要求先显式统一类型 |
| 将 `int(2)` 转为 double，再加 `double(0.5)` | 得到 `double(2.5)` |
| 将 `double(0.5)` 转为 int，再加 `int(2)` | 转换向零截断，得到 `int(2)` |
| `int(2) < double(2.5)` | 类型冲突，要求先显式统一类型 |
| `int(2) == double(2.0)` | 类型冲突，不自动转换后比较，也不以 false 替代类型错误 |
| `int(2) == int(2)` | 类型匹配，得到 bool `true` |

整数除法与余数规则见 R-26，double 相等与近似比较见 R-28。其他具体算术运算符范围尚待确认。

### R-26 整数除法与余数

确认依据：用户明确要求“整数除法向零截断，余数与被除数同号，除零报错”。

1. int 除以 int 时，商仍为 int，向零截断；需要小数结果时，须先显式转换为 double，不因无法整除而自动改变结果类型。
2. 对被除数 `a` 和非零除数 `b`，商 `q` 与余数 `r` 满足 `a = q × b + r`。非零余数与被除数 `a` 同号，且 `|r| < |b|`；整除时余数为 int `0`。
3. 整数除法和取余均采用任意精度整数计算，不借助有精度损失的浮点中间值确定商或余数。
4. 除数为 int `0` 时，除法和取余均按 R-18 报错：编辑时可确定的错误阻止启动，运行中出现的错误停止本次执行，不以零值替代失败结果。

验收场景：以下操作数均为 int。

| 被除数 a | 除数 b | 商 q | 余数 r |
|---|---|---|---|
| `7` | `3` | `2` | `1` |
| `-7` | `3` | `-2` | `-1` |
| `7` | `-3` | `-2` | `1` |
| `-7` | `-3` | `2` | `-1` |
| `-6` | `3` | `-2` | `0` |
| `0` | `3` | `0` | `0` |
| `7` | `0` | 报错 | 报错 |
| `0` | `0` | 报错 | 报错 |

表中的商与余数分别对应除法和取余操作，不要求一个节点同时返回两个结果。具体控件与运算符呈现方式另行对齐。

### R-27 整数位运算与移位

确认依据：用户明确要求“任意精度补码位运算、算术右移、移位位数非负且受资源限制”。

1. 支持 int 的按位与、按位或、按位异或、按位取反、左移和右移，操作数均须为 int；不隐式转换 double 或其他类型。
2. 位运算采用无限符号扩展的补码语义，不隐式截为 32 位或 64 位；按位取反满足 `~x = -x - 1`。此处定义整数运算语义，不要求实际存储无限位。
3. 左移保留完整的任意精度结果，不按固定宽度截断或回绕。右移采用保留符号的算术右移；负数右移可能与 R-26 的向零截断整数除法产生不同结果。
4. 移位位数必须为非负 int；移位 0 位保留原值，负数位数报错，不自动改变移位方向，也不对移位位数取模。
5. 移位位数与运算资源消耗受统一资源限制，超过限制按 R-18 报错，不自动缩小位数或截断结果。具体上限留待运行限制部分统一确定。
6. 类型冲突、非法移位参数与超限错误均按 R-17、R-18 处理；编辑时可确定的错误阻止启动，运行中出现的错误停止本次执行。

验收场景：以下操作数均为 int，成功场景均以未超过资源限制为前提。

| 表达式或操作 | 预期结果 |
|---|---|
| `~0` | `-1` |
| `~(-1)` | `0` |
| `5 & 3` | `1` |
| 按位或：5 与 3 | `7` |
| 按位异或：5 与 3 | `6` |
| `1 << 40` | `1099511627776`，不截为 32 位 |
| `8 >> 1` | `4` |
| `-3 >> 1` | `-2`；对应的整数除法 `-3 / 2` 仍按 R-26 得到 `-1` |
| `-3 << 1` | `-6` |
| `5 << 0` 或 `5 >> 0` | `5` |
| 移位位数为 int `-1` | 报错，不反向移位 |
| 移位位数为 double `1.0` | 类型冲突，要求先显式转换为 int |
| 移位位数或结果大小超过资源限制 | 按 R-18 报错，不截断后继续 |

### R-28 double 的精确相等与显式近似比较

确认依据：用户明确要求“double 默认精确比较，需要近似比较时显式指定容差”。

1. double 的普通相等比较按双方当前实际浮点数值精确判断，不自动加入容差，也不按界面显示的小数位数舍入后比较。
2. 普通不等比较与上述相等比较互为否定；`+0.0` 与 `-0.0` 在普通相等比较中视为相等。
3. 需要近似比较时，用户须显式指定容差，并在画布中明确表达该近似比较；普通相等比较不会因配置了其他近似比较而改变含义。
4. 近似比较可以表达为两数差的绝对值不超过用户指定的容差；具体控件形式、是否提供其他容差策略及参数规则另行对齐。
5. 比较双方仍须满足 R-25 的同类型要求；非有限数值仍按 R-13、R-18 拒绝，不以相等或不等的布尔结果替代错误。

验收场景：以下参与比较的值均为 double。

| 场景 | 预期结果 |
|---|---|
| `1.0 == 1.0` | bool `true` |
| `1.0 == 1.000001` | bool `false`，不因差值较小而自动视为相等 |
| `1.0 != 1.000001` | bool `true` |
| `+0.0 == -0.0` | bool `true` |
| 两值显示为相同小数文本，但实际浮点值不同 | 普通相等比较得到 bool `false` |
| 显式使用绝对差比较 `1.0` 与 `1.000001`，容差设为 `0.00001` | 近似比较得到 bool `true`；普通相等比较仍为 bool `false` |

### R-29 bool 节点取反的作用范围与状态显示

确认依据：用户明确要求“bool 取反只影响当前节点输出，不修改原变量，且明确显示取反状态”。

1. bool 节点的取反功能作用于当前节点的输出。开启时，每次求值先取得当前 bool 值，再输出逻辑取反结果；关闭时输出原值。
2. 对引用变量的节点开启或关闭取反，不修改该变量的初值、当前值或派生定义，也不改变其他读取该变量的节点的取反状态。
3. 变量在流程中变化后，开启取反的节点在后续求值时基于变量的新值输出反值，不固定使用开启取反时的值。
4. 结果为 bool 的比较表达式节点也可对其输出取反，原比较表达式本身的求值规则不变。
5. 节点必须明确显示取反状态，让用户能区分原值输出与取反输出；具体控件形式与布局另行对齐。
6. 如果要翻转普通变量自身，须使用明确的流程修改操作，例如 `enabled ← !enabled`，遵循 R-01；节点取反开关不执行变量赋值。

验收场景：普通变量 `enabled` 的当前值为 bool `true`。

| 操作或状态 | 预期结果 |
|---|---|
| 读取 enabled 的节点 A 开启取反 | A 输出 bool `false`，enabled 仍为 `true`，A 明确显示取反状态 |
| 另一个读取 enabled 的节点 B 未开启取反 | B 输出 bool `true`，不受 A 的取反设置影响 |
| 流程将 enabled 修改为 `false` | A 后续求值输出 `true`，B 后续求值输出 `false` |
| 在 enabled 为 `false` 时关闭 A 的取反 | A 输出 `false`，enabled 仍为 `false`，A 显示未取反状态 |
| 对结果为 bool `true` 的比较表达式节点开启取反 | 该节点输出 bool `false`，不修改比较操作数 |
| 流程对普通变量执行 enabled ← !enabled | 修改变量当前值，与切换节点取反状态的操作区分 |

### R-30 逻辑与、逻辑或的类型与短路求值

确认依据：用户明确要求“操作数必须为 bool，按明确的左右操作数顺序求值，并采用短路规则”。

1. 逻辑与、逻辑或的两侧操作数均必须为 bool，结果也为 bool；不将 int、double、string、byte 或数组隐式解释为真假。
2. 操作数具有明确的左、右顺序，每次求值先求左侧，再根据左侧结果决定是否求右侧；不得为求值方便交换操作数顺序。
3. 逻辑与：左侧为 false 时，直接返回 false，不求右侧；左侧为 true 时，求右侧并返回其 bool 值。
4. 逻辑或：左侧为 true 时，直接返回 true，不求右侧；左侧为 false 时，求右侧并返回其 bool 值。
5. 短路仅影响本次表达式的运行时求值。两侧仍须通过静态类型和配置检查，不因右侧可能被跳过而允许类型或已知配置错误。
6. 被短路跳过的右侧表达式不因本次逻辑运算而执行，因此不触发其中依赖本次运行值才会出现的计算错误；实际求值的部分若失败，仍按 R-18 报错并停止，不以 bool 值替代错误。

验收场景：A、B 均为类型和配置合法的 bool 表达式。

| 场景 | 预期结果 |
|---|---|
| A 为 false，计算 A 且 B | 返回 false，不求 B |
| A 为 true，计算 A 且 B | 求 B，返回 B 的 bool 值 |
| A 为 true，计算 A 或 B | 返回 true，不求 B |
| A 为 false，计算 A 或 B | 求 B，返回 B 的 bool 值 |
| 左侧求值发生运行时错误 | 按 R-18 停止执行，不继续求右侧 |
| 左侧为 false，右侧直接使用 int 参与逻辑与 | 静态类型错误，阻止启动，不用短路绕过检查 |
| 对 int 变量 x 计算 `(x != 0) 且 (10 / x > 1)`，运行中 x 为 0 | 左侧为 false，跳过右侧除法，返回 false，不触发除零错误 |
| 同一表达式在运行中 x 为 2 | 左侧为 true，求右侧，最终返回 true |

左右操作数的具体控件与连接呈现方式另行对齐；本条不确定一般模块调用的副作用、调用次数或缓存规则。

### R-31 条件分支与条件循环的 bool 类型要求

确认依据：用户明确要求“分支与条件循环只接受 bool，其他类型必须显式形成布尔条件”。

1. 条件分支和条件循环的条件输入必须为 bool，可以来自 bool 变量、常量或结果为 bool 的表达式。
2. int、double、string、byte 和数组均不能直接作为条件，不根据零值、非零值、空值或非空值隐式判断真假。
3. 使用其他类型的数据作为判断依据时，须显式构造 bool 条件，例如整数 `x != 0`，或通过长度与 int `0` 的比较判断字符串、字节串或数组是否非空；表达式仍须遵循既有类型规则。
4. 非 bool 条件作为类型冲突处理，允许保留编辑状态，在冲突位置标错并阻止运行，直到修复，遵循 R-17、R-18。
5. 条件表达式求值失败时按 R-18 处理，不将错误替换为 false，也不据此选择假分支或正常退出循环。

验收场景：

| 条件输入或状态 | 预期结果 |
|---|---|
| bool 常量、bool 变量或 bool 比较结果 | 类型检查通过，可作为分支或条件循环的条件 |
| 直接使用 int `0`、`1` 或其他整数 | 类型冲突，标错并阻止运行 |
| 对 int 变量 x 显式构造 `x != 0` | 得到 bool 条件，可用于分支或条件循环 |
| 直接使用 string、byte 或数组，无论是否为空 | 类型冲突，不隐式判断真假 |
| 显式比较长度是否大于 int `0` | 得到 bool 条件，可用于分支或条件循环 |
| 条件中实际执行的数据计算在运行时失败 | 停止本次执行，不当作 false 继续流程 |

条件循环的判断时机见 R-32，条件分支的判定、执行与汇合见 R-35；其他循环控制规则另行对齐。

### R-32 条件循环的判断时机

确认依据：用户明确要求“每轮执行前重新判断，首次为假不执行，循环体中的修改在下次判断生效”。

1. 条件循环在首次执行循环体之前求值条件；结果为 false 时执行零次循环体，退出循环。
2. 每轮执行循环体之前，均使用当前变量值重新求值条件；结果为 true 时进入本轮，结果为 false 时退出循环，不沿用上一轮的判断结果。
3. 循环体内对普通变量的修改在同一次运行内保留，并在下一次条件判断时生效；依赖这些变量的派生值按 R-01、R-11 的规则反映当前值。
4. 当前循环体执行期间，即使变量修改使条件变为 false，也不因此自动中断本轮；正常完成本轮后，再进行下一次条件判断。
5. 条件仍须满足 R-31 的 bool 类型要求。实际求值发生错误时按 R-18 停止执行，不将错误视为正常退出循环。

验收场景：

| 输入或操作 | 预期结果 |
|---|---|
| 首次判断条件为 false | 判断一次，循环体执行零次，继续循环后的流程 |
| int 变量 i 初始为 0，条件为 `i < 3`，循环体执行 `i ← i + 1` | 循环体执行 3 次，条件判断 4 次，退出时 i 为 3 |
| bool 变量 enabled 初始为 true，条件读取 enabled，循环体先将 enabled 设为 false，再执行一个后续步骤 | 本轮后续步骤仍执行；下一次判断为 false，退出循环 |
| 循环体修改条件所依赖的普通变量 | 下一次判断读取修改后的值，相关派生值随依赖更新 |
| 后续某轮执行前的条件求值失败 | 停止本次执行，不进入该轮，也不按正常退出继续循环后的流程 |

本条确定条件循环的正常判断时机；break、continue 见 R-36，运行资源上限另行对齐。

### R-33 次数循环的次数读取时机

确认依据：用户明确要求“进入时读取一次，本次轮数固定，再次进入时重新读取”。

1. 每次流程进入次数循环时，使用当前变量值计算一次次数，作为本次循环的固定轮数。
2. 本次循环期间不重新计算次数；循环体修改次数来源变量或其派生依赖，不改变本次固定轮数。
3. 同一次运行中，流程之后再次进入该次数循环时，使用届时的当前值重新计算次数，不复用上一次进入时的结果。
4. 次数表达式实际求值失败时，按 R-18 停止执行，不进入循环体，也不将错误替换为零次。

验收场景（执行过程正常完成）：

| 输入或操作 | 预期结果 |
|---|---|
| 次数来自 n，进入时 n 为 3，第一轮将 n 改为 5 | 本次仍执行 3 轮，不扩展为 5 轮 |
| 上述循环完成后 n 保持为 5，流程再次进入该循环 | 重新读取 n，本次执行 5 轮 |
| 次数来自 n，进入时 n 为 3，第一轮将 n 改为 1 | 本次仍执行 3 轮，不提前结束 |
| 次数来自派生表达式，循环体修改其依赖变量 | 本次轮数保持不变；再次进入时按更新后的依赖重新计算 |

本条确定次数的读取时机；次数的类型与合法范围见 R-34，break/continue 见 R-36，运行资源上限的具体数值另行对齐。固定轮数不覆盖 R-18 的错误停止规则。

### R-34 次数循环的次数类型与合法范围

确认依据：用户明确要求“次数必须为非负 int，零次跳过，负数或超限报错，其他类型须显式转换”。

1. 次数输入必须为非负 int，可以来自常量、变量或结果为 int 的表达式，并按 R-33 在每次进入时读取和校验。
2. 次数为 0 时不执行循环体，直接继续循环后的流程；负数报错，不自动按零次处理。
3. double、bool、string 等其他类型不得直接作为次数，须通过受支持的显式转换形成 int；例如 double `3.0` 不能直接作为次数。转换结果仍须满足非负及资源上限要求。
4. 次数超过资源上限时报错，不截断为上限，也不开始执行部分轮数。具体上限数值在资源限制部分统一确定；此约束不改变 int 的任意精度类型定义。
5. 统一遵循 R-17、R-18：静态可确定的类型、范围或转换错误在冲突位置标错并阻止启动；运行时才确定的错误停止执行，不进入本次循环体。

验收场景：

| 次数输入或状态 | 预期结果 |
|---|---|
| int `0` | 循环体执行零次，继续后续流程 |
| 合法范围内的 int `3` | 正常完成时执行 3 轮 |
| int `-1` | 报错，不按零次处理 |
| 直接输入 double `3.0`、bool 或 string | 类型错误，须先显式转换为 int |
| double `3.9` 按 R-24 显式转换为 int | 得到 int `3`，通过范围校验后作为次数 |
| 次数超过资源上限 | 报错，不截断、不执行本次循环体 |
| 次数在运行时计算为负数，或其显式转换失败 | 停止本次运行，不继续循环后的流程 |

### R-35 条件分支的判定、执行与汇合

确认依据：用户明确要求“进入时判断一次，只执行选中分支，正常结束后汇合，空分支直接通过”。

1. 每次流程进入条件分支节点时，使用当前值求值一次 bool 条件，按结果选中真分支或假分支；以后再次进入时重新求值。
2. 本次只执行选中的分支。分支执行期间修改条件所依赖的变量，不触发重新选择，也不切换到另一条分支。
3. 选中分支正常结束后，进入共同的后续流程；允许真分支或假分支为空，选中空分支时直接进入共同后续流程。
4. 未选中的分支不执行，不触发其中步骤的运行时计算或副作用；两条分支仍须通过静态检查，不能利用分支选择绕过已知错误。
5. 条件须满足 R-31；条件求值或选中分支执行发生错误时，按 R-18 停止本次运行，不执行另一分支，也不按正常汇合继续后续流程。

验收场景：

| 输入或操作 | 预期结果 |
|---|---|
| 条件为 true，真分支执行 A，假分支执行 B，汇合后执行 C | 依次执行 A、C，不执行 B |
| 同一结构的条件为 false | 依次执行 B、C，不执行 A |
| enabled 初始为 true，真分支先将其改为 false，再执行 A | 仍执行 A，随后汇合；本次不转入假分支 |
| 选中的分支为空 | 直接进入共同后续流程 |
| 条件依赖值改变后，再次进入同一分支节点 | 按当前条件重新选择分支 |
| 未选中的分支存在静态可确定的错误 | 标错并阻止启动，不能以本次不会选中为由跳过检查 |
| 选中分支运行时发生错误 | 停止执行，不执行另一分支或汇合后的流程 |

本条确定正常执行与汇合语义；break、continue 造成的控制转移见 R-36，模块返回另行对齐。

### R-36 break 与 continue 的作用范围

确认依据：用户明确要求“只控制当前模块内的最内层循环，禁止跨层或跨模块，循环外使用报错”。

1. break 和 continue 仅作用于当前模块内、结构上包围该节点的最内层循环；主流程中同样按结构上的最内层循环确定目标。条件分支不构成循环层级。
2. break 立即结束目标循环，跳过本轮剩余步骤及剩余轮次，继续该循环之后的流程；外层循环不会因此退出。
3. continue 跳过目标循环本轮剩余步骤。条件循环返回 R-32 的条件判断；次数循环将本轮计入固定次数，有剩余轮数才进入下一轮，不重新读取次数来源。
4. 不支持指定外层循环为目标，也不能跨模块控制调用方的循环。模块中没有包围该节点的循环时，即使调用方位于循环内，也属于循环外使用。
5. 循环外使用或试图指定不合法目标属于结构错误；允许保留编辑中的无效结构，在冲突位置标错并阻止运行，直到修复。
6. 分支内执行 break 或 continue 时，按目标循环转移控制，不再执行该分支剩余步骤或被跳过的本轮后续步骤；R-35 的正常汇合规则不覆盖此控制转移。

验收场景：

| 输入或操作 | 预期结果 |
|---|---|
| 内层循环执行 break，外层本轮在内层循环后还有步骤 A | 退出内层后执行 A，外层循环继续 |
| 条件循环先修改条件依赖变量，再执行 continue | 跳过本轮剩余步骤，使用修改后的当前值重新判断条件 |
| 次数为 3，每轮均执行 continue | 共进入 3 轮，每次 continue 均消耗当前轮次，不额外增加轮次 |
| 次数循环最后一轮执行 continue | 跳过本轮剩余步骤，继续循环后的流程 |
| 循环内的条件分支执行 break | 退出包围该分支的最内层循环，不执行本轮中分支汇合后的剩余步骤 |
| 主流程或模块在循环外放置 break/continue | 标错并阻止运行 |
| 循环调用某模块，模块内部在自身循环外放置 break/continue | 标错并阻止运行，不能控制调用方循环 |
| 试图让内层 break/continue 直接控制外层循环 | 结构错误，阻止运行 |

### R-37 取消跳转节点

确认依据：用户明确要求“跳转节点砍了，这个功能不做”。

1. 本次节点画布修改不提供跳转节点，原始说明中列出的跳转功能从需求范围移除。
2. 不提供跳转目标选择、目标标记或跳转专属的跨区域、跨模块配置；此前提出的跳转范围建议未被采纳，不作为实现要求。
3. 已确认的条件分支、次数循环、条件循环及 break/continue 规则继续适用；本条不取消正常流程连接、模块调用或返回。
4. 跳转功能不再列入待对齐事项。一般流程连线的合法结构与执行顺序见 R-38。

验收要点：节点库不提供跳转节点，编辑界面不提供跳转专属配置，最终需求与验收清单不将跳转列为待实现功能。

### R-38 流程连线与串行执行

确认依据：用户明确要求“按连线串行执行，普通步骤单一后继，重复执行只通过循环节点表达”。

1. 流程按连线确定的顺序串行执行，不提供并行执行；节点在画布中的位置、排列和移动不改变执行顺序。
2. 普通步骤最多只能有一个后继，不允许连接多个后继形成并行或隐式分支；条件选择通过条件分支节点表达，遵循 R-35 的选择与汇合规则。
3. 流程中的循环重复通过次数循环或条件循环节点表达，不允许用普通流程连线形成自环或多个步骤之间的环路。
4. 循环节点按已确认规则组织循环体的重复执行，break/continue 按 R-36 转移控制，不属于非法普通连线环路。
5. 非法多出口或普通连线成环属于结构错误；允许保留编辑中的无效结构，在冲突位置标错并阻止运行，直到修复。

验收场景：

| 输入或操作 | 预期结果 |
|---|---|
| 连线为 `A → B → C`，将 C 拖到 A 左边 | 仍按 A、B、C 的顺序串行执行 |
| 普通步骤 A 同时连接 B 和 C 作为后继 | 结构错误，标错并阻止运行，不执行隐式并行或任意选路 |
| 普通连线为 `A → A` 或 `A → B → A` | 结构错误，标错并阻止运行 |
| 使用次数循环或条件循环包络 `A → B` | 按循环规则逐轮串行执行 A、B |
| 条件分支通过真假出口选择路径并正常汇合 | 按 R-35 执行，允许该结构，不将其误判为普通步骤多后继 |

流程入口、结束与未连接节点的处理，以及模块调用和递归规则另行对齐。

### R-39 主流程与模块共享全局变量

确认依据：用户明确要求“主流程与模块共享全局变量，普通全局可显式修改，派生全局只读，模块调用不重置全局”。

1. 同一次运行中，主流程与所有模块共享同一份全局变量；模块读取全局变量时取得当前值，不为每个模块创建独立的全局变量副本。
2. 主流程和模块均可通过明确的流程修改操作写入普通全局变量；修改对后续执行立即可见，模块返回不会撤销已完成的修改。
3. 派生全局变量在主流程和模块中均只读，读取结果反映依赖变量的当前值；不允许模块绕过 R-01、R-11 直接改写派生变量。
4. 模块调用、再次调用或返回均不重新初始化全局变量；只有从头开始一次新运行时，按 R-10 重新初始化。
5. 全局修改和派生计算的错误沿用 R-18；运行时错误停止执行，不自动回滚此前已完成的全局修改。

验收场景：

| 输入或操作 | 预期结果 |
|---|---|
| 全局 base 初始为 `0x1000`，模块 A 显式改为 `0x2000` 后返回 | 主流程及随后调用的模块 B 均读到 `0x2000` |
| 派生全局 target 为 `base + 0x20`，模块 A 将 base 改为 `0x2000` | 此后的主流程与模块读取 target 均得到 `0x2020` |
| 模块直接改写派生全局 target | 按既有只读与错误规则标错并阻止运行 |
| 普通全局 count 初始为 0，模块每次将其加 1，同一次运行连续调用两次 | 返回后 count 为 2，不因调用重新初始化 |
| 上述运行结束后，从头开始新运行 | count 重新初始化为 0，再按本次流程执行 |
| 模块先修改普通全局，再发生运行时错误 | 停止本次执行，保留此前已完成的修改与运行记录，不自动回滚 |

模块参数、局部变量的作用域、命名与传递方式，以及模块作为数据节点时的调用和副作用规则另行对齐。
