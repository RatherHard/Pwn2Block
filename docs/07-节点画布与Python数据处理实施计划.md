状态：进行中（P0 决策已吸收、证据缺口待补；P1、P3、P4、P6、P7 已实现；P2 随 P9 接入运行链路；P5 已实现模型/调用/提取/升级，面包屑与流程模块提取的界面未做；P8、P9 未开始）

依据：[06-节点画布与 Python 数据处理需求](06-节点画布与Python数据处理需求.md)。本计划采用节点画布，不引入后续讨论的步骤编辑器替代方案。

## 1. 实施原则

- 保持“编译生成动作 → 调试执行 / 初态判题”，不增加运行时读取 VM 状态的能力。
- 保留现有动作协议、题目权限校验和判题逻辑；Python 只参与编译期数据处理。
- 图模型、求值和存档独立于 Rete；Lit 组件负责展示和编辑。
- 先交付基础题的完整路径，再增加控制流、模块和 Python；迁移与验收通过后替换 Blockly。
- 各阶段按契约、行为实现、界面接入拆成可验证的小提交。修改共享类型时同步适配调用方。
- 本文列出的新增目录为建议位置；不要求为了目录结构迁移无关代码。

## 2. 实施前决策

以下事项在 P0 记录结论，相关阶段不得以未验证假设完成交付。

| 事项 | 建议起点 | 完成条件 |
|---|---|---|
| 画布技术 | Rete + Lit 自定义节点 + SVG 折线 | 验证容器、折叠、端口定位、缩放、键盘连接和卸载重建；记录锁定版本 |
| Python 隔离 | 独立、受资源限制的隔离环境；Windows 开发可通过容器后端接入 | 确定部署方式，证明无法访问宿主秘密、目标进程或网络；普通子进程不能作为隔离完成的证据 |
| 首批 Python 工具 | 明确导入 packing / cyclic 工具，候选为 p32/p64、u32/u64、flat、cyclic、cyclic_find | 固定解释器、依赖与工具范围；确认可在隔离环境运行，不以禁用 import 代替系统隔离 |
| 旧存档迁移 | 保留原存档，受支持格式单向转换；失败时保留原文并提供导出 | 盘点实际存档及积木种类，确定支持版本、兼容映射和失败提示 |
| 执行额度 | 沿用现有循环、求值、字节和动作限制，新增 Python 与模块额度 | 写明每轮、每次编译、每个请求的计数范围及超限行为，前后端使用一致定义 |

当前限制定义在 `packages/shared/src/limits.ts`：循环展开 256、表达式求值 4096、单次动作请求 512、提交动作 4096。以代码常量为准，不在新模块复制数值。另需确定 Python 单次与整图总耗时、内存、输出、并发、排队长度和模块嵌套深度。

| 位置 | 改动 |

| `packages/web/src/compiler/` | 复用字节构造；调整产物状态、错误与来源定位；保留旧编译器作迁移对照直至切换 |
| `packages/web/src/components/`、`viewmodel/` | 接入画布、Python 侧栏、预览、执行定位、存档和运行门禁 |
| `packages/server/src/` | Python 求值入口、输入校验、配额、取消、隔离任务管理 |
| `packages/python-runner/`（新增） | 固定依赖、输入输出协议、隔离环境定义及 Python 测试 |
| `tests/`、`.github/workflows/ci.yml` | 编译执行回归、隔离验证、浏览器验收和部署检查 |

核心接口在 P1 固定：

- **图文档**：格式版本、稳定节点 ID、类型及版本、参数、端口、数据连接、结构化执行区域、模块依赖和布局。分支、循环以包含关系表达，不用任意回边编码。
- **图编译**：输入图文档、公开题目配置、参数及求值能力；异步返回完整产物或带节点路径的错误。可取消，不访问 DOM 或 VM。
- **Python 求值**：只接收代码、命名输入、声明的输出类型和请求标识，返回类型化结果或错误；额度由服务端约束。
- **编译产物**：动作、来源表、数据预览、编译轨迹、文档修订标识。仅动作进入现有执行及判题接口。
- **画布适配器**：读取文档、原子装载、订阅编辑、定位节点、销毁。装载失败保留旧图；销毁后不得以空存档覆盖数据。
