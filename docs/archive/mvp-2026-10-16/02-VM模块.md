# 02 VM 模块

VM 模块有五条设计目标，作为硬性规范，下面逐条落成 MVP 方案。

| 设计目标 | MVP 落地 |
|---|---|
| 位宽由出题人指定 | `archBits ∈ {32, 64}` |
| 寄存器名称、种类、数量由出题人自由设定 | 寄存器列表自由命名，另指定 `sp / bp / ip` 三个角色 |
| 以 VMA 为基本单元，权限、类型、大小由出题人设定 | 见 §3，大小须为 4KB 的倍数 |
| 指令集由出题人自由设定 | 出题人定义“指令作用 ↔ 机器码”的映射表，指令作用从内置语义中选取 |
| 未获取的内存数据不提前下发 | 隐藏 VMA 只公开布局、不下发内容；程序把内容读进寄存器、可见内存或 stdout，或执行 `reveal` 后才可见 |

## 1. 数值与端序

- 所有值以 64 位容器承载，按 `archBits` 掩蔽高位。算术、移位和比较都在掩蔽域内进行，溢出时按 2^archBits 回绕。
- 端序固定为小端（little-endian）。
- 字长 `W = archBits / 8` 字节，内存操作数、立即数、栈槽都按 W 计。
- 题目包和 API 中的地址与值一律使用十六进制字符串，例如 `"0x7ffff000"`。

## 2. 寄存器

出题人声明寄存器列表，例如：

```json
{ "registers": ["RAX", "RDI", "RSP", "RBP", "RIP"],
  "roles": { "sp": "RSP", "bp": "RBP", "ip": "RIP" } }
```

- 寄存器名匹配 `^[A-Z][A-Z0-9_]{0,15}$`，数量为 1–32。
- `roles` 必须指定栈指针、帧指针和指令指针。这样 32 位题目可以命名为 `ESP / EBP / EIP`，不强制使用固定的字面名。
- 所有寄存器都进入投影。MVP 不设秘密寄存器：真实 pwn 里寄存器没有“看不见”的，需要藏的东西放进隐藏 VMA 或虚拟文件（§5.3）。
- 标志位只有 `ZF / CF / SF` 三个，由引擎内置。它们不含秘密，会出现在投影中供教学展示。
  - `add / sub / cmp` 设置全部三个标志。
  - 逻辑运算和移位只设置 `ZF / SF`。

## 3. 虚拟内存（VMA）

```json
{ "id": "stack", "kind": "stack", "label": "栈",
  "start": "0x7fffe000", "size": "0x2000", "perm": "rw",
  "hidden": false, "init": [ { "at": "0x7fffff10", "hex": "00…" } ] }
```

| 字段 | 约束 |
|---|---|
| `id` | 题内唯一 |
| `kind` | `code / global / stack / heap / key / custom`。`key` 表示关键区；`custom` 必须带 `label` |
| `start` / `size` | `size` 为 0x1000 的倍数；`start` 按 0x1000 对齐；各 VMA 互不重叠 |
| `perm` | `r / w / x` 的任意子集 |
| `hidden` | 为 `true` 时区域的**内容**不进入投影；布局（`id / kind / label / start / size / perm`）照常公开 |
| `init` | 初始内容补丁列表 `[{ "at": "0x…", "hex": "…" }]`，补丁不得越出本 VMA；未覆盖的部分为 0 |

访问规则如下：

- 读需要 `r`，写需要 `w`，取指需要 `x`。违反时报 `memory_fault`。
- 访问未映射地址时报 `memory_fault`。
- 程序指令在执行时可以正常读写隐藏 VMA，权限检查照常进行。这正是“获取”数据的途径。
- 学习者的直接动作（[04](04-会话与API.md) §2）不能读写隐藏 VMA，否则动作本身就成了读取通道。
- 隐藏的只是内容，不是布局。拿到 binary 就知道全局变量在哪，不知道的是它运行时装了什么。所以隐藏地址可以出现在投影和错误信息里，隐藏的字节永远不会。

“获取”的语义：隐藏数据被程序读进寄存器或可见 VMA、被 `write` 写到 stdout，或被效果 `reveal` 整块公开，就自然出现在投影里。除此之外不存在别的揭示通道。

## 4. 指令集：作用 ↔ 机器码映射

MVP 只支持**字节形态**：程序就是 code VMA 里的字节，IP 是字节地址。取指可以从任意可执行地址开始，因此指令中间的 gadget 也能执行。MVP 不支持 IR 形态。

出题人在**公开包**中声明编码表 `encoding`。编码表不含秘密，学习者需要它来理解机器码、寻找 gadget。表里每一项把 1 字节 opcode 映射为“内置作用 + 操作数形态”：

```json
{ "opcode": "0x50", "op": "push", "operands": ["reg:RBP"] },
{ "opcode": "0xb8", "op": "mov",  "operands": ["reg:RAX", "imm"] },
{ "opcode": "0xe8", "op": "call", "operands": ["imm"] }
```

- 操作数形态共四种：
  - `reg:R`：固定寄存器
  - `const:N`：固定常量，例如 `syscall` 的调用号
  - `imm`：内联立即数
  - `mem:R+disp`：内存操作数，`disp` 为内联位移
- 寄存器操作数固定写进 opcode。同一个助记符搭配不同寄存器，就是不同的 opcode。这样编码最简单，也能让学习者直接看懂机器码。
- `imm` 和 `disp` 按 W 字节小端紧跟在 opcode 之后。
- 内存操作数写作 `mem:REG+disp`，有效地址 = 寄存器 + disp，按 2^archBits 回绕。
- **伪汇编里位移的显示口径（D4 定，BG05）**：`disp` 在**编码与地址算术上始终是无符号**的（W 字节小端，有效地址按上式回绕），只有**显示**按 W 字节二补数判符号——最高位为 1 时写成 `R-0xN`（`0xfffffffffffffff8` → `[RBP-0x8]`），否则 `R+0xN`；位移为 0 仍写 `R+0x0`。32 位下 `0x80000000` 是二补数最小值（绝对值在本字宽内不可表示），约定了显示成 `[EBP-0x80000000]`。
  - **`imm` 不适用这条**：`imm` 既可能是跳转/调用目标地址也可能是常量，按最高位判符号会把地址读成负数。`imm` 一律按无符号显示。真要负数立即数，应在编码表引入显式标记（如 `imm:signed`），不要全局判符号。
  - 这条口径的存在理由：`[rbp-0x8]` / `[rbp-0xc]` 是栈帧与局部变量最常见的写法，按无符号显示会变成 `[RBP+0xfffffffffffffff8]`，对新生是天书。
- 出题人可以给每项配置 `mnemonic` 作为显示名，默认取 `op`，供指令视图的伪汇编使用。
- 未命中编码表的字节在取指时报 `invalid_instruction`，在指令视图中显示为 `db 0x??`。
- 编码表可以只声明题目用到的那部分作用；没有声明的作用在本题中不存在。
- 项目提供一张默认编码表（x86 风味的 opcode 取值），出题人可以直接引用并按需增删，不必从零设计。配套的汇编器让出题人写伪汇编而不是手写 hex，见 [06](06-出题指南.md)。
- 反汇编（伪汇编）由服务端针对可见的可执行区域生成，随投影下发。前端不自己实现解码器。

### 4.1 内置指令作用（封闭集）

| 作用 | 操作数形态 | 语义 |
|---|---|---|
| `mov` | R,I / R,R / R,M / M,R | 赋值 |
| `push` | R / I | `sp -= W; [sp] = v` |
| `pop` | R | `r = [sp]; sp += W` |
| `add` `sub` `cmp` | R,R / R,I / R,M | 算术，设置标志；`cmp` 不写回 |
| `and` `or` `xor` `shl` `shr` | R,R / R,I | 位运算；移位量对 archBits 取模 |
| `jmp` | I / R / M | 无条件跳转 |
| `je` `jne` `jb` `jae` | I | 条件跳转（ZF / CF） |
| `call` | I / R | `push 下一条地址; ip = 目标` |
| `ret` | — | `ip = pop`；允许无配对 call（ROP） |
| `leave` | — | `sp = bp; pop bp` |
| `syscall` | — / const（调用号） | 按调用约定派发到 syscall 表，见 §5 |
| `nop` | — | 无操作 |

跳转目标 I 是绝对地址，这样实现最简单，学习者也能直接看到地址。相对跳转留到 P1。

## 5. syscall

syscall 仿照 Linux：调用号和参数放在约定的寄存器里，`syscall` 指令触发对应效果。调用约定、syscall 表、fd 表都写在**公开包**：它们是固定的，相当于拿到 binary 就能看到，公开不影响解题。私有包只放虚拟文件的内容（§5.3）。

### 5.1 调用约定

```json
"syscallAbi": { "nr": "RAX", "args": ["RDI", "RSI", "RDX"], "ret": "RAX" }
```

- `nr`、`args`（最多 3 个）、`ret` 都必须是已声明的寄存器，`nr` 和 `ret` 不得是 `ip` 角色。
- 建议沿用 x86-64 Linux 的寄存器与调用号（`read=0`、`write=1`、`exit=60`），学习者以后查真实 syscall 表不会陌生。
- `syscall` 有两种编码形态：
  - 无操作数：调用号取自 `nr` 寄存器。这是 ret2syscall 要考的形态。
  - `const:N`：调用号固化在 opcode 里，参数照常取自 `args`。适合前几关当捷径，比如 `syscall win`。
- 调用号不在 syscall 表里时报 `invalid_instruction`。
- 执行完不压栈，ip 指向下一条指令。

### 5.2 syscall 表

```json
"syscalls": [
  { "nr": 0,  "name": "read",  "kind": "read",  "doc": "read(fd, buf, count)" },
  { "nr": 1,  "name": "write", "kind": "write", "doc": "write(fd, buf, count)" },
  { "nr": 60, "name": "exit",  "kind": "exit",  "doc": "exit(code)" },
  { "nr": 99, "name": "win",   "kind": "custom", "doc": "置 FLAG=1 并退出",
    "effects": [ { "type": "set_reg", "reg": "FLAG", "value": "0x1" }, { "type": "exit" } ] }
]
```

`kind` 是封闭集：

| kind | 参数 | 语义 |
|---|---|---|
| `read` | fd, buf, count | 从 fd 读至多 count 字节写入 buf，`ret` = 实际字节数 |
| `write` | fd, buf, count | 把 buf 起的 count 字节写到 fd，`ret` = count |
| `exit` | code | 程序结束，退出码为 code，立即判题 |
| `custom` | — | 按序执行 `effects`，不写 `ret` |

`read` / `write` 的约束：

- `count` 超过 0x1000 时按 0x1000 截断。
- 整段 buf 先做权限检查，全部通过才读写，否则报 `memory_fault` 且不产生任何副作用。部分写入会让“写了多少”变成探测边界的手段。
- `len === 0` 一律通过且不触碰任何字节：零长度没有信息量，不能当成“这个地址是否映射”的探测手段。
- 权限检查和普通指令一样：buf 可以落在隐藏 VMA 里，比如 `read` 进隐藏区、`write` 出隐藏区，后者就是“获取”。
- fd 未声明，或方向不对（读 stdout、写文件），`ret` = `-1`（按位宽回绕），不触发异常。

`custom` 的效果原语只有四种，按序执行，只收常量，没有参数求值和分支：

| 效果 | 语义 |
|---|---|
| `set_reg` | 把寄存器置为常量，不得写 `ip` 角色 |
| `reveal` | 把指定隐藏 VMA 整块变为可见 |
| `copy` | `{src, dst, len}` 均为常量，`len ≤ 0x1000`；权限与原子性同 `read` / `write` |
| `exit` | 程序结束，可带常量 `code`，默认 0。只能是最后一个效果 |

syscall 没有宿主副作用，也不能执行任意代码。

### 5.3 fd 与虚拟文件

```json
"fds": [
  { "fd": 0, "name": "stdin",      "kind": "stdin" },
  { "fd": 1, "name": "stdout",     "kind": "stdout" },
  { "fd": 3, "name": "secret.txt", "kind": "file", "size": 16 }
]
```

fd 在开局就已打开，MVP 不做 `open` / `close`。`stdin`、`stdout` 各至多一个。

- **stdin**：一个输入缓冲。学习者用 `feed` 动作往里追加字节（[04](04-会话与API.md) §2），缓冲上限 4KB。`read` 从当前位置取 `min(count, 剩余)` 字节，读完返回 0，和 Linux 的 EOF 一样。不存在“等待输入”的状态：要先 `feed`，再执行到 `read`。
- **stdout**：只能追加的字节流，进入投影。累计超过 4KB 时报 `resource_limit`。
- **file**：只读，内容写在私有包的 `files`，按 fd 记录读偏移。`size` 公开且必须等于内容长度：长度是“拿到题目就知道”的那类信息，而且 `read` 的返回值本来就会暴露它。

**虚拟文件的内容绝不能是 flag 真值**，否则调试实例里一个 `write` 就把 flag 打出来了，绕过判题。文件里放题目自己的秘密，判胜用 `stdout_contains` 检查“学习者把它打印出来了”，见 [03](03-题目包格式.md) §2.1。服务端加载时若发现文件内容包含 flag 真值，拒绝加载该题。

## 6. 执行模型与异常

- 一次 `step` 执行恰好一条指令：取指 → 解码 → 执行 → 判题。
- 运行受资源上限约束，默认值为：
  - 单次运行最多 10 000 步
  - 每会话累计最多 1 000 000 步
  - 历史快照最多 1 000 份

  超出上限时报 `resource_limit`。

| 异常 | 触发 |
|---|---|
| `memory_fault` | 越权或未映射的访问；`read` / `write` / `copy` 的 buf 不合法 |
| `invalid_ip` | ip 落在不可执行或未映射的地址 |
| `invalid_instruction` | 未命中编码表，或调用号不在 syscall 表里 |
| `resource_limit` | 超出步数上限，或 stdout 超过 4KB |

- 指令执行期间发生异常时，实例进入 `failed`。调试实例里可以 `undo` 或 `step_back` 回到异常前的状态，便于在教学中反复尝试；判题实例不回退，异常即判负。
- 错误响应由服务端用模板生成，内容包括出错地址、原因，以及一条教学提示。
  - 例如：“`ret` 跳到了 0x4141414141414141，该地址未映射。检查 padding 长度和小端序。”
  - 隐藏地址可以出现在错误里（布局是公开的），但错误里永远不带隐藏字节的值。

## 7. 快照与确定性

- 引擎完全确定：不读取时间，不使用随机数。
- 内存按 4KB 分页，采用写时复制（COW）。调试实例每个执行类动作执行前压一份快照（支持 `undo`），每条指令执行前再压一份进环形缓冲（支持 `step_back`，N=64）；判题实例不留快照，只留回放记录。回退分级见 [04](04-会话与API.md) §3。
- 快照覆盖全部 VM 状态：内存、寄存器、标志位，以及已 `reveal` 的 VMA 集合、stdin 缓冲与读位置、stdout、各文件 fd 的读偏移。回退到 `reveal` 之前，该区域重新隐藏。
- 实现语言建议使用 Rust，也可以用 TS 进程内实现。MVP 只要求 VM 运行在服务端，不要求独立进程隔离。
