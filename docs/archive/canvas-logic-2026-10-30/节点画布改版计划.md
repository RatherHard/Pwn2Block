# 节点画布改版实施计划

> 历史方案：2026-10-29 起，节点画布 UI 与交互以新的重构要求为准，当前实现见 [02-已实现需求](../../02-已实现需求.md#节点画布交互与布局)。本文件中端口拖线、就地编辑、预览位置等旧规则不再作为界面验收标准。


状态：阶段一（数据语义内核）已完成；阶段二、三未开始。依据：[节点画布大型修改](节点画布大型修改.md)（需求与 A–AC 决策，2026-10-23 对齐）；边界见 [基本架构](../../01-基本架构.md) §4。

## 1. 拆分原则

改版把「值」与「结构」变成编辑器的一等公民，同时删除 Python 与旧节点体系，一次做完无法验证。按下面的线切成三段：

1. **先语义，后交互**：值、组合、运算、转换、变量、流程必须先有脱离 DOM 的权威实现与单元测试，再接画布。否则每次调试都要点鼠标，语义错误会伪装成界面问题。
2. **每段独立可验证、可回滚**：一段结束时代码可运行、`pnpm typecheck` / `lint` / `test` 全绿，且不依赖下一段才存在的契约。
3. **旧体系最后删**：阶段一、二以新增为主，`main` 始终可运行；旧节点目录、Python、旧画布组件在阶段三连同其测试一起删除，避免半删状态。
4. **后端权威不动**：三段都不改 `engine` / `server` 的安全边界。新画布仍然只产出受限原子动作，判题仍由服务端从初态回放。

```text
阶段一 数据语义内核     阶段二 流程与变量        阶段三 画布交互与清理
值/组合/运算/转换  ──▶  变量/if/循环/方法/动作 ──▶  视觉/吸附编辑/包络/存档 UI/删除
（shared 新增模块）    （web 编译管线切换）      （组件 + 逐题适配 + 验收）
```

## 2. 阶段一：数据语义内核（已实施）

### 2.1 范围

只做「值怎么算」，不做「值怎么画」。对应需求：

| 需求 | 内容 |
|---|---|
| §2.1 | `byte`（字节串）、`int`、`double`、`string`、`bool`、列表、字典；字典键为字符串或整数、保留插入顺序、重复键报错、缺失键报错 |
| §2.2 | 吸附组合的行列、成员顺序、模式（合并为串 / 组成列表）、默认模式推导、不兼容类型拒绝、折行不插入额外字节 |
| §2.3 | 整数/浮点算术语、数字比较、布尔与或非（短路）、长度/索引/切片/重复、字典按键取值；显式类型、除零/非法移位/越界报错；切片 `[开始:结束:步长]` |
| §4.1–4.2 | 转换包络（整体或局部、可嵌套、不交叉占有）；转换目录全文；参数摘要；字典不参与转换 |
| §7（数据部分） | 纯数据表达式预览；错误阻止结果；结果大小与求值预算限制 |
| §8（数据部分） | 新版存档格式与版本；旧版存档明确不兼容，不静默改写 |

### 2.3 关键设计决定

1. **表达式是显式的节点引用**：每个数据节点有一个结果，输入写成「节点 id」。表达式结构完全由引用关系决定，不靠坐标或连线位置推断优先级（§2.3「表达式结构决定求值顺序」）。
2. **组合是容器节点**：`group` 节点保存 `rows`（外层是行，内层是成员 id）与 `mode`。成员顺序 = 先行后列；嵌套组合就是成员本身是另一个 `group`，因此列表层级天然保留（§2.1 嵌套集合）。
3. **归属用成员关系表达，不用坐标**：一个节点最多出现在一个组合的 `rows` 里；包络（`convert`）通过 `input` 引用内部结构，包络「局部」= 包住一个子组合。校验器拒绝交叉占有（§4.1）。
4. **类型只在值上判定**：静态校验只看类型标签（`byte`/`int`/`double`/`string`/`bool`/`list`/`dict`），列表元素类型在求值时检查。这样 `list` 的异构与嵌套不需要类型推导入门门槛，也不会出现「静态通过、求值炸」之外的含糊状态。
5. **不隐式转换**：整数与浮点混用、字节串与文本混用都直接报错，必须经过转换节点（§2.2、§4.2）。
6. **错误即结果**：运算/转换/切片返回 `Result`，不抛异常；求值把首个错误定位到节点 id 后停止该分支，其余节点继续，便于一次报多处。
7. **预算显式**：求值步数、集合大小、重复结果大小、整数位数、值嵌套深度全部读 `limits.ts`，不散落魔法数字。

验证结果：`pnpm typecheck` 与 `pnpm lint` 通过；`pnpm test` 为 140 个文件、2250 条通过、7 条跳过、5 条 todo（阶段一新增 8 个文件、267 条用例，既有 132 个文件保持全绿）。AT-01/02/03/04/11/12/13/14 的语义条目分别落在 `value.test.ts`（值模型与编码）、`ops.test.ts`（算术/位/比较/布尔）、`collection.test.ts` 与 `slice.test.ts`（AT-11）、`convert.test.ts`（AT-12/13）、`schema.test.ts`（§8 存档）、以及两个 `canvas-*.test.ts`（AT-01–04 与结构校验的端到端断言）。

实现中定下的口径，阶段二沿用、不再重猜：

1. **「长度」只有一份实现**：`ops.ts` 的一元 `length` 委托 `collection.lengthOf`，错误文案同源，避免两处对「文本按码点」的处理漂移。
2. **校验与求值分开**：`validateCanvasDocument` 只拦「不依赖具体值就一定是错的」问题（未知节点、归属冲突、数据环、类型不匹配、字典重复键、转换适用性）；`evaluateCanvasDocument` 不自动跑校验。阶段二的编译入口按「先校验、后求值」串起来，编辑中途的单节点预览才不会被无关结构错误挡住。
3. **只从根开始求值**：根是没有任何节点引用它的数据节点，加上 `main` 里的流程节点；布尔与/或短路时右侧不求值，因此被短路掉的分支没有预览值、也不报错——这是需求 §7「先求值再生成动作」的必然结果，不是遗漏。
4. **静态类型只推到值种类**：列表元素与字典取出的值是「未知（any）」，元素级错误在求值时定位到具体节点。这样异构列表与嵌套集合不需要类型推导入门门槛。
5. **预算拆两条**：`CANVAS_MAX_EVAL_STEPS`（一次求值的总步数）与 `CANVAS_MAX_EXPR_DEPTH`（引用嵌套深度）；又深又窄的链先撞深度上限，并排的多个根先撞步数上限。
6. **切片对照过 CPython**：`slice.ts` 照 `slice.indices()` 实现，并用真实 CPython 3.13 对文本/字节串/列表各 22032 组边界（含省略、负值、±10³⁰）做过对照，结果零不一致。
7. **导出用命名空间**：`shared` 以 `export * as canvas` 暴露这一层，和旧 `workflow/` 里同名的 `Value`/`EncodedValue` 并存到阶段三删除为止，调用点显式写 `canvas.xxx`。

阶段二定下的口径：

1. **变量只有一份声明**：全局限定成「当前工作流的一次执行」，没有跨运行的持久值，也没有旧实现的区域内层作用域。「已声明但未初始化」是一等状态（`binding.mode: 'none'`），只在真正读取时报错。
2. **派生变量惰性重算**：每次读取按当前状态求值，并用「执行轮次版本号（epoch）」缓存同一轮内的重复读取；流程赋值与进入新一轮都会让版本号前进。派生变量不可写，解绑后不保留旧值（不会有「残留的旧预览」当初始值）。
3. **流程用数组表达顺序**：`main` 与分支的 `then`/`else`、循环的 `body` 都是有序数组，一个流程节点只能属于一条序列。因此回边、跨区域接线在结构上就表达不出来，不需要靠校验去追环（需求 §5.2）。
4. **缺开始节点只在有流程时算错误**：纯数据表达式文档（`main` 为空、没有流程节点）继续合法，阶段一的数据能力与用例不受影响；一旦出现流程节点就要求恰好一个开始节点且是 `main[0]`。
5. **次数超上限报错、不截断**：旧实现把超过 256 的次数静默夹到 256，阶段二改为明确报错并定位到循环；另有「所有循环累计轮数」与「动作数」两条独立预算，任一条超限都整体失败。
6. **循环索引显式指向循环**：`loop-index` 上带 `loop` id，作用域按**使用点**判定（使用点必须在所属循环体子树内），因此嵌套循环可以显式读外层索引——旧实现只能取最近一层。
7. **方法即题目公开声明**：方法目录来自 `authorBlocks`，生成的动作只有 `{ type: 'block', id, args }`，展开仍由服务端完成；参数编码为字节串→无前缀 hex、整数/地址→`0x…`，地址校验不超过 64 位，生成前用服务端同一个 `expandBlock` 做一次本地预检。
8. **失败不发布部分动作**：生成器返回 `ok: false` 加问题列表，没有 `sequence` 字段；步骤快照（每步之后的变量值、这一步读到的输入、所在轮次）只存在于前端内存，不上行服务端。
9. **静态校验与求值分层不变**：类型推导搬到 `canvas/types.ts`，断开校验器与流程分析的循环依赖；`loop.count`/`if.cond`/`assign.value`/变量绑定在静态期就查类型，方法签名由流程分析按声明校验。
10. **存档沿用 v2**：`main` 与区域直接内联在文档/节点上（分支节点自带 `then`/`else`，循环节点自带 `body`），不新增版本号——阶段一的 v2 存档本来就有 `main` 字段，语义校验器补上了流程规则。

5. **删除**（§9、§10）：Python 全链路（节点、编辑器、求值 API、运行器、部署配置、协议、测试、文档）；旧 `workflow/` 节点目录、`kinds.ts` 与旧节点编译分支；被删除能力的工具箱/侧栏入口。

### 4.3 逐题公开方法（已实施）

`challenges/<id>/public.json` 的 `authorBlocks` 逐题补上画布方法节点唯一可调用的声明，只搬旧画布已经有的入口——不新增动作类型、不改 `allowedActions`、不改 `private.json`：`callret` → `push_value`；`endian` → `write_bytes`；`localvar` → `gets`；`pushpop` → `push_value`、`pop_value`；`ret2rop` → `name`、`introduce`；`ret2win` → `gets`；`stackframe` → `capture`。`step` / `run` 仍由顶栏提供，没有做成方法。

验证结果：7 道题的 `challenge:check` 与 `challenge:solve` 全部通过（flag 用 CI 哨兵值）；另用一次性内联脚本对每题每个 `authorBlock` 造该类型的最小合法参数（bytes → `00`，int/addr → `0x0`）调 `shared` 的 `expandBlock`，8 个声明全部 `ok: true`，展开为 `push` / `write_bytes` / `pop` / `feed`，零失败。

既有 4 题（`ret2win`/`localvar`/`stackframe`/`ret2rop`）的声明保持原名：E2E 与题面直接写着 `gets(buf)`、`capture(buf)`，改名会同时改坏两者；而且固定落点的 `gets` 比带地址参数的 `write_bytes` 更窄，合并成一个 id 等于放开「自己挑地址」的能力。

### 4.4 语义与命令层（已实施）

- **「未接线」是一等状态**：引用字段接受空串（`document.ts` 的 `UNCONNECTED`），`inputIdsOf` 跳过它，校验报 `unconnected` 并点明「哪个节点的哪个端口」，求值也回同一句话。方法标识同样接受空串（还没选方法），由 `method_mismatch` 提示。这样新拖出来的节点可以先落盘再接线，不会被迫先造一个占位节点。
- **节点目录**（`packages/web/src/canvas/catalog*.ts`）：18 种节点的规格、默认值、端口类型与工具箱分组集中一处；端口由 `inputRefsOf` 派生，所以「目录端口」与「实例端口」结构上不可能漂移。工具箱按值 → 集合 → 运算 → 转换 → 变量 → 流程 → 方法排列，同一分类不切开。
- **编辑命令层**（`editor*.ts`）：所有编辑都是「输入文档 → 新文档 + 问题」的纯函数，界面只负责调用。删节点会连带删掉只依赖它的引用者与区域成员；拆包络、删行这类结构操作不连带删别的节点，把悬空引用交给校验器。补了 `setAssignTarget`：`assign` 的写入目标是变量声明而不是数据节点，接线命令管不到它。
- **渲染视图模型**（`view-model*.ts`）：把文档算成盒子、行、端口、连线与包络矩形，几何是确定性的纯函数（同一输入两次结果完全相等）。白框节点与彩色关系方框分开：运算类节点只出关系方框，字面值/组合/字典/切片等方法出大白框。

实施记录：`8c8bc81`（未接线 + 逐题公开方法）、`00ebac3`（节点目录，66 条测试）、`155ec51`（编辑命令层，126 条测试）、`4a94ab3`（渲染视图模型，40 条测试）。

## 5. 风险与依赖

| 风险 | 应对 |
|---|---|
| 新模型与旧画布并存导致双份目录/存档逻辑 | 阶段一、二只新增；阶段三一次性删除旧目录与旧存档路径，`kinds.ts` 不留兼容层 |
