## 1. 目标

以节点画布替换 Blockly，保持现有 TUI 风格和教学体验。基础操作通过内置节点完成，复杂数据处理通过 Python 节点完成，常用逻辑可封装为模块。

Python 仅处理数据，可使用 pwntools 的便捷工具，不操作 VM、不参与收发交互。

## 2. 执行模型

- 流程先完成数据计算、分支选择、循环和模块展开，再生成动作序列，交由现有 VM 执行与判题。
- 节点输入来自用户参数、题目公开常量、变量或上游结果，不读取本轮 VM 执行后的状态。
- 数据连接表达值的依赖；执行连接表达动作和变量更新的顺序。
- 数据节点按当前路径的依赖求值，未选中分支中的 Python 不执行；全图仍检查结构和类型。
- 编辑后产物标记为过期；重新编译成功后才能运行或提交。编译和预览不推进 VM。
- 编译失败或超出额度时，不执行部分产物。服务端继续校验动作权限并从初态判题。

## 3. 画布与节点呈现

- 复用现有主题：单一深色背景、等宽字体、直角边框、反显选中；不使用渐变、阴影和圆角。
- 保持现有颜色语义。类型、状态和连接同时用文字或形状表达，不仅依赖颜色。
- 数据从左向右连接；执行流程从上向下连接。端口形状区分数据与执行。
- 参数默认在节点内填写，可切换为连接输入；连接后显示上游值和来源。
- 支持平移、缩放、框选、移动、删除、复制、撤销和重做，以及无需拖拽的键盘连接方式。
- 分支、循环和模块可折叠。缩小时隐藏细节；Python 编辑器在侧栏打开。
- 工具箱按题目权限和学习阶段展示节点。画布及模块支持保存、加载、导入和导出。

## 4. 节点目录

### 4.1 数据节点

| 节点 | 功能 |
|---|---|
| 填充字节 | 按数量重复指定字节 |
| 文本转字节 | 按编码生成字节，默认 UTF-8 |
| 十六进制字节 | 输入并校验原始字节 |
| 整数转字节 | 设置位宽、字节序，编码整数 |
| 地址转字节 | 默认采用题目位宽和字节序 |
| 拼接字节 | 按顺序组合多段字节，展示各段偏移和长度 |
| 整数计算 | 算术和位运算 |
| 比较与逻辑 | 比较数值、组合布尔条件 |
| 字节转整数 | 按位宽和字节序解码，检查长度 |
| 截取字节 | 按偏移和长度截取 |
| 按偏移组装 | 按位置放置数据，显式设置空隙填充，重叠时报错 |
| 生成定位序列 | 生成用于定位覆盖位置的序列 |
| 查找序列偏移 | 按匹配配置查找字节位置，未找到时明确提示 |
| 条件选值 | 按条件输出两个同类型候选值之一 |
| Python 处理 | 对显式输入执行代码，返回有类型的结果 |

### 4.2 动作节点

保留现有动作能力：输入数据、写入内存、压栈、出栈、调用、返回、执行指定数量的指令、运行程序、题目专用动作。

- 输入数据只向 VM 输入队列追加字节；推进 VM 由执行指令或运行程序负责。
- 动作节点不向数据图返回运行后的内存、寄存器或程序输出。
- 题目未授权的动作不可使用，封装进模块后仍受同一限制。

### 4.3 控制与变量节点

提供开始、条件分支、重复 N 次、条件循环、跳出循环、继续下一轮、声明变量、读取变量、设置变量。

## 5. 入口、分支与循环

### 5.1 入口

- 每个顶层流程恰好一个“开始”，可声明带默认值的输入参数。
- 未被入口流程引用的节点显示为“未使用”。
- 流程结束位置自动标识；结束不代表 VM 退出或判题成功。

### 5.2 分支

- 条件分支采用容器，包含“成立”“否则”，可添加“否则如果”。
- 容器具有一个执行入口和一个继续出口；选中分支完成后自动汇合。
- 对外返回数据时，各条可能到达出口的分支必须提供同类型结果。
- 简单数据二选一使用“条件选值”，无需创建动作分支。

### 5.3 循环

- 循环采用容器，循环体结束自动进入下一轮，不要求手动连接回边。
- 次数循环提供从 0 开始的当前序号；条件循环支持“当条件成立”和“直到条件成立”，均先判断后执行。
- 跳出和继续作用于最近一层循环；循环外使用时报错。
- 依赖轮次或变量的数据每轮重新求值。
- 累计结果须有初始值；循环执行零次时结果仍有定义。
- 设置循环、总求值和动作数量额度，错误定位到对应循环。
- 除结构化循环外，不允许任意执行回边或循环数据依赖。

### 5.4 变量

- 变量显式声明类型和初始值，设置操作由执行顺序决定。
- 分支和循环可访问外层已声明变量，内部新建变量不自动暴露到外层。
- 模块内部变量与调用者隔离；跨模块数据只通过参数和输出传递。
- Python 不隐式修改流程变量，需要更新时使用“设置变量”。

## 6. Python 节点

- 显式声明命名输入和一个输出，支持整数、布尔、字节、文本；不传递任意 Python 对象。
- 提供打包、解包、拼接、定位序列等工具及代码模板，固定 Python 和依赖版本。
- 不开放 VM 句柄、目标进程、网络连接、私有题目包或判题凭据；不得通过文件等外部状态传递节点数据。
- 在隔离工作进程中求值，约束时间、内存和输出大小；失败时返回节点、代码行和错误说明。
- 每次求值使用独立上下文，不依赖上次运行的全局变量；整数传输不得损失精度。
- 节点显示输出类型、摘要和状态；字节输出可查看长度、十六进制和文本。

## 7. 模块化

| 形式 | 语义 |
|---|---|
| 分组框 | 仅用于命名、整理和整体移动节点 |
| 数据模块 | 封装数据计算，提供明确输入输出，无执行端口 |
| 流程模块 | 封装控制流和动作，提供参数、结果、一个执行入口和一个返回出口 |

- 支持选中节点后“提取为模块”，将跨选区连接整理为输入输出。
- 提取范围必须包含完整控制结构；不完整的分支、循环或多入口选区须明确提示。
- 模块定义包含名称、说明、端口类型、默认值和版本；数据模块内部不得包含动作。
- 模块内部使用参数入口和结果出口，可通过面包屑进入、返回。
- 支持模块复用和有限嵌套，不支持递归；实例固定版本，升级须显式操作。
- 流程模块的数据结果仍在编译期产生，不包含 VM 运行结果。

## 8. 预览与执行定位

- 每个数据节点自带结果预览，无须额外连接预览节点。
- 拼接与组装结果展示来源、偏移和长度；选择某段时高亮对应输入及结果字节。
- 编译演示显示分支选择、循环轮次和模块路径，与 VM 执行状态分开呈现。
- 动作来源记录模块调用位置、分支、循环轮次和具体节点，可从 VM 执行记录定位回画布。
- 运行中高亮由真实执行结果驱动。历史查看不宣称恢复任意 Python 执行现场。

## 9. 技术方案

首选 Rete.js 管理编辑交互，使用 Lit 自定义节点、SVG 折线连接，复用项目主题。节点数据模型、编译器和持久化格式独立于画布库。

原型须验证 Lit 集成、控制容器、端口定位、缩放和键盘操作。Python 求值接入编译阶段，保留现有动作执行、服务端校验及判题路径。

## 10. 验收标准

1. 无需 Python，即可用填充、地址编码、拼接和动作节点完成基础题；结果与现有实现一致。
2. Python 可生成与内置节点相同的数据；类型错误、异常和超时可定位，不能操作目标或读取判题私有数据。
3. 分支只生成选中路径的动作；未选中分支中的 Python 不执行。
4. 次数循环、条件循环、变量更新、嵌套、零次循环、跳出和继续均符合定义；超限时不执行部分结果。
5. 提取模块前后结果一致，多实例变量互不干扰，模块内部动作仍受题目权限限制。
6. 保存后重新加载，图结构、参数、代码、布局及模块版本保持一致。
7. 编译失败或产物过期时无法运行、提交；判题仍从初态执行并由服务端判定。
8. 能从动作记录定位到模块内具体节点及循环轮次；1280×720 下可完成编辑、预览和执行，关键操作支持键盘。
