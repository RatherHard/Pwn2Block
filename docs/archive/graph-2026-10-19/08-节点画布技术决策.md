## 1. 画布技术：自建 Lit + SVG，不引入 Rete

**决定**：画布与编辑器自建（`packages/web/src/graph/`、`components/graph-*.ts`），不引入 Rete。

**理由**：

- 图的语义是"数据依赖边 + 有序执行序列 + 容器区域"，与 Rete 的节点/连接模型重叠但不等价：
  执行顺序用序列表达，不存冗余的执行边；引入 Rete 反而要再翻译一层。
- 交互与渲染都要脱离 DOM 测试：`geometry.ts` 是纯函数坐标计算，`editor.ts` 是纯函数命令，
  测试直接断言文档与坐标；Rete 的插件生态与无头测试成本更高。
- 主题是严格 TUI（单背景色、无渐变/阴影/圆角），自建 SVG 更容易保持一致。
- 不新增运行时依赖，符合"先量后换"的工程取舍。

**代价与再评估**：自动布局、小地图、折叠、框选优化都要自己写。现在已覆盖端口定位、正交走线、
缩放锚点、框选、键盘接线与卸载重建；如果 P4（分支/循环容器）阶段交互复杂度超出可控范围，
再评估 Rete 或其它库——届时保留 `GraphDocument` 作为稳定接口，替换成本集中在渲染层。

**证据**：`packages/web/test/graph-geometry.test.ts`、`graph-editor.test.ts`、
`graph-canvas.test.ts`、`graph-panel.test.ts`。这些测试在 jsdom 与纯函数层运行，
不需要浏览器布局。

## 2. Python 隔离：默认关闭，只有容器后端才算隔离

**决定**：服务端通过 `PWN2BLOCK_PYTHON_BACKEND` 选择后端：

| 后端 | 行为 | `capability().isolated` |
|---|---|---|
| `none`（默认） | 直接回 `unavailable`，Python 节点编译时明确报错 | false |
| `docker` | 容器内运行运行器：`--network=none --memory --cpus --pids-limit --read-only --user`，只读挂载运行器本身 | true |
| `process` | 显式配置才启用的开发后端：清理环境变量、临时工作目录、超时杀进程树 | **false**（不是隔离证据） |

**不可妥协的三条**：

- **默认不执行**：没有配置就是不可用；绝不"先在这台机器上直接跑一下"。
- **普通子进程不是隔离证据**（07 §2）：`process` 后端的注释、README 与 `capability()` 都写明这一点。
- **结果只从协议来**：运行器 stdout 必须是一行符合 `PythonRunnerResultSchema` 的 JSON；
  类型、大小、请求标识都在服务端再校验一遍，对不上就丢弃（迟到结果）。

**现在还不能声称**：开发机（Docker Desktop）与 CI 已用真实 `python:3.12-alpine` 跑通 7 项 Docker 隔离用例；
"目标部署环境确实无法访问宿主秘密/网络"仍需在部署环境重跑并留证据。CI 用
`PWN2BLOCK_REQUIRE_PYTHON=1` 把缺镜像从 skip 改为失败；本地无 Docker 时相关用例跳过，跳过不等于通过。

**运行器细节**（`packages/python-runner/`）：

- 一次求值对应一次进程或容器；每次全新的 globals，用户代码必须自己给 `result` 赋值。
- 输入按类型解码：整数走十进制字符串（不经 float）、字节走十六进制、文本与布尔按原样。
- 错误码分四类：`syntax`（带行号）、`runtime`（带行号与最后一行异常文案）、`bad_output`、`too_large`；
  不回传宿主路径、环境变量或完整 traceback。
- 用户的 `print` 与协议输出分开：协议只认 stdout 的第一行 JSON，stderr 只用于诊断且最多 4 KB。
- 工具与 `packages/shared/src/workflow/toolkit.ts` 的语义对齐，两侧各有测试。

**已知缺口（不美化）**：

- 杀 `docker run` CLI 不会停容器，只能靠 `--name` 与超时后的 best-effort `docker kill`；
  容器内 rlimit 兜底。这条未经真实守护进程验证。
- `RLIMIT_AS` 是"解释器 + 用户数据"的总量；启动时若解释器已占用接近上限，运行器会跳过该限制
  并在 stderr 写一行说明，而不是假装设过。
- 用户代码直接写 fd 1（例如 `os.write(1, ...)`）会破坏单行协议，该次求值以 `bad_output` 失败；
  但伪造不了结果，因为 `requestId` 由服务端生成并在服务端校验。
- Windows 没有 `resource` 模块，RLIMIT 行为只覆盖了降级分支。

**证据**：`packages/server/test/python.test.ts`（桩运行器覆盖协议与配额）、
`packages/server/test/python-real.test.ts`（真实解释器与 Docker 用例；CI 缺后端时显式失败）、
`packages/python-runner/test_runner.py`（33 条运行器自测）、`packages/python-runner/README.md`。

## 3. 首批 Python 工具：内置实现，不依赖 pwntools

**决定**：运行器自带 `p32/p64/u32/u64/flat/cyclic/cyclic_find`，不安装 pwntools。
`cyclic`/`cyclic_find` 与 `packages/shared/src/workflow/toolkit.ts` 使用同一 de Bruijn 语义：
`cyclic(16) == 'aaaabaaacaaadaaa'`、`cyclic_find('baaa') == 4`，两侧各有测试对齐。

**解释器**：Docker 后端默认镜像 `python:3.12-alpine`；`process` 后端默认 `python3`。
版本以部署配置为准，不在代码里散落版本号。

**边界**：跑在运行器里的代码仍然可以 `import` 标准库——系统隔离由容器提供，
不以"禁用 import"冒充隔离（07 §2）。

## 4. 旧存档迁移：新键只读迁移，旧键永不覆盖

**现状（P8 收尾）**：新画布把带格式、版本、题目和依赖的存档写到
`pwn2block.graph.v1.<challengeId>`；早期裸文档键 `pwn2block.graph.<challengeId>` 与旧 Blockly 键
`pwn2block.canvas.v1.<challengeId>` 都保留。读取顺序是新键 → 过渡键 → Blockly 键；新键存在但损坏时
直接报错并保留原文，**不回退**到旧键，避免用户以为旧内容还在。

**迁移**：旧 workspace 按支持的积木白名单单向转成 `GraphDocument`：变量在 `main` 顶部声明为整数 0，
`vars_set` 转 `var.set`，控制结构展开成 `regions`，字节与动作保持原语义。未知积木、多入口/无入口、
只读变量或字节变量会拒绝整次迁移并列出原因；失败时原文不删除、不覆盖，面板提供导出 JSON。

**不承诺**：迁移只保证受支持积木的动作等价，不保留 Blockly 的视觉布局；旧键不会被清理，回退版本
仍按旧格式读取，不会声称能编辑新格式的模块/Python 功能。

## 5. 执行额度：定义在 shared，前后端共用

数值只写在 `packages/shared/src/limits.ts`，这里只列口径：

| 额度 | 值 | 超限行为 |
|---|---|---|
| 单循环轮数 / 全图累计轮数 | 256 / 4096 | 报 `limit_exceeded`，定位到对应循环 |
| 单次求值步数 | 4096 | 报 `limit_exceeded`，带节点 id |
| 单次动作字节 / 提交动作数 | 512 KB / 4096 | 编译期拒绝，不发布部分产物 |
| 图节点 / 连线 / 区域条目 / 嵌套 | 256 / 1024 / 512 / 8 | 校验期报错 |
| 模块数 / 模块嵌套深度 | 64 / 4 | 校验期报错 |
| Python 单次超时 / 内存 | 2000 ms / 64 MB | 杀进程，回 `timeout` |
| Python 输出 / 日志 | 8 KB / 4 KB | 回 `too_large`，不截断成"成功" |
| Python 输入个数 / 整数位数 | 8 / 512 位 | 请求校验或运行器拒绝 |
| Python 并发 / 排队 | 2 / 8 | 回 `quota` |
| 每次编译 Python 求值次数 | 64 | 编译期报错，不发请求 |

**口径一致**：前端求值器与服务端共用同一组常量；服务端对客户端传入的每个请求再校验一次，
不假设客户端守规矩。
