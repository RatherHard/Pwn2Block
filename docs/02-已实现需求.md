# Pwn2Block 已实现需求

以下记录当前已实现能力，包括 MVP、节点画布与交互布局。历史需求和阶段验收见 [归档目录](archive/README.md)，工程待办见 [05-未完成工作](05-未完成工作.md)。

## 学习者能力

- 浏览题目公开说明和公开内存布局。题面和提示按 Markdown 子集渲染：`#`–`######` 标题、段落、代码块、`>` 引用、有序和无序列表（最多 3 层嵌套）、`---` 分隔线，以及粗体、斜体、行内代码和链接；链接只显示文字，不生成外链，原始 HTML 和无法识别的标记按原文显示。
- 返回题目列表并切换题目，保留各题画布并接回仍有效的调试会话。题目列表（`/`）和题目页（`/challenges/<id>`）各有地址，刷新、前进后退和分享链接都落到对应页面；不存在的题目显示「题目不存在」。
- 创建、查询、删除会话，并在会话中反复调试。
- 查看栈、指令、寄存器、内存（含 VMA）和标准 I/O 等状态。视图区一次只显示一个视图，用固定标签切换（本题没有 I/O 时不显示该标签）；标签栏支持 ←/→/Home/End，页面上任意非输入位置可用 Ctrl+↑/↓ 循环。当前标签存在浏览器本地 `p2b:view-tab`，所有题目共用，读取失败或值非法时回到「栈」。
- 题目带伪代码时，可在视图区的「伪代码」标签页查看出题人写的伪代码（等宽、只读，按 C 语法着色：注释、预处理指令、字符串、数字、关键字、类型、函数名）；没有伪代码的题目不显示该标签。
- 使用 `write_bytes`、`push`、`pop`、`call`、`ret`、`feed`、`step`、`run`、`undo`、`step_back`、`reset` 等动作。
- 在节点画布中拼装字面值、表达式（含组合、字典、切片与十二种转换）、变量与流程，并调用题目公开的方法积木；方法参数只能是字节串、整数或地址，展开由服务端完成。
- 改动节点后自动重新编译为受限的原子动作（每次变化都重编，修订号 +1，没有单独的「编译」按钮）；编译错误按节点列在输出区，点「定位积木」会滚到那个节点并高亮 1.2 秒。没有独立程序区。
- 点画布顶栏的「运行」执行整段 payload：先 `reset`，再按单次请求上限分片发送完整动作序列，末尾不补 `run`，与提交判题回放的是同一份序列；画布为空时发 `reset` + `run`。运行中可点「终止」，它只在浏览器侧停止发送后续分片，已发出的请求照常生效，状态栏显示「已终止：执行到动作 n/m」。单步、运行 N 步、后退、撤销、重置和提交判题在顶栏「运行」菜单里。在输出区和状态栏查看失败原因、错误定位、状态变化和回放录像。
- 逐级查看提示；提示和节点画布可以按题目保存在浏览器本地。
- 提交 payload 进行独立判题；判胜后查看并复制 flag，失败后回到调试继续修改。
- 刷新页面后恢复已有服务端状态和前端程序指针（在会话仍有效时）。

## VM 与安全能力

- 可配置位宽、寄存器、VMA、权限、指令编码和成功/失败条件。
- 实现教学需要的栈操作、调用/返回、内存读写、指令执行、快照、回退和回放。
- 支持受控的 `read`、`write`、`exit` 等 I/O/syscall 语义和虚拟文件。
- hidden memory 只在服务端执行，公开投影不包含隐藏字节。
- 调试和判题使用独立 VM 实例；提交从初态回放，不能借用调试时的手工操作。
- 动作、payload、请求体、编译展开、I/O 和资源使用均有边界校验。
- 未声明动作或 syscall 会被拒绝；失败动作不会产生未声明的副作用。
- 服务端负责最终校验，浏览器编译器不承担安全职责。

## 题目与工程能力

- 六道 MVP 题目包与后续新增的 `ret2rop` 均包含公开题面和服务端私有材料。
- `challenge:new`、`challenge:asm`、`challenge:check`、`challenge:solve` 出题工具链可用。
- 题目 flag 使用环境变量注入，缺少 flag 时题目不会被加载。
- 题目可附带 `pseudocode.c` 伪代码，随公开包下发；服务端加载和 `challenge:check` 校验 UTF-8 / LF（仅出题侧）、长度上限，并拒绝含 flag 占位符或真值的伪代码。`challenge:new` 不生成该文件。`ret2rop` 已提供伪代码，其余六道题暂未提供。
- Fastify API 和构建后的前端静态资源可以由单进程提供。
- 已有单元、集成、验收和浏览器 E2E 测试覆盖核心闭环、边界和安全契约。

## 节点画布（新版，三阶段已完成）

旧 Blockly 画布（`packages/web/src/graph/`、`packages/web/src/workflow/`、客户端编译实现、`packages/shared/src/workflow/`）与整条 Python 求值链路已经删除。现在的画布是三组纯函数：编辑命令是「文档 → 新文档 + 问题」，渲染是「文档 → 视图模型」，编译是「文档 → 受限动作」。需求与验收标准见 [节点画布大型修改](节点画布大型修改.md)，分阶段实施映射与逐条验收结论见 [节点画布改版计划](节点画布改版计划.md)。

### 文档模型与存档

- `CanvasDocument` 只有五个字段：`format`（固定 `pwn2block.canvas`）、`version`（2）、`nodes`（平铺数组）、`layout`（`节点 id → {x, y}`，只影响显示）、`main`（顶层有序序列）。区域**内联在节点上**——`if` 自带 `then` / `else`，`loop` 自带 `body`，没有独立的 `regions` 表；变量声明、引用视图、循环索引都是普通节点，没有单独声明表；方法不存定义，只存指向题目 `public.json` 里 `authorBlocks` 的标识。选中集、就地编辑框、撤销栈都是面板状态，不写进文档。
- Schema 在 `packages/shared/src/canvas/schema.ts`：严格对象、多余字段拒绝，节点 id 只允许字母/数字/下划线/连字符且长度 1–64，坐标绝对值上限 100000。`parseCanvasDocument` 先判 `format`、再判 `version`、最后判形状，失败原因是 `legacy` / `format` / `version` / `invalid` 之一；读到旧档给的是「这是旧版画布存档（格式），新版画布不兼容」，不当作损坏。
- **「未接线」是一等编辑期状态**：数据输入引用与方法标识都允许空串（`UNCONNECTED`）。`inputIdsOf` 跳过它，校验报 `unconnected` 并点明哪个节点的哪个端口，求值回同一句话；引用检查也只对非空 id 报「引用了不存在的节点」，所以新建一个方法节点只会得到一条「还没接线」，不会同时冒出两条自相矛盾的错误。新拖出来的节点因此可以先落盘再接线，不必先造占位节点。
- 节点 18 种，按能力分三类：数据节点 10 种（`value`、`group`、`dict`、`relation`、`unary`、`index`、`lookup`、`slice`、`repeat`、`convert`）、变量节点 3 种（`var-decl`、`var-ref`、`loop-index`）、流程节点 5 种（`start`、`if`、`loop`、`method`、`assign`）。
- 存档外壳是 `pwn2block.canvas-save`（版本 1），按题目写入 `pwn2block.canvas.v2.<challengeId>`；写之前读回校验一遍，坏数据不进存储。加载结果三种：`empty`（给一份只有开始节点、已排在 `main[0]` 的默认文档）、`canvas-v2`（直接装载）、`corrupt`（**保留原文**、明说不可用，绝不静默覆盖）。编辑 400ms 后写一次，面板卸载时立刻补写。

### 值语义

- 值 7 种：字节串、整数（任意精度）、浮点、文本、布尔、列表、字典；其中标量 5 种。
- 二元运算 28 个：整数 10（加、减、乘、整除、取余、与、或、异或、左移、右移）、浮点 4（加、减、乘、除）、整数比较 6、浮点比较 6、布尔 2（`bool.and` / `bool.or`，短路）。一元运算 2 个：`bool.not`、`length`。整数是任意精度，整除向零截断、取余符号跟着被除数（**与 Python 的 `//`、`%` 不同**）；移位量先验范围（0–1024）再算；浮点除零与溢出都报错，不产生 `Infinity` / `NaN`。
- 转换 12 种：文本↔字节串、整数↔字节串、整数↔浮点、整数↔文本、浮点↔文本、字节串列表→字节串、文本列表→文本。参数是可枚举的封闭集合：编码只有 `utf-8` / `ascii`，整数宽度 1/2/4/8 字节，字节序 `little` / `big`，取整方式 `trunc` / `floor` / `ceil` / `nearest`，整数文本进制 10 / 16。非法输入（孤立代理项、非 ASCII 字符、非法 UTF-8、NaN 与无穷、超宽整数、长度与宽度不符）逐项报错并给出原因，不静默替换。
- 组合两种模式：`merge`（合并为串）只支持全字节串或全文本，否则报 `group_mode_conflict` 并建议改「组成列表」或先逐项转换；`list`（组成列表）接受任意成员，可嵌套。字典键按编码后的身份判重，重复键报 `dict_duplicate_key`。
- 切片照 CPython `slice.indices()` 实现：省略、负值、超界都按同一套裁剪规则，文本按码点、字节串按字节、列表按元素切；步长为 0 报「切片步长不能为 0」。
- 问题代码集 20 个（`unknown_node`、`unknown_kind`、`duplicate_id`、`invalid_id`、`self_reference`、`input_cycle`、`type_mismatch`、`group_empty`、`group_mode_conflict`、`dict_duplicate_key`、`conversion_unsupported`、`invalid_value`、`eval_failed`、`limit_exceeded`、`ownership_conflict`、`variable_error`、`flow_error`、`method_mismatch`、`unconnected`、`pending`）。等级只有 `error` 与 `warning`，`pending` 是唯一的警告（「这个值依赖流程执行结果，运行后按步骤查看」）；同一节点上重复的问题按「代码 + 节点 + 文案」去重。
- 静态校验只推到值类型这一层（值的种类，不推列表元素），明显错的在编辑期就拦下；额度：单值字节串 512 KiB、文本 262144 字符、整数 1024 位、嵌套深度 16、集合条目 1024、字典键 128 字符、求值步数 4096、表达式深度 64。

### 节点目录

- 目录集中在 `packages/web/src/canvas/catalog-specs.ts`：18 种节点的默认值、字段、端口类型与工具箱分类一处定义；端口由 `inputRefsOf` 派生，所以「目录端口」和「实例端口」结构上不可能漂移。
- 工具箱七个分类，实际顺序是**值 → 集合 → 运算 → 转换 → 变量 → 流程 → 方法**，同一分类不切开。集合类是组合、字典、按索引取元素、按键取值、切片、重复；运算类是关系运算与附属的一元操作；流程类是开始、分支、循环、赋值。

### 流程、变量与方法

- 顺序用数组表达：`main`、`if.then`、`if.else`、`loop.body` 都是有序数组，一个流程节点只能属于一条序列，所以回边与跨区域接线在结构上就表达不出来，校验不必追环。
- 开始节点：一旦出现流程节点，就要求恰好一个 `start` 且排在 `main[0]`；纯数据文档（`main` 为空、没有流程节点）继续合法。
- 循环：次数只读一次、必须是非负整数，超过 256 直接报错、不截断；`loop-index` 显式带上所属循环的 id，作用域按**使用点**判定（必须在那个循环体的子树内），因此嵌套循环可以显式读外层索引。
- 变量：声明带名称（去空白后唯一）、固定类型与绑定（无绑定 / 初值 / 派生）。派生变量只读、每次读取按当前状态重算（同一轮内用轮次版本号缓存），流程赋值一次写入且只能写普通变量，解绑不保留旧值；自引用与循环依赖报错。变量只有一份声明，全局限定为「本次执行」，没有跨运行的持久值。
- 方法：目录来自题目 `authorBlocks`，参数类型只有字节串、整数、地址（中文名分别是「字节串」「整数」「地址」）。生成时把参数值**快照**进动作：字节串→无前缀 hex，整数/地址→`0x…`，地址不得超过 64 位；生成前用服务端同一个 `expandBlock` 预检一次，本地就能发现「参数形式对、模板展开必被拒」的图。
- 预算：流程节点 256、区域嵌套深度 8、单循环 256 轮、所有循环累计 4096 轮、动作 2048、步骤快照 2048、方法参数 8，任一超限整体失败并定位到节点。

### 编辑命令与撤销

- 命令都在 `packages/web/src/canvas/editor*.ts`，形状统一为「(文档, 参数) → `{document, issues}`」：拒绝时返回原文档并带一条可直接显示的中文问题。界面只调命令，不直接改文档；**一条命令 = 一次文档变化 = 一次可撤销快照**（历史深度 100，拖动十像素也只堆一条）。
- 节点与属性：`addNode`、`addExistingNode`、`setValue`、`setRelationOp`、`setUnaryOp`、`setConversion`、`setDictEntries`、`setGroupMode`、`setMethodBlock`、`connect`、`disconnect`、`removeNodes`、`moveLayout`。
- 变量：`createVariable`、`createReference`、`renameVariable`（只改声明名，所有引用视图跟着变）、`setBinding`、`setAssignTarget`（赋值的写入目标是变量声明而不是数据节点，接线命令管不到它）。
- 组合（行列是权威值，坐标只影响显示）：`createGroup`、`insertRowAfter`、`removeRow`、`moveMember`、`dissolveGroup`；成组至少一个成员、不含流程节点、不与既有组合重叠。
- 序列：`insertStatement`、`appendStatement`、`moveStatement`、`removeStatement`；一个流程节点已经在某条序列里时不能再插一次。
- 包络：`wrapInLoop`、`wrapInBranch`、`unwrapLoop`、`unwrapBranch`。只接受**同一条序列里连续的一段**，包完继承第一句的坐标并整体下沉一层（嵌套会超过 8 层就先拒绝）；解除循环按原顺序接回原位置，解除分支固定「成立分支在前、不成立分支在后」顺序展开——这是确定的顺序展开，不是合并两条路径，容器节点与它的坐标一起删掉。
- 转换包络：`wrapInConversion`、`unwrapConversion`、`externalRefsOf`（`packages/web/src/canvas/editor-convert*.ts`）。包络为转换要求选区全是数据节点、且**有明确的整体结果**——多于一个成员时先合组成整体，再把外部对整体结果的引用一次性改接到新转换节点，所以原来读整体的地方自动变成读转换结果，类型不匹配由校验器标错；如果还有外部节点引用着**内部中间结果**，直接拒绝并在提示里点名是哪个节点，先把那条改接或删除（否则转换会悄悄改变它的语义）。底层 `unwrapConversion` 保留单独拆转换的命令；界面的解除入口统一走 `dissolveEnvelope`，移除包络及附着转换，内部数据保留。单一结果的消费者接回该结果，多成员整体的消费者明确断开，不保留悬空 id。改接按端口形状分三种写回（普通端口、变量绑定、字典条目），组合成员跳过——结构归属不是引用。
- 连带删除：删节点会连带删掉只依赖它的引用者、它的区域成员与因此变空的包络，`layout` 一起清理；拆包络、删行这类结构操作不连带删别的节点，悬空引用交给校验器报错。

### 视图与落位

- `layoutCanvas`（`packages/web/src/canvas/view-model*.ts`）把文档算成：`boxes`（包络矩形 + 白框节点 + 彩色关系方框）、`ports`（数据输入）、`flowPorts`（流程进/出，外置小方框）、`edges`（数据线 + 流程线）、`previews`（每个数据节点一行摘要）、`issuesByNode`、`regionOf`。几何是确定性纯函数：同一输入两次结果完全相等，不读 DOM、时间与随机数。
- 拖动超过 4px 后更新临时坐标，松手将移动和结构修改合为一次撤销。不按 Shift 时启用 8px 网格及结构吸附：组内行列重排、同类数据组装、流程插位。纵向流程按纵坐标插入，横向流程按横坐标插入。拖到空白处会脱离原链，剩余前后链自动接回并收拢；流程容器的内部语句随整体移动。组合按结构真实尺寸排布，最小行距 142px，列距至少 292px，横向关系间隔 112px。按 Shift 关闭吸附和脱离。
- 工具箱加出的流程节点须拖入序列才会执行；数据节点只能参与数据结构，方法及其他节点的数据来源在侧栏选择。
- 框选：空白处按下拖动即框选，Shift 加选；方向键移动 8px，Shift+方向键 32px。
- **没有缩放**：画布 1:1 绘制，`.stage` 是原生滚动容器，平移就是滚页面或滚画布；工具箱里没有缩放按钮，也没有「适应画布」快捷键。

### 编译与产物

- 入口 `compileCanvas`（`packages/web/src/canvas/compile.ts`）：输入文档、题目 `authorBlocks`、`documentRevision` 与可选动作上限，输出 `{ok, artifact, warnings}` 或 `{ok: false, issues}`；`compileCanvasWithSteps` 另外交出每步快照（这一步读到的输入、之后的变量值、所在轮次），面板用它渲染画布下方的**步骤表**：每行是步号、节点标题、各层循环轮次（外→内全部列出，显示 +1）、读入的值与执行后的变量值，点一行定位到对应节点；没有可执行步骤时给空态文案，编译失败时步骤表清空（不残留上一轮的行）。
- 产物 `WorkflowArtifact`：`actions`、`origins`（与动作等长同序，`index` 逐项对齐，错位直接抛错而不是静默定位错节点）、`originsVersion`、`previews`、`trace`（上限 256 条）、`documentRevision`。
- 动作只有 `{type: 'block', id, args}` 一种，凡客户端可见的动作列表都由服务端的 `expandBlock` 展开；客户端不展开出题人积木，失败时**不发布部分动作**。
- 问题代码映射成产物的 `WorkflowIssue['code']`：`self_reference` / `input_cycle` → `data_cycle`，`group_empty` / `group_mode_conflict` / `dict_duplicate_key` / `conversion_unsupported` / `invalid_value` → `invalid_param`，`ownership_conflict` → `duplicate_placement`，`unconnected` → `missing_input`，`variable_error` / `flow_error` / `method_mismatch` / `pending` → `eval_failed`，其余同名。中文文案不经过映射，原样保留。
- 面板每次变化都重编译（修订号 +1）：成功发 `p2b-canvas-compiled`、失败发 `p2b-canvas-compile-failed`；改动画布后控制器把上一份产物标为过期，运行菜单据此拦住执行类动作（提示「积木已改动，正在重新编译」）。面板在同一次变化里就重编译，所以这个拦截通常只持续一瞬。

### 逐题公开方法

- 画布上的方法节点只能调用 `public.json` 的 `authorBlocks` 声明，未声明的 id 在编译期和提交时都被拒绝。7 道题均已声明 `authorBlocks`：`callret` → `push_value`；`endian` → `write_bytes`；`localvar` → `gets`；`pushpop` → `push_value`、`pop_value`；`ret2rop` → `name`、`introduce`；`ret2win` → `gets`；`stackframe` → `capture`。`step` / `run` 不由方法提供，仍在顶栏的「运行」菜单里。
- 参数类型只有字节串、整数、地址，展开一律由服务端 `expandBlock` 完成，客户端只发 `{type:'block', id, args}`。`write_bytes` / `push_value` / `pop_value` 的展开动作都落在该题 `allowedActions` 内；`gets` / `capture` / `name` / `introduce` 是不带地址参数的固定落点窄接口，展开出的 `write_bytes` / `feed` 只作用于旧画布已经给的那一处，权限面没有变大。
- `packages/shared/test/challenge-methods.test.ts` 读真实题目包逐题锁定 id 清单与权限面：8 个方法声明的 id 表、5 个窄接口（只允许固定落点、不许地址/整数参数）的签名、4 个已被画布用例覆盖的方法。

### 旧档与迁移

- 旧档只识别、不迁移。`LEGACY_STORAGE_KEYS` 认四个前缀：`pwn2block.canvas.v1.`、`pwn2block.graph.v1.`、`pwn2block.graph.`、`pwn2block.workflow`。扫描只读，格式按原文里的 `format` 分类为 `pwn2block.workflow` / `pwn2block.canvas` / `blockly` / `unknown`，跳过新版 v2 键、会话键与探测键。
- 提示条（`legacy-archive-bar`）非模态、`role="status" aria-live="polite"`，列出份数、涉及题目与总字节数，出口两个：「导出旧存档」按原文逐份下载 `pwn2block-legacy-<题目>-<档位>.json`（内容一字不改，能喂回旧版本）；「新建新版画布」需要点两次（先切到「确认丢弃 N 份」）才删，且只删扫描到的旧键。任何路径都不会静默覆盖或清空旧档。
- 旧工作流原文被塞进 v2 键时，面板发 `p2b-canvas-legacy` 把原因与原文交给外壳提示条；上一版画布（`format` 对、`version` 为 1）的失败原因是 `version` 而不是 `legacy`，所以面板不为它发事件，它只由提示条扫描层列出。

## 节点画布交互与布局

2026-10-29 按新的 UI 与交互重构要求修整。旧改版计划与大型修改文档保留为历史记录，界面行为以本节为准；底层值模型、编译与后端权威边界沿用现有契约。

- **布局与节点库**：三栏为 `20rem / minmax(0, 1fr) / 18rem`。左栏首页列分类，进入后显示小类与节点选项，并提供返回；分类与搜索结果均每页 5 项。每个选项内常驻标题、外观、说明和用法预览，随选项一起滚动。点击添加或拖到画布添加都保留。
- **节点与关系**：节点为白色边框、深色背景的大方框，只展示内容。运算、赋值、列表组装和串连接使用较小的彩色边框关系框，显示符号或名称，并在两侧保留间距。关系在 DOM 中使用 `data-relation`，不作为节点参与框选；点击或 Enter/Space 切换运算。转换作为附着在包络边缘的控制框展示。
- **配置位置**：字面值、变量名称与绑定、方法选择及参数来源、转换选项、集合属性等统一在右侧检查器编辑。节点上没有数据连接点、输入控件或双击编辑；数据来源可在侧栏选择或清空。工具按钮不再显示装饰性方括号。
- **流程连接**：纯色正交线连接节点外部的独立小方框，仅展示实际连接的入口/出口。数据关系无需端口拖线；方法等普通数据引用仍可显示只读依赖线。
- **吸附与脱离**：数字吸附默认加法、布尔默认与；同类文本和字节串默认连接，其余数据组成列表。值吸附到变量声明建立赋值关系，可点击关系切换初值/派生绑定。拖走链中成员后，剩余表达式或流程序列接回并收拢；拖走赋值两端会解除绑定。流程吸附同时检测鼠标与被拖节点上下边缘，落位后纵向对齐，节点结构间保留 48px 连线间距并推动后链；游离的普通流程节点可相互吸附，按上下位置确定先后并接入主流程。一次拖动及其结构变化只占一条撤销记录。
- **框选与包络**：空白拖动框选，Shift 加选。完整表达式自动提升为关系根，无需额外选中关系框。右键可包络数据结构、包进循环/条件分支、包络为转换。流程包络要求同一区域内的连续语句；循环、分支与转换控制框附着在包络边缘，拖动标题时内部结构整体跟随。
- **解除**：右键、顶栏与侧栏统一移除选中包络及附着转换，保留内部节点。单结果引用接回内部结果；多成员整体失去聚合语义后，其消费者显式断开。循环按原顺序展开，分支按成立区域在前、不成立区域在后的顺序展开。均可撤销。
- **右键菜单**：TUI 菜单包含撤销、重做、数据包络、循环包络、条件分支包络、转换包络和解除。不可用动作禁用；右击已选结构内部保持选区，方向键移动菜单焦点，Escape 或外部点击关闭。
- **精简交互**：删除端口悬停放大、临时拉线、吸附提示层、就地编辑和限时闪烁高亮。保留选中边框、框选框、原生滚动及必要状态提示；定位错误节点改为持续选中。没有缩放。
- **快捷键与运行**：保留撤销/重做、删除、方向键移动、循环/分支包络快捷键；文本输入期间不劫持编辑键。运行、编译计数、步骤与轮次、存档恢复和旧档导出沿用现有入口。
