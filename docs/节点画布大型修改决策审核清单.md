# 节点画布大型修改：剩余决策审核清单

状态：全部待用户审核，尚未采纳。整理日期：2026-10-23。

对应需求草稿：[节点画布大型修改需求](节点画布大型修改需求.md)。已确认 R-01 至 R-82 不重新表决；本清单集中列出原文范围及当前已知的全部剩余产品决策，供一次审核。D 编号仅表示建议，不是已确认的 R 规则。

审核方式：可以整体采用，也可以仅列出需要修改、删除或暂缓的 D 编号和具体意见。存在依赖的建议已写明；接受“本期不做”也属于明确范围决策。技术实现方式、组件内部划分和开发排期不在这里替用户预先决定。

## 一、数据、变量与表达式（D-01—D-10）

### D-01 基础运算符集合

建议：int、double 支持同类型的加、减、乘、除、一元正负号、绝对值；int 另支持余数、按位与/或/异或/取反、左右移位。bool 提供 NOT、短路 AND/OR，以及非短路 XOR。XOR 先左后右完整求值。第一期不加入幂、三角函数、复数、double 取余或自动向量运算。

边界：double 除以正零或负零均报错；计算产生非有限值沿用 R-13。整数除法和余数沿用 R-26，不改变已有向零截断约定。

### D-02 相等与大小比较

建议：所有同类型值支持 `==`、`!=`；数组逐层按类型、长度、元素值比较，byte 按字节，string 按码点，bool 按真假。数组长度不同结果为 false，不是类型错误；嵌套层级或元素类型不同属于类型错误。大小比较 `< <= > >=` 第一期开给 int、double，其他类型不提供隐含排序规则。

例：`[1, 2] == [1, 2]` 为 true；`[1] == [1, 2]` 为 false；int `1` 与 double `1.0` 需先显式转换。双方表达式仍先左后右完整求值，结构比较不会跳过另一方表达式的副作用。

### D-03 近似比较只采用显式绝对容差

建议：第一期提供 `abs(a - b) <= tolerance`，a、b、tolerance 均必须为 double，容差必须有限且不小于零，不预填隐含容差；按 a、b、tolerance 顺序求值。零容差按精确数值相等处理。相减产生非有限结果也报错，不返回 false 掩盖错误。

取舍：暂不增加相对容差、有效位数和 ULP 模式，避免同时出现数套接近规则。需要更多策略可后续独立扩展。

### D-04 表达式由结构确定，不靠视觉优先级猜测

建议：每个运算关系明确输入与输出；嵌套或显式分组确定计算树，不根据节点横坐标、线条交叉或连线创建顺序套用算术优先级。普通表达式的数据依赖禁止成环。读取变量当前值是表达式的叶子，流程 `x ← x + 1` 仍合法；模块递归仍按函数调用处理。

例：`(a + b) * c` 与 `a + (b * c)` 必须显示为不同结构。引用同一个模块输出两次仍按 R-55 调用两次，表达式共享不构成结果缓存。

### D-05 其余多参数操作统一使用声明顺序

建议：尚无专门规则的操作按界面明确列出的输入顺序，逐个完整求值并捕获值；全部成功后执行操作。中途失败停止后续输入，已发生的副作用保留。已确认的短路、切片、转换、索引读写和模块实参顺序优先适用。

补充：提供“条件选值”，先求 bool 条件，只求选中值；两个候选结果静态类型必须完全一致，未选中一侧仍静态检查。本条禁止为了预览、优化或公共子表达式消除而重排有副作用的求值。

### D-06 常量输入语法与显示

建议：int 支持有符号十进制，以及带 `0x`、`0b`、`0o` 前缀的十六、二、八进制；double 支持十进制与科学计数法；bool 用真假切换。byte 默认用十六进制输入，每两个十六进制字符表示一字节，允许字节间空白，禁止奇数位、隐式补零与非法字符。string 默认按原文输入，转义视图是明确切换的另一编辑模式；转义模式仅支持明确列出的反斜杠、引号、换行、回车、制表及 Unicode 码点转义，不支持表达式插值或执行。

例：byte 输入 `00 FF` 保留零字节；原文 string 中输入反斜杠和 n 是两个字符，不自动变为换行。未完成输入如 `0x` 或 `A` 保留为编辑草稿并标错。导入导出须保留这类尚未解析成功的编辑文本。

### D-07 名称规则

建议：变量、形参、模块名称采用 Unicode 字母或下划线开头，后续允许 Unicode 字母、组合标记、数字、下划线，最多 64 个码点；比较名称前做 NFC 规范化，大小写敏感。模块在项目内不重名；变量仍遵守 R-42 的作用域规则。名称是显示标签，引用绑定稳定身份，不按名称重新寻找声明。

例：支持“载荷长度”；`data` 与 `Data` 不同；两个规范化后相同的名称不能在同一命名空间共存。界面提示规范化结果，不静默覆盖其他声明。

### D-08 全局初始化与派生值的计算时机

建议：从头运行时先建立普通全局的初值，再开始流程；普通初值中没有运行副作用。派生全局的依赖关系在运行前检查为无环，实际读取派生值时使用依赖变量的当前值求值。修改来源不强迫立刻读取所有派生值；读取结果不形成冻结快照。

例：派生 `d = 10 / x`，x 的运行值变成零时，单独修改 x 不触发 d 的运行时除零；真正读取 d 时出错。能够静态确定的错误仍按 R-18 阻止启动。运行面板对尚未求值的派生值显示“待求值”，不因刷新而额外计算；依赖变动后旧读值标记已过期。

### D-09 变量声明、引用与常量的关系

建议：同一声明可生成多个引用节点；常量节点不建立可赋值声明。主流程使用全局变量和常量；模块另有形参和局部变量，第一期不增加主流程局部作用域或块级局部变量。

界面将全局“定义初值／派生定义”和流程“赋值”作为不同操作，清楚标出只读派生变量；读取引用没有初始化副作用。新增局部声明只定义类型和零值，显式初始化仍是用户放入流程的赋值步骤。

### D-10 修改声明类型与参数签名

建议：允许编辑声明的类型、模块参数和返回类型；保留使用处、旧连接和用户填写内容，重新校验，冲突时标错，不自动强转、补参、改写调用方或将原内容清零。变量改名不改变引用身份；模块参数按稳定身份绑定，修改显示顺序后按新的声明顺序求值。

边界：删除参数造成的旧实参保留为待处理的孤立参数项，必须显式删除或重新映射；新增必填参数保持缺失状态，不能偷偷填类型零值。

## 二、转换与序列工具（D-11—D-19）

### D-11 文本编码清单

建议：第一期支持 UTF-8、ASCII、Latin-1、UTF-16LE、UTF-16BE。全部采用严格编码与解码；不自动检测编码、不自动插入或去除 BOM、不规范化字符串内容。Latin-1 仅允许 U+0000 至 U+00FF，ASCII 仅允许 U+0000 至 U+007F。

边界：UTF-16 要求完整合法的代码单元序列；孤立代理项和不完整输入报错。BOM 若存在，按普通 U+FEFF 内容往返；UTF-16LE/BE 的字节序由所选编码明确决定。其他编码本期不加入。

### D-12 double 与 byte 的转换

建议：使用 64 位浮点二进制表示，固定 8 字节，默认小端，可选大端；byte 转 double 长度必须恰好为 8。保留正零、负零及有限值，解析出 NaN 或无穷时报错。

区别：这是浮点位表示转换，不是先向零截断为整数再编码；没有“有符号／无符号”选项，也不沿用整数转换的动态宽度。本期不支持 4 字节浮点转换。

### D-13 int 与 string 的转换

建议：string 转 int 严格采用 D-06 的整数语法，须消费完整文本，不自动去除首尾空白，不接受小数、分隔符或残余字符。int 转 string 默认十进制，可固定选择 2、8、10、16 进制；非十进制输出前缀，负号位于前缀之前，十六进制字母默认小写。

例：`"0xff" → 255`；`"12abc"`、`" 12 "` 报错；负数格式化为 `-0xff`。进制是节点固定配置，不是运行时表达式。

### D-14 double 与 string 的转换

建议：输入仅接受完整的十进制或科学计数法文本，不接受 NaN、Infinity、千分位、首尾空白或本地化小数逗号。输出使用可还原同一有限 double 的十进制表示，不受系统语言影响；负零明确输出为 `-0.0`。下溢正常舍入为零或有限非正规数沿用正常舍入规则，溢出报错。

第一期不增加任意小数位格式化面板；显示缩略值与真实转换输出分开。

### D-15 bool 的显式转换

建议：bool 转 int 使用 false→0、true→1；int 转 bool 只接受 0、1，其他整数报错。bool 与 string 仅接受、输出小写 `false`、`true`。bool 不直接与 double、byte 或数组互转，用户通过已有显式步骤组合。

取舍：不引入“非零即真”或“非空即真”；例如需要 `x != 0` 就使用明确的比较节点。

### D-16 转换矩阵封闭，数组不自动逐元素转换

建议：直接转换仅开放 R-19 至 R-24 和 D-11 至 D-15 列出的类型对；不支持的组合在编辑时标错。相同类型无需增加转换层。数组不能被自动打包、自动展平或自动逐元素强转；转换包络先取得整体值，再检查该整体类型能否转换。

例：int 数组不能直接通过 int→byte 包络变成机器字节序列；应分别转换元素后合并 byte。byte 数组可通过 D-18 的显式合并得到 byte。

### D-17 十六进制文本与字节编码分开

建议：提供 byte↔十六进制 string 的独立操作，明确标注“十六进制解析／格式化”。解析采用完整偶数位十六进制，允许字节间空白；格式化默认每字节两位大写、空格分隔。不要把它列为 UTF-8 等文本编码的一种。

例：HEX 解析 `"41"` 得到 byte `41`；UTF-8 编码 `"41"` 得到 byte `34 31`。

### D-18 序列长度、合并与重复

建议：string、byte、数组均提供 length，输出 int；数组长度仅数当前层元素。提供同类型序列合并，数组合并仅合并当前一层，不递归展平；另提供 `byte[] → byte`、`string[] → string` 的显式合并。byte/string 支持非负 int 次重复，零次为空，负数或超资源上限报错。

顺序：合并按输入列表顺序求值；重复先求对象再求次数，次数为零也不省略对象求值。数组合并的元素类型和层级必须一致。

### D-19 保留面向 payload 的便利操作

建议：保留填充、地址转字节、按偏移组装、定位序列生成与偏移查找。地址在画布中是 int，使用题目公开位宽、默认小端和无符号的明确转换配置，超范围报错。填充单元是长度为 1 的 byte，次数是非负 int。

按偏移组装先求填充值，再按声明的段顺序逐段求偏移、内容；偏移为非负 int，重叠报错、空隙用明确的一字节填充值补齐，不隐式覆盖。定位序列保留现有固定规则和字母表选项，查找失败报错，不返回可误用为负索引的 -1。所有结果受统一资源限制。

## 三、结构、拖放与编辑（D-20—D-29）

### D-20 拼接模式与显式嵌套的创建方式

建议：byte/string 同类型片段吸附默认合并为一个串，可切换为“保留片段构成数组”；其他类型默认构成数组。已建立结构的模式固定保留，新增元素不自动切换。切换模式会明确展示输出类型变化，必要时让使用方显示类型错误。

提供“将选区构成子数组”，显式增加一层；显示完整结果类型与边界。换行只影响布局。同一包络层的连续选区才允许直接打包，禁止通过新建子数组穿越已有包络边界。

### D-21 跨结构拖动与非法落点

建议：落位前显示来源补位、目标插入点、预期结果类型。成功落位时同时移出来源并插入目标，一次撤销恢复两边。可表达但类型不匹配的落位允许保留，按 R-17 标错；自包含、产生交叉包络或没有合法所属位置的落点拒绝并恢复原位置。

拖到空白处按 R-06 脱离；Esc 取消整个拖动。空结构保留有类型的占位边框。整体移动不重新计算元素顺序。

### D-22 删除内容、解包与删除整体分开

建议：Delete 删除当前明确选中的对象；选中整个拼接结构或转换包络时连内部内容一起删除。另设“仅移除转换包络”和“解散拼接”，保留内部节点及顺序。删除元素后的补位、外部断开的连接与错误状态纳入同一个撤销单位。

转换包络被移除后不偷偷用未转换结果接管原转换结果的使用处；受影响连接保留修复信息并重新校验。变量声明删除与普通引用节点删除是不同操作，声明删除遵循 R-81。

### D-23 一般表达式的转换选区

建议：拼接结构仍按 R-16 选取连续片段；一般运算表达式仅允许包络具有一个明确输出的完整子表达式。禁止包络半条运算连接、多个互不相连结果或交叉选区。

嵌套包络按从内到外执行；先完成内部结构，再转换整体结果。创建包络时显示输入类型、输出类型和包含范围。

### D-24 包络的外部连接边界

建议：外部仅通过包络的整体输出使用其结果，不能直接穿过边界引用某个内部成员。创建包络导致原有连接穿界时保留连接信息并标错，要求用户显式改接；不自动把内部某值改成整个转换结果。

需要复用原值时可在外部放置同一变量的独立引用或显式保存结果。包络不是缓存：多次实际引用其包含的模块，仍分别调用。此限制针对画布结构边界，不限制内部引用合法作用域的变量声明。

### D-25 本期不做切片赋值和原地插入删除

建议：本期支持已经确认的整体赋值、单元素或嵌套路径替换；暂不新增切片赋值、append、insert、remove 等原地修改操作。需要改变长度时，显式用切片和 D-18 的合并构造新值，再整体赋回。

例：在数组 a 的 i 处插入 x，表达为合并 `a[:i]`、显式数组 `[x]`、`a[i:]`，再赋值给 a；多次读取可能含副作用时先显式保存需要复用的值。

### D-26 运算与参数编辑控件

建议：运算关系使用彩色小方框，明确标出左、右输入及结果；一元操作显示一个输入。多参数按声明顺序排列。切片使用 start、end、step 三个槽位，每个独立选择“省略”或“显式表达式”；索引使用单独槽位，不能把空输入自动解释成零。

允许槽位切换“常量／接线”；缺失必填接线是错误，只有切片允许明确省略。转换节点始终展示编码、端序、符号模式和固定宽度或宽度表达式入口；bool 取反显示持续可见的 NOT 标识。变量赋值明确显示“目标 ← 值”。

### D-27 分支与循环的区域边界

建议：条件分支显示条件区域、真/假两个流程区域及唯一汇合出口；循环显示条件或次数区域、循环体及正常出口。容器内空尾部按 R-71 结束本区域，正常返回容器的汇合或下一轮；区域折叠不改变执行。

不允许普通线从区域内部绕过容器任意连到外部或另一区域。条件区域允许合法表达式及模块调用，但不能塞入无表达式输出的任意流程片段。

### D-28 流程连线的编辑约束

建议：普通流程节点最多一个普通前驱、一个普通后继；开始节点无前驱。分支与循环通过自身结构管理多出口与汇合，不允许靠普通节点的多前驱偷偷创建另一套汇合机制。return、break、continue 没有普通后继。

插入到已有连线上可明确预览并一次替换连接；单独删除节点时不自动补接前后步骤，保留断开的结构由用户修复。允许暂存错误连线并标错，但运行前必须消除跨区域、普通环路等冲突。

### D-29 变量面板与声明编辑入口

建议：变量面板分为“全局”“当前模块形参”“当前模块局部”，引用节点持续显示作用域。全局声明显示普通/派生状态、初值或定义表达式；局部只显示类型零值与相关流程赋值入口，不提供会被误认为调用前执行的局部初始化栏。

删除声明、修改类型或定位使用处有独立操作；双击引用打开对应声明。编辑时看到的初值与运行面板的当前值遵循 R-80，不能直接修改运行值绕过流程。

## 四、模块、出题方法与已有功能（D-30—D-35）

### D-30 模块统一定义与版本策略

建议：统一成一种带固定返回类型的模块，可用作流程或数据。流程调用执行后可忽略返回值；数据调用按实际引用求值。同一项目内调用绑定同一个模块声明，定义变化后全部调用重新校验；本期不在一个模块内部维护多份可选择的历史版本。

现有固定版本依赖在迁移时可展开为不同模块声明，保留各自调用关系；不能静默将旧调用升级到新实现。代码仓库与项目导出可承担历史留档，不等同于运行时版本选择。

### D-31 出题人方法的参数、结果和权限

建议：沿用封闭的受限动作模板，第一期出题人方法只作为流程动作使用，不新增任意脚本或后端计算返回值机制。参数按声明顺序求值，类型、数量与题目权限严格检查；已有 bytes 映射为 byte，int/addr 使用 int，addr 另检查题目位宽和范围。

动作成功没有数据返回；需要数据用法时可放在模块内，由模块显式返回自己的值或按固定返回类型补零。禁止把方法直接放入全局定义、派生定义或编辑预览。界面仅显示服务端允许公开的信息，隐藏内容和 flag 不下发。

### D-32 选区提取为模块

建议：保留“选区封装成模块”，流程选区须有可明确替换的单入口、单出口；纯数据选区须有一个明确输出。进入提取预览后列出待提升为形参的外部数据输入、保留的全局引用和返回类型，用户确认一次才执行变换。

不隐式捕获调用方局部变量；跨选区的普通流程线或 break/continue 若无法合法封装，拒绝提取并说明原因。多个输出可由用户先组成同类型数组或调整结构，第一期不引入元组或多返回值。

### D-33 复制变量声明和模块定义

建议：声明复制产生新身份，名称冲突时给出可编辑的唯一名称；已有引用继续指向原声明。复制模块时连内部声明、结构和连接一起复制，内部形参/局部引用重绑定到副本。

副本对自身的递归调用重绑定到副本；对其他模块、全局变量的引用仍指向原声明。复制一个模块不会复制整个互递归模块集合；需要完整独立项目时使用 R-82。

### D-34 跨画布与跨项目粘贴

建议：同一项目内可跨主流程和模块粘贴；全局及模块引用保持身份，局部/形参若不属于目标作用域则保留为“作用域不匹配”，要求显式重绑定，不按同名猜测。普通外部连接不跟随复制。

第一期不提供跨项目局部节点粘贴或自动依赖合并；跨项目迁移使用完整 JSON 导入为独立项目。这样避免无意共享变量或漏带模块依赖。

### D-35 既有能力保留清单

建议：保留题目选择、公开内存/寄存器/指令视图、调试、提交判题、历史来源定位、变量、流程、模块、payload 工具及纯视觉分组。视觉分组只影响展示，与数组、转换包络、循环容器有不同边框和名称，不改变类型或执行顺序。

旧节点只保留功能目标，参数、类型、求值语义迁移到新规范；Python、跳转不保留，旧模块版本、默认参数、刷新恢复进度按对应迁移条款处理。新功能列表不会自动承诺复刻每个旧控件。

## 五、运行、停止与记录（D-36—D-41）

### D-36 从头运行与后端 VM 重置

建议：“从头运行”先做完整静态校验，建立新一轮画布变量状态，再将调试 VM 重置到题目初态，成功后执行流程；静态校验或初始化失败不触发后端动作。每次从头运行使用新的运行身份，不承接上一轮局部、栈或进度。

“继续”仅恢复本次暂停；单独手工重置或操纵 VM 前须结束正在运行/暂停的画布执行。这样程序从头运行具有明确起点，提交回放也能对齐。

### D-37 暂停与停止的安全边界

建议：暂停保留变量、函数栈、循环状态和待求值位置，继续不重算已完成输入；暂停期间仍按 R-78 锁定编辑。停止结束本次执行并解锁，不能再继续，既有副作用保留。

暂停/停止请求在下一处可中断边界生效；等待后端动作时显示“正在暂停／停止”，先核实在途动作结果，禁止后续动作。网络失败时标出“结果未确认”，不自动重发可能有副作用的请求，也不宣称动作已撤销；状态核实后才允许新一轮操作。

### D-38 单步的语义

建议：界面区分“画布单步”与“VM 指令单步”。画布单步默认执行一个当前流程步骤及其全部数据求值；模块调用默认执行完本次调用再停，循环容器每次进入/判断及循环体内步骤可分别停下。

第一期不加步入、步出或断点编辑器。即使单步执行包含长循环或递归，也必须能响应暂停/停止和资源限制；不会为了完成“一步”失去终止能力。暂停在表达式中途时内部求值状态保留，下一步不得重复副作用。

### D-39 提交使用固定运行产物，判题仍由服务端完成

建议：从题目初态开始且正常完成的当前项目运行可生成不可变的后端动作序列及来源记录，供提交到独立判题实例从初态回放。提交不重新调用画布模块或重复调试动作；服务端重新校验动作和权限，不接收客户端宣称的 VM 状态或成功结果。

修改执行语义后旧产物过期，须重新运行；仅平移、缩放等查看不使产物过期。错误、停止、状态未确认或未完成的运行不作为正式完整产物提交。是否通关仍由后端判定，流程正常结束不等于成功。

### D-40 运行值和记录保留

建议：节点默认展示本次最近一次实际求值，记录包含运行身份、节点、模块调用层、循环轮次与执行顺序；能定位出错表达式和调用路径。普通记录使用最近 10,000 条的环形窗口，超出时明确提示；完整提交动作与来源另存，不随显示窗口裁剪。

普通诊断记录另设 20 MiB 体积预算，单条大值仅留类型、长度及缩略摘要，较早记录按完整条目淘汰；终止原因独立保留。当前页面会话保留最近一次运行记录；重新打开项目不恢复运行值或执行状态。可单独导出公开的诊断记录，明确与项目 JSON 分开；大值缩略显示但不改变真实计算值，错误原因和来源必须可查看。

### D-41 运行模型与错误时机

建议：使用按流程逐步求值的运行模型，不把整个程序预先执行一遍来生成预览；编译/校验只处理静态结构与纯常量。运行到出题动作时等待完成再继续，运行到数据模块引用时才调用。

初始化失败不进入流程；普通运行错误停止所有栈帧，不增加异常捕获或自动重试。纯常量错误在静态阶段报告，即使位于未使用区域也阻止运行；依赖实际变量或调用结果的错误只在真实求值时检查。

## 六、资源限制（D-42—D-46）

以下数值是本轮建议的新画布默认值，不是性能实测结论，不自动扩大题目 VM、HTTP、I/O 等已有服务端限制。MiB = 1,048,576 字节，KiB = 1,024 字节。

### D-42 单值、类型与表达式限制

| 项目 | 建议默认上限 | 计量方式 |
|---|---:|---|
| 单个 byte | 256 KiB | 实际字节数，保留传输封装余量；动作仍可能有更小上限 |
| 单个 string | 262,144 码点 | 不按 UTF-16 单元计数；编码结果另受 byte 限制 |
| 单个数组 | 100,000 个槽位 | 递归累计各层元素槽位，空子数组自身也占父层一个槽位 |
| 数组类型嵌套 | 32 层 | 类型和实际值都检查，空数组不能绕过 |
| int 有效位数 | 65,536 位 | 按绝对值二进制位数计，零计 1 位，符号不另占有效位 |
| int↔byte 宽度 | 8,192 字节 | 任意正整数，且转换数值仍须满足 int 位数和定宽范围 |
| 移位位数 | 65,536 | 非负 int；结果超 int 有效位上限仍报错 |
| 表达式与转换包络嵌套 | 128 层 | 静态结构限制，避免深链耗尽宿主栈 |

边界：恰好等于上限允许，超过报错；所有来源同样检查，包括模块返回、导入常量、解码和复制，不通过预估截断或部分结果继续。

### D-43 执行限制

| 项目 | 建议默认上限 | 计量方式 |
|---|---:|---|
| 活跃模块调用深度 | 128 | 仅计模块栈帧，主流程不占一个模块帧；数据、流程、递归共享 |
| 单次进入一个循环的次数 | 1,000,000 | 次数循环进入前检查；while 在将进入超限轮次前报错 |
| 整次运行语义步数 | 1,000,000 | 每次数据/运算/转换节点求值计 1，每次流程节点进入计 1，每次循环判断或轮次入口另计 1，空循环也消耗 |
| 整次运行有效时长 | 30 秒 | 包含等待后端动作，暂停时间不计；超时按停止流程核实在途动作 |
| 一份可提交动作序列 | 4,096 个动作 | 同时受完整序列化提交请求 1 MiB 限制；服务端模板展开限制另行同时适用 |

循环限制与总步数都检查，前者不保证一定能跑满一百万轮。达到限额但已正常结束不追补错误；尝试执行下一步或进入下一层才超限。记录具体触发的是哪一个预算。

### D-44 累计值资源预算

建议：单值上限外，活跃画布值采用 64 MiB 的逻辑计费预算；覆盖全局、所有栈帧、待求值临时值与捕获副本，避免用大量合法小值绕过限制。预算在新值产生或复制前检查。

计费约定：byte 按字节，string 每码点 4 字节，int 按有效位向上取整成字节并计 1 字节符号，double 为 8 字节、bool 为 1 字节，数组每槽位另计 16 字节并递归累计内容。按语义独立副本计费，不因实现采用共享存储而改变行为。诊断与提交产物另受自己的条数、动作数及体积限制。

说明：这是可重复计算的产品预算，不宣称等于宿主真实内存；实现仍须防止分配失败并把失败转为可定位的执行错误。

### D-45 项目与导入容量

建议：每项目最多 10,000 个节点、40,000 条连接、128 个模块；单画布最多 2,000 个节点，分支/循环区域嵌套最多 32 层；导入文件最多 20 MiB。空项目和缺开始节点的草稿可保存，但运行仍须满足 R-70。

格式解析所需的文件、结构深度、节点总量超限时拒绝导入并保留当前项目；合法大小项目中的运行值超限属于语义错误，可导入修复但不能运行。新建项目自动放置一个开始节点，删除后不偷偷补回。

### D-46 限制配置与统一计数

建议：限额由统一配置提供，运行开始时固定本次有效配置；题目或部署可收紧，画布普通用户不能自行绕过。界面显示有效上限，错误包含实际量与上限；同一运行跨模块、递归、分支累计，不通过暂停、重入或切换画布刷新预算。

后端动作同时满足题目、会话、请求体、I/O 和 VM 的现有限制；画布单值合法不代表一定能作为某个动作参数发送。序列化后的体积必须单独校验，不以原始 byte 长度代替 JSON/HTTP 大小。

## 七、存储、撤销与项目身份（D-47—D-51）

### D-47 自动保存与手动保存

建议：按题目与项目身份在当前浏览器本地保存，编辑完成后空闲 1 秒自动保存；Ctrl+S 立即保存，显示“保存中／已保存／保存失败”。保存完整无效草稿；存储失败保留内存内容，提示导出，不清空旧存档。

保存采用完整版本切换，成功后再替换上一份；第一期不加入云同步、账户跨设备同步或实时协作。运行中保存也只保存已锁定的编辑定义，不写回运行当前值。

### D-48 撤销容量、合并与持久性

建议：编辑历史最多 100 个完整操作且计费体积最多 20 MiB，超出淘汰最旧操作并提示。一个完整操作不拆半保留；单个操作超过预算时仍保留操作结果，明确提示本次无法撤销并清理不连贯的历史。

一次拖动、粘贴、声明删除、模块提取各算一步；同一输入控件连续文字编辑在焦点未离开且输入间隔不超过 1 秒时合并。保存不清历史，关闭或重新打开项目清空历史；运行行为不进入编辑撤销栈。

### D-49 多标签页与保存冲突

建议：同一项目同一时刻只允许一个编辑窗口；其他窗口默认只读，可显式接管。接管前检查持久化版本，旧窗口的未保存内容提供“另存副本”，禁止用旧内容静默覆盖新版本。

原项目与 R-82 导入出的新项目具有不同身份，可独立编辑。离开存在保存失败的项目时给出保留/导出的明确提示，不把自动保存成功当作无条件保证。

### D-50 JSON 无损表示与草稿字段

建议：JSON 显式记录类型；int 用十进制字符串，byte 用十六进制字符串，double 使用可还原值的表示并额外保留负零，数组记录完整元素类型和嵌套类型，空数组不靠元素反推类型。保存结构身份、作用域、参数身份、连接、布局和固定转换配置。

同时保存无法解析的编辑输入、缺失引用与修复信息；坏的常量草稿和损坏的 JSON 格式是不同错误。运行缓存、临时栈、私有题目材料和 flag 不进入项目文件。格式版本只在兼容规则明确时升级，不靠猜测解析。

### D-51 题目关联与独立导入

建议：导出的项目记录题目身份及公开能力依赖，导入生成新的项目身份；项目内部声明和连接保持一一映射，不与其他项目的相同 ID 共享。题目不存在或方法已变化时仍可打开编辑，相关能力标为不可用并阻止运行，不能悄悄改投当前题目。

第一期不提供项目自动合并；缺失引用仍遵循 R-81，不靠同名声明自动修复。重新绑定题目须显式操作，并重新校验位宽、方法、权限和所有相关转换。

## 八、迁移、移除与视觉（D-52—D-56）

### D-52 Python 移除范围

建议：删除 Python 节点、分类、编辑器、求值接口、runner 包、启动/部署依赖、配置、诊断入口，以及专门测试和现行操作文档；清理安装脚本和 CI 中的对应任务。用新的内置表达式、模块和流程承接可表达的功能，不加入另一种任意脚本执行器。

历史归档保留并标注过时，不改写历史事实；原始存档保持不变，Python 代码只可作为迁移修复材料保存或导出，不再执行。本项不等同于删除与本任务无关的所有 `.py` 文件。

### D-53 旧存档迁移采用显式转换副本

建议：支持识别当前画布存档的版本，先展示兼容检查结果，再将可保持语义的部分转换为独立新项目；保留原始文件和本地旧键。更早的 Blockly 等格式第一期只提供原文导出与不支持提示，不新增多级迁移链。

Python、未知节点或无法等价映射的结构转换为“待修复的旧节点”，保留原配置与连接资料并阻止运行；不静默删除或补零。没有开始节点的旧草稿仍保留缺失状态。迁移不是对旧数据强行应用默认零值。

### D-54 已知语义差异的迁移规则

建议：迁移清单至少覆盖 bytes→byte、text→string、旧切片偏移/长度→新切片边界、旧固定模块版本、旧形参默认值、旧整数范围、旧短路行为和旧 Python 输入输出。能静态证明等价才自动改写。

旧缺参调用若声明了默认值，在调用处显式补出同值实参；不同模块版本生成不同声明。旧切片参数若是有副作用的表达式，不通过复制表达式计算 end，以免重复调用；不能保留次数和顺序则标待修复。旧运行指针、快照与进度不恢复。更新当前文档，明确新规范替代旧语义的边界。

### D-55 视觉系统与空间关系

建议：主节点统一白色大矩形、深色文字，类型用标签和边框辅助识别；运算关系用有间距的彩色中小矩形；流程用非白色直角线、节点外置小方形接点。节点内不再嵌突兀连接圆点。

数组、转换、循环、分支、纯视觉分组使用可区分的标题和边框，均可折叠；折叠仍显示输出类型、配置摘要、错误数量和运行状态。长值截断仅影响展示，展开查看完整值。错误不能只靠颜色表达。

### D-56 选择、快捷键与基础可用性

建议：支持单选、框选、追加选择、整体拖动、平移缩放、居中定位；Ctrl+C/V/Z/Y、Ctrl+Shift+Z、Delete、Esc、Ctrl+S 使用常见语义。输入框有焦点时优先文本编辑，Delete 不误删画布节点；Esc 取消尚未落位的拖动或操作预览。

重点支持桌面鼠标与键盘，第一期不承诺触屏完整编辑。以 1280×720、1440×900、1920×1080 验收，面板收起后保留可用画布；支持键盘进入参数、可见焦点、文本错误说明与按类型搜索节点。

## 九、验收、文档与本期范围（D-57—D-60）

### D-57 代表性验收任务

建议：验收至少包括以下端到端任务，关联相应 R/D 规则并给出具体输入、结果、执行顺序与错误位置：

1. 填充 byte + 地址打包 + UTF-8 文本构造 payload，拖动重排与换行后检查字节顺序。
2. 派生长度字段随来源变化；读取时计算、禁止写派生值；整体赋值保存的副本不跟随。
3. 显式嵌套、不等长子数组、定型空数组和跨结构拖动，检查类型与层级不被自动改写。
4. 带副作用的模块参与二元运算、短路、切片和索引赋值，检查确切求值次数与顺序。
5. 条件/次数循环、break/continue、递归和提前返回，检查栈帧隔离及超限停止。
6. 转换包络的连续选择、嵌套、交叉拒绝、内部引用越界和类型冲突。
7. 无效草稿保存、删除声明后同名重建、撤销、JSON 往返与损坏文件导入。
8. 运行暂停/停止/单步、后端在途请求失败、旧产物过期和独立判题回放。
9. 旧版本迁移及含 Python 的草稿，验证不执行旧脚本、不丢失修复材料。
10. 资源边界及大值，验证上限允许、超限报错，不截断、不自动补零，不泄露私有状态。

### D-58 最终需求文档的组织

建议：审核结束后把访谈式 R 规则整理成可直接实现和验收的 PRD：目标/范围、术语与类型、表达式/转换表、结构编辑、流程/模块、执行与错误、持久化/迁移、视觉交互、资源限制、验收矩阵。

保留 R 编号用于追踪，建立 D→R→验收场景映射；合并重复描述，修正过时的“待确认”，更新文档目录。原始说明保持原样。需求文档不冒充已实现能力，也不在本轮启动产品代码修改。

### D-59 性能与可操作性验收

建议：约定一台固定桌面基准机并记录浏览器版本；使用单画布 500 节点、项目 2,000 节点的固定样例。拖动/选择输入反馈目标 100 ms 内，常规参数修改后的局部预览和校验目标 300 ms 内，保存与导入必须有进度或完成状态；最终测试同时记录 P95 与最慢值。

大项目处理要能取消或停止并保持界面可响应。目标超出时不通过漏校验、少算模块或改变语义改善成绩；需要优化或明确缩小支持范围。以上是建议验收目标，尚无本次改版实测；具体基准机在实施开始前固定并记录，不作为用户需另行选择的产品语义。

### D-60 本期交付边界

建议：本期覆盖所有已确认 R 规则与审核通过的 D 项；明确列为暂不支持的能力不做隐含承诺。第一期不包含任意脚本、跨项目依赖合并、云协作、运行状态持久恢复、异常捕获、多个返回值、可选/可变参数、自动类型转换、断点步入/步出及原地切片赋值。

当前交付仍是需求对齐与需求文档，不生成开发完成声明。审核意见落定后可直接收敛文档；仅当用户修改造成新的相互矛盾时，再针对矛盾点补充对齐，不继续逐轮重复确认已经接受的建议。
